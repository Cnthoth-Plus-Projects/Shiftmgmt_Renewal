# 1. 🔴 결과물 형식이 바뀝니다 — 이미지가 아니라 **HTML**

이번에 받은 것은 PNG 이미지였습니다. **원래 발주서(§I)가 요구한 것은 실행되는 HTML입니다.**

이미지로는 아래를 **확인할 방법이 없습니다.**

- Tab 키로 포커스가 순서대로 도는지
- 표에서 ↑↓·Space·Enter가 먹는지
- 모달에서 포커스가 갇히는지, Esc로 닫히는지, 닫은 뒤 원래 자리로 돌아오는지
- 비활성 버튼이 **포커스는 가되 눌리지 않는지**
- 스크롤한 뒤에 **긴 목록이 옆 패널을 덮어 버튼을 가리지 않는지**

마지막 항목이 특히 중요합니다. **근무지 등록 마법사는 과거에 긴 목록이 옆 패널을 침범해 버튼이 아예 안 눌린 사고가 실제로 났던 화면입니다.** 정지된 그림으로는 절대 알 수 없습니다.

```
- 🔴 CSS는 각 HTML 파일 안에 <style>로 인라인. **공통 CSS 파일을 만들지 마세요**
- 외부 파일 참조 금지. 예외: Material Symbols 아이콘 폰트 CDN 1개는 허용하되,
```

## 최소 JavaScript 5가지 (반드시 동작)

| # | 동작 |
|---|---|
| 1 | **Tab 이동** — 메뉴 → 탭 → 필터 → 표 → 버튼 순으로 논리적 순서. 포커스 링이 눈에 보일 것 |
| 2 | **표 키보드 조작** — ↑↓로 행 이동, Space로 선택, Enter로 상세 열기 |
| 3 | **모달** — 포커스가 모달 안에 갇히고, Esc로 닫히고, 닫으면 **열기 전 버튼으로 포커스 복귀** |
| 4 | **비활성 버튼** — `aria-disabled="true"`. **포커스는 가되 클릭·Enter·Space 어느 쪽으로도 실행되지 않을 것.** 비활성 사유를 `aria-describedby`로 연결 |
| 5 | **승인 (되돌아오는 방식)** — 승인을 누르면 그 행 배지가 `대기`→`승인`으로 바뀌고, 상단 건수가 갱신되고, **포커스가 다음 미처리 행으로** 옮겨 가고, 선택·스크롤 위치가 보존되고, **미리 자리 잡아 둔 `aria-live="polite"` 영역의 글자가 승인 완료 문장으로 바뀝니다** |

🔴 **5번은 상태 03 블록 안에서만 동작하고, 페이지를 새로 열면 원래 그림(대기 행이 있는 상태)으로 돌아와야 합니다.**
발주서는 **승인 작업을 키보드만으로 끝낼 수 있을 것**, **승인 후 포커스가 예측 가능하게 이동할 것**, **승인 완료가 낭독될 것**을 요구합니다. 이 셋은 **글로 적어서는 확인할 수 없고 실제로 눌러 봐야** 확인됩니다.
동시에 승인이 되돌아오지 않으면 **검수 대상 화면 자체가 망가집니다.** 그래서 **되돌아오는 방식**입니다.

🔴 **`window.confirm` · `alert` · `prompt`를 쓰지 마세요.** 확인이 필요하면 **화면 안에 직접 그린 모달**을 쓰세요(20의 이탈 확인 모달이 그 예입니다).
브라우저 기본 대화상자는 ① 세로로 이어 붙인 20상태 안에 그림으로 남지 않아 검수를 할 수 없고, ② §5-3의 자동 검증 스크립트를 멈춰 세웁니다.

> **실제 데이터 연동은 필요 없습니다.** 다만 위 5가지는 **프로토타입의 화면 내부 상태로 실제로 동작해야 합니다.** 그 동작은 §5-1 동작 정의표에 적습니다.
> **20개 검수 상태 자체는 숨기거나 갈아 끼우지 않습니다** — 세로로 이어 붙인 채로 둡니다.

## 2-1. 직급 `주임`을 쓰면 안 됩니다

**어디에**: 03 · 04 · 13 · 14 · 15 · 19
예: `10018 최유나 주임`, `10041 최유진 주임`, `20011 이서연 주임`

**왜 안 되는가** — 이 프로그램이 저장하는 직급은 **딱 5개**입니다.

```
사원 · 대리 · 과장 · 차장 · 부장
```

**그 밖의 값은 저장할 때 버려집니다.** 실제 코드에서 확인했고, `주임`이 버려지는 것을 검증하는 테스트도 이미 있습니다. 버려진 직급은 **품의서 별첨1의 직급 칸에 `-`로 출력됩니다.** 결재 서류가 잘못 나가는 사고입니다.

## 2-4. `14`**와 `06`**의 고아 승인 카드에서 **숫자와 버튼을 지우세요** — 안내 문단만 남깁니다

## 3-6. `18`의 검증 오류 샘플이 규칙과 맞지 않습니다


## 5-3. 화면 캡처 + **자동 검증 산출물**

체크박스 5줄만으로는 부족합니다. **아래 3가지를 함께 주세요.**

**① 20상태 전부의 캡처** — **1440×900 실제 뷰포트**에서 찍은 것.
파일 이름은 **§1 「번호가 두 가지입니다」의 형식**을 씁니다. 예: `05_08-performance_인테이크-진행중_reviewer.png`

**② 자동 검증 스크립트 + 실행 로그** — 아래를 사람이 아니라 **스크립트가 눌러 본** 결과입니다.

```
1. Tab 순서       메뉴 → 탭 → 필터 → 표 → 버튼. 실제 포커스 이동 순서를 로그로
2. 표 키보드      ↑↓ 행 이동 / Space 선택 / Enter 상세 열기
3. 모달           포커스가 모달 밖으로 안 나가는가 / Esc로 닫히는가 / 닫은 뒤 원래 버튼으로 돌아오는가
4. 비활성 버튼    aria-disabled 요소를 클릭·Enter·Space로 눌러 보고 → 실행되지 않음을 확인
                  + 사유가 aria-describedby로 연결돼 있는가
5. 마법사 침범    긴 목록을 끝까지 스크롤한 뒤 진행 버튼이 여전히 클릭 가능한가   ← 과거 사고 항목
6. 승인 (되돌리는 방식)
     · 키보드만으로 행 선택 → 승인까지 끝낼 수 있는가
     · 승인 후 그 행 배지가 `대기`→`승인`으로 바뀌고 상단 건수가 갱신되는가
     · 포커스가 다음 미처리 행으로 옮겨 가고, 선택·스크롤 위치가 보존되는가
     · 승인 **전부터** `aria-live="polite"` 영역이 화면에 있고,
       승인 후 그 영역의 글자가 승인 완료 문장으로 **바뀌는가**   ← 화면의 구조를 보고 판정
     · **페이지를 새로 열면** 배지·건수·행이 원래 03 그림으로 **되돌아오는가**
```

> ⚠️ **네 번째 항목은 "실제로 낭독되는지"를 재는 것이 아닙니다.** 브라우저 자동화 도구로는 화면 낭독기가 실제로 소리 내어 읽는지 확인할 수 없습니다.
> 여기서 확인하는 것은 **① 낭독될 영역이 미리 자리 잡고 있는가**(승인 후에 새로 만들어 붙이면 안 읽힙니다) **② 그 영역의 글자가 바뀌는가** 두 가지입니다.
> **실제로 소리가 나는지는 사람이 화면 낭독기를 켜고 확인하는 별도 항목**이며, 이번 제출물에 포함하지 않습니다.

> 🔴 **6번은 "되돌리는 방식"으로 만드세요.**
> 실제 데이터를 부르지 말고 **화면 안의 모의 상태로만** 바꾸고, **페이지를 새로 열면 원래 그림(대기 행이 있는 03)으로 돌아오게** 하세요.
> 되돌아오지 않으면 검수 대상 화면 자체가 망가집니다(§1의 "20상태를 갈아 끼우지 않는다").
> **캡처는 승인을 누르기 전 상태로 찍어 주세요.**

- **각 항목마다 어느 상태(§6 번호)를 대상으로 돌렸는지**와 **통과/실패 + 실제 포커스 이동 순서**를 로그에 남겨 주세요

> 도구는 자유입니다(Playwright·Puppeteer 등). **스크립트 파일과 실행 결과 로그를 같이** 주시면 됩니다.

**③ 5번 항목은 스크롤 전/후 캡처를 함께** 주세요. 정지 화면 한 장으로는 판정할 수 없습니다.
