`AGREE-2I`로 지시서가 최종 승인된 뒤, 발주 직전에 **아직 안 본 14장을 확인**했다.

# 🔴 A. 심각 — 지시서에 한 글자도 없는 것 (14건)

## A-1. 정체불명 버튼 4종이 화면마다 박혀 있다

§2-3은 `엑셀 다운로드`·`증적 내려받기` **두 개만** 지목했다. 아래는 지목되지 않았다.

| 버튼 | 나타나는 장 | 위험 |
|---|---|---|
| **`되돌리기`** | 03·04·07·13·16 (툴바 + 04 상세 패널 하단) | **승인을 되돌리는 동작**으로 읽힌다. 절대 규칙 2(forward-only, 승인된 계산을 이력 없이 덮어쓰지 않는다)와 충돌 가능. 창구 불명 |
| **`행 숨김 ▾`** | 03·07·13·16 | **데이터를 숨기는 동작.** 절대 규칙 5(데이터를 조용히 잘라내지 않는다)와 충돌 위험. 창구 불명 |
| **`빠른 시작 옵션`** 카드 3개 — `기존 설정 복사` / `회전 템플릿` / **`기존 엑셀에서 패턴 추출` + `[엑셀 업로드]`** | 08 | 화면에서 엑셀을 올리는 동작. `회전 템플릿`은 소스에 `site-rotation-templates.ts`가 있어 실재 가능성 있음. 나머지 둘은 창구 불명 |
| **`자동 시작 복구`** | 06 | 복구를 실행하는 동작. 창구 불명 |

**할 일**: §2에 항목을 신설해 각각 **창구를 댈 수 있을 때만 남기고 아니면 삭제**하도록 지시.
특히 `되돌리기`·`행 숨김`은 **절대 규칙과 충돌하므로 창구가 있어도 별도 확인**이 필요하다.

## A-2. `고아 승인 상태` 카드가 06에도 있다 — §2-4가 14만 지목했다

06에 `고아 승인 건수 2건` / `고아 데이터 건수 158건` / `최신 발생 시간 2025-06-10 14:18:07` / `자세히 보기`가 **14와 똑같이** 있다.

**할 일**: §2-4의 대상을 **`14`에서 `14·06`으로** 넓힌다.

## A-3. 같은 종류의 "창구 불명 숫자 패널"이 05·06에 더 있다

| 장 | 패널 | 숫자 |
|---|---|---|
| **05** | `시작 복구 상태` | `대기 실적 12건` · `8월 근무표 미배포 — 보라매 사업장 1건` · `파일 해석 실패 1건` · `시작 시 자동 복구 실패 — 7일 7건` · `대기 수당 34건` |
| **06** | `진행 요약` | `대기 파일 3개` · `검증 대기 0건` · `승인 대기 12건` · `오늘 승인 완료 3건` |
| **05** | 기타 | `해석 규칙: 기본 해석 규칙 v2.1` (정체 불명) · `전체 보기 >` 링크 2개 (열어 줄 화면 불명) |

§2-4가 14의 고아 카드에만 적용된다. **같은 판정 기준을 05·06에도 적용해야 한다.**

**할 일**: §5-1의 "집계·상태 숫자도 표에 적고, 세 칸 못 채우면 삭제" 규칙이 **이 패널들을 명시적으로 포함**하도록 §2 또는 §5-1에 예시로 적는다.

## A-4. 🔴 `12건`과 `128건`이 온 화면에서 충돌한다

| 장 | 같은 화면 안의 두 숫자 |
|---|---|
| **01·02** | `승인 대기 실적 **128**건`(현황 카드) ↔ `대기 실적 **12**건`(지금 해야 할 일) |
| **05** | 메뉴 배지 `128` ↔ `시작 복구 상태`의 `대기 실적 **12**건` |
| **06** | 메뉴 배지 `128` ↔ `진행 요약`의 `승인 대기 **12**건` |
| **03·13** | 메뉴 배지 `128` ↔ 본문 `대기 실적 **128**건` ✅ **여기만 일치** |
| **14** | 메뉴 배지 `128` ↔ 본문 `대기 실적 **126**건` |
| **11·16** | 본문 **전부 `0건`** ↔ 메뉴 배지 **`128`** |
| **12** (로딩) | 데이터를 불러오는 중인데 배지 `128`이 **이미** 떠 있음 |

지시서 §3-1은 **14의 `128 vs 126`만** 언급하고 "무엇을 세는 숫자인지 §5-1에 적고 회신하라"로 열어 뒀다.
**실제로는 `12`라는 세 번째 숫자가 있고, 빈 상태에서도 배지가 뜬다.**

**할 일**: §3-1에 위 표를 넣고, **`12`·`128`·`126`·`0`이 각각 무엇을 세는지 전부 §5-1에 적도록** 요구.
빈 상태(11·16)와 로딩(12)에서의 배지 처리도 회신 항목에 포함.

## A-5. 표가 화면마다 다른 물건이다

| 장 | 행 하나가 뜻하는 것 | 예 |
|---|---|---|
| **03·13** | **하루치** | `2025-05-28 (수)` · 총 `8.00` |
| **07** | **한 달치 집계** | `2025-07-01 ~ 2025-07-31` · 총 근무시간 `173:30` |
| **06** | **근무지별 집계** | `보라매 사업장` · `데이터 건수 42건` |

열 구성도 다르다.
- 03·13: `근무지(그룹)/사번/이름/직급/근무일/구분/근로유형/시작-종료/총/기본/연장/야간/시급/수당/상태/경고`
- 07: `근무표 그룹/근무표명/사원명/부서/실적 기간/총 근무시간/연장시간/야간시간/휴일근무시간/상태/제출일`
  → 03에 없는 열: `근무표명`·`사원명`·`부서`·`휴일근무시간`·`제출일` / 07에 없는 열: `사번`·`직급`·`시급`·`수당`

§2-2는 **탭 이름만** 통일했다. 표의 행 단위·열 구성 통일 지시가 없다.

**할 일**: §2-2에 **"실적 표의 행 하나 = 근무일 한 건"** 을 정본으로 못 박고 열 구성도 확정한다.
(정본이 무엇인지는 `03-data-model.md`·`04-api-contract.md`로 확인 필요 — **미확인**)

## A-7. 10의 1-B가 09·17과 완전히 다른 화면이다

| | 09 · 17 · 20 | **10** |
|---|---|---|
| 본문 구성 | `근무 유형 팔레트` + `묶음별 설정` + `3개월 시뮬레이션` | **`교대 수` + `교대 유형` + `교대 순서(7일 주기)`** |
| 용어 | `근무 유형`·`묶음`·`패턴` | **`교대 수`·`교대 유형`·`선택된 교대`** |

같은 `1-B 근무시간 설정`인데 **다른 제품처럼 보인다.**
§3-3은 단계 표시만, §3-5는 유형 추가 버튼만 다룬다. **본문 구조 불일치는 지시서에 없다.**

**할 일**: §3-3 또는 §3-5에 **"1-B의 본문 구성은 09·17을 정본으로 하고 10도 같은 구조로"** 를 넣는다.
`교대 수`·`교대 유형`은 §3-8 용어표에 없으므로 정본 낱말 확인 필요 — **미확인**.

## A-8. 16(빈 상태)에서 선택 행이 0인데 버튼이 활성이다

`승인`(파란 주 버튼)·`반려`·`되돌리기`·`행 숨김`·`원본 엑셀 열기`가 **전부 활성**이다.
§5-1이 `승인`의 활성 조건을 **"선택 행 ≥1"** 로 확정했는데 16이 그것을 어긴다.

**할 일**: §5-1 또는 §4에 "16에서는 행 선택이 불가능하므로 `승인`·`반려`·`되돌리기`가 비활성 + 사유"를 명시.

## A-9. 04의 `일괄 승인` / `일괄 반려` 이름이 §5-1과 충돌한다

§5-1은 승인을 **"행마다 1회씩 호출, 일부만 성공할 수 있음"** 으로 확정했다.
그런데 04의 버튼 이름 **`일괄 승인`** 은 "한 번에 다 되거나 다 안 된다"로 읽힌다. 03·13은 `승인`이다.

**할 일**: §3-7 또는 §5-1에 **버튼 이름을 `승인`·`반려`로 통일**하고 `일괄`을 쓰지 말라고 명시.
