## §2 D11 원인과 해법(정본 근거)

- 원인: 실행 버튼이 포커스를 가진 채 `disabled`가 되면(또는 프로그램 클릭이면 처음부터) 포커스가 모달 안 살아 있는 요소에 있지 않다. 모달의 `keydown` 트랩은 모달 안 요소에서 난 이벤트만 받으므로 Tab이 브라우저 기본 순차 이동으로 넘어가고, 시안은 한 페이지에 여러 상태를 두어 **현재 상태의 `app-body`만 `aria-hidden`** 이라 다른 상태의 nav로 간다.
- 해법(Codex 최소 수정안 그대로): 잠금 직후 `modal.focus()` — 오버레이는 24파일 전부 `tabindex="-1"`(02-common-1 4/4 · 04-sites-2 1/1 · 07-schedule-3 1/1 · 09-allowance-2 3/3 · 11-operations-4 2/2 · 06-employees-2 2/2 · 06-employees-3 3/3) — 그리고 트랩 첫 줄에 `if (processing && e.key === 'Tab') { e.preventDefault(); return; }`. 완료 콜백은 기존대로 닫고 opener 복귀. 취소 경로·API 신설 없음.
- 13차 실측(후): E3·E4·E6·E8 잠금 직후 `activeElement = modal-e3 / modal-e4 / modal-e6-confirm / modal-e8`(모달 안 4/4) · 합성 Tab keydown 차단 **true 4/4** · 실제 Tab: E6·E8(800ms) 1회 후에도 모달 안 유지, E3·E4(600ms)는 CLI 지연으로 완료 후 측정(opener로 복귀 = 정상 닫힘).

## §4 ⑤가 배운 것

- **"데모 1회용"은 면책이 아니다.** 요청서 780행이 처리 중 상태를 정의하는 이상, 완료 후 그 상태가 남으면 거짓 상태다. 잔여로 넘기기 전에 정본 정의에 비춘다.
- **포커스가 있던 요소를 `disabled`로 만들면 포커스가 새어 나간다.** 잠금 = 포커스 목적지 지정 + Tab 억제까지가 한 묶음. `dyn15`(합성 Tab 차단 + 재열기 복원) 정규 편입.
