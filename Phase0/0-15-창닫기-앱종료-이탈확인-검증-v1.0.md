## 현재 제품의 종료 경로

1. V4 `src/web/app.ts`는 서버 연결을 표시하는 Phase 3 이전 준비 화면뿐이다. 미저장 상태나 `beforeunload` 처리기가 없다. 따라서 지금은 탭을 닫아도 이탈 확인창이 뜨지 않는다.
2. `scripts/dev.mjs`는 Chrome이 기존 창에 탭을 추가할 수도 있어 Chrome 자식 프로세스 종료를 앱 종료 조건으로 쓰지 않는다. 서버는 종료 신호나 서버 프로세스 종료 전까지 남는다. 실제 탭 닫기 시험 뒤 `/api/health`는 HTTP 200이었다.
3. `src/main/server.ts:414-451`은 SIGINT/SIGTERM에서 연결·서버·런타임을 닫고 종료한다. 브라우저에 미저장 상태를 묻거나 종료를 취소하는 교신은 없다. 현재 구조에서 터미널 Ctrl+C, 서버 중지, 강제 종료는 브라우저 경고로 보호되지 않는다는 것은 이 소스 경로에서의 추론이다.
4. 읽기 전용 V3.4 `src/main/main.ts:306-314`도 창이 모두 닫힌 *후* 파일 감시·백업·DB를 정리하고 앱을 종료하며, 창 `close`를 가로채 미저장 내용을 확인하지 않는다.

## 구현 가능 범위와 Phase 3 검증 기준

- 브라우저의 `beforeunload`는 미저장 입력이 있을 때만 등록하고 저장·취소·폐기 후 해제할 수 있다. 사용자 상호작용이 있어야 경고가 표시되고, 문구는 브라우저가 정하는 일반 문구라 제품이 한국어 세부 설명으로 바꿀 수 없다. [MDN beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event), [Chrome 대화상자 정책](https://developer.chrome.com/blog/dialogs-policy).
- 앱 안 화면 이동은 제품이 제어하는 별도 확인 모달로 상세 설명을 줄 수 있다. 탭·창 닫기와 새로고침은 브라우저 기본 확인창을 사용한다. 이 구분은 Phase 3의 실제 입력 화면과 탐색 구조가 생길 때 구현·클릭 시험으로 검증해야 한다.
- 서버를 별도로 중지하거나 OS가 프로세스를 강제 종료하는 경우를 `beforeunload`로 보장할 수 없다. 서버 종료까지 확인하려면 사용자가 제어하는 종료 동작과 브라우저·런처 간 별도 절차가 필요하다. 현 제품에는 그 경로가 없다. [MDN의 신뢰성 제한](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event), [Chrome 페이지 수명주기](https://developer.chrome.com/docs/web-platform/page-lifecycle-api).
- Phase 3 완료 시험에서는 실제 미저장 폼의 창 닫기 취소/허용, 저장 후 무경고 닫기, 앱 안 이동 시 보존/폐기, 서버 종료와 탭 닫기의 구별을 확인한다. 현재는 Phase 3 입력 화면이 없어 이 기능이 구현됐다고 판정하지 않는다.
