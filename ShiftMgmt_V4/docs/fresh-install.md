# 새 PC에 처음 설치하기 — 1.0.4

이 배포물은 Windows x64 PC 한 대에서 사용하는 교대근무관리 시스템입니다. Node 실행 환경을 포함하므로 Node나 npm을 따로 설치할 필요가 없습니다. Google Chrome은 미리 설치해 주세요. ARM 및 32비트 Windows용 설치 파일은 아닙니다.

**EXE 설치:** 같은 릴리즈의 `ShiftMgmt-1.0.4-Setup-x64.exe`를 받아 실행하고 설치 안내를 따릅니다. 압축을 직접 풀거나 Node를 따로 설치할 필요가 없습니다. 설치 후 바탕 화면의 바로가기로 실행합니다. EXE의 해시는 `INSTALLER_SHA256SUMS.txt`에서 확인합니다.

**ZIP 설치도 계속 사용할 수 있습니다.** 아래는 ZIP으로 설치하는 순서입니다.

1. ZIP과 SHA256SUMS.txt를 같은 릴리즈에서 받습니다. PowerShell의 Get-FileHash -Algorithm SHA256 명령으로 ZIP의 해시가 목록과 같은지 확인합니다.
2. ZIP을 마우스 오른쪽 버튼 → 모두 압축 풀기로 풉니다. ZIP 안에서 바로 실행하지 마세요.
3. 압축을 푼 폴더의 INSTALL.cmd를 두 번 클릭합니다. 관리자 권한은 필요 없습니다. 성공하면 바탕 화면에 ‘교대근무관리 시스템’ 바로가기가 생깁니다.
4. 바로가기를 실행합니다. 실행 창에 표시되는 admin 아이디와 임시 비밀번호로 로그인합니다. 기존 첫 로그인 정책(admin / 1234)을 유지하며, 처음 로그인하면 비밀번호 변경 화면이 먼저 나옵니다. 비밀번호는 대문자·소문자·숫자·특수문자를 포함한 8자 이상으로 정해 주세요.
5. 프로그램의 운영 관리에서 계정과 연락처, 폴더·백업 위치, 요율·정책 적용일을 실제 업무 기준에 맞게 확인하고 인력·근무지를 등록합니다. 기본 계정의 연락처는 예시입니다. 운영담당 계정은 필요한 경우 관리자가 비밀번호를 재설정해 전달하고, 승인담당 계정은 사용 여부를 확인한 후 승인합니다.

실행 창은 작업하는 동안 열어 두세요. 종료할 때는 실행 창에서 Q를 입력하고 Enter를 누릅니다. 크롬 화면을 닫는 것만으로 서버가 종료되지는 않습니다. 다음 실행도 같은 바로가기를 사용합니다.

근무표는 Excel로 생성한 뒤 내보내기 폴더 아래 ‘배포’ 폴더에 게시합니다. 현장에서 수정해 돌려받은 실적 원본은 승인대기 폴더에 접수하고 실적 관리에서 검토·승인합니다. 배포만으로 실적이 승인되지는 않습니다. 파일명과 본문의 근무월·실제 근무일이 다르거나 연장근무의 시작/종료 ‘시’가 비어 있으면 원본을 정정해 다시 가져와 주세요. 정시의 분 생략과 명시적 0시는 사용할 수 있습니다.

프로그램은 %LOCALAPPDATA%\Programs\ShiftMgmt_V4 에 설치됩니다. 자료는 프로그램과 별도로 %LOCALAPPDATA%\ShiftMgmt_V4 에 보관되며, 그 아래 data 폴더에 DB와 가져오기/내보내기/백업 폴더가 생성됩니다. 자료 폴더를 지우면 업무 자료가 사라집니다. 임시 비밀번호 파일은 첫 비밀번호 변경 후 해당 계정 정보가 제거됩니다.

기존 설치 폴더, 자료 폴더 또는 같은 이름의 바로가기가 있으면 설치는 중단됩니다. 기존 자료를 삭제해서 해결하지 마세요. EXE를 다시 설치하는 방식으로 기존 프로그램을 덮어쓰지는 않습니다. 1.0.4부터 아래의 실행 시 자동업데이트를 지원하며, 구판 자료 이관은 별도 JSON 복원으로 진행합니다. 구판 JSON 이관은 아래 복원 순서로 별도 진행합니다. 설치 실패 시 임시 복사 폴더만 정리하고 기존 자료는 건드리지 않습니다. 바로가기 생성만 실패한 경우 표시된 설치 폴더의 START.cmd를 실행할 수 있습니다.

처음에는 실제 업무 인력·실적·승인·수당 자료가 없는 상태로 시작합니다. 설치 파일에 운영 DB나 실적 엑셀은 포함하지 않습니다. 요율 등 초기 기준값은 실제 운영 전에 확인해야 합니다.

1.0.2부터 요율은 근무일의 적용 기간으로 선택합니다. 미래 요율을 미리 등록해도 과거 실적에 적용하지 않습니다. 공휴일 추가 연장근무도 지급 대상이며, 운영 관리 → 요율에서 해당 근무일의 ‘휴_연장근로수당’ 연장·야간 배율을 업무 기준에 맞게 확인해 주세요. 초기값은 0이므로 그대로 승인하면 중단 안내가 나옵니다. 임의 배율로 지급하지 않으며, 올바른 요율을 저장한 뒤 다시 승인하면 됩니다. 이미 승인된 금액은 요율 변경이나 재시작으로 자동 정정되지 않습니다.

품의서·별첨1·별첨2만 A4로 출력합니다. 근무표 샘플과 근무표는 Excel 파일로 생성합니다.

백업은 운영 관리의 백업 기능으로 생성하고 프로그램 폴더 밖의 별도 저장소에도 보관해 주세요. JSON3 백업에는 승인 취소 전 기록이 포함되므로 구판 프로그램에서 복원할 수 없습니다. 기존 PC로 교체·이관하거나 구판으로 돌아가는 작업은 별도 확인과 백업이 필요합니다.

## 기존 ShiftMS 0.5.8에서 JSON으로 이관하기

1.0.4 이상에서 진행합니다. 기존 공개 1.0.3은 구판의 39표 JSON을 지원하지 않으므로 먼저 설치 버전을 확인하세요. 구판의 JSON 파일을 직접 편집하거나 새 표·설정을 손으로 추가하지 마세요.

1. 기존 운영 PC에서 0.5.8의 JSON 백업을 만들고 원본과 복사본을 보관합니다. 이관할 백업 이후에는 구판에 새 승인·업무 자료를 입력하지 않아야 두 PC의 자료가 갈라지지 않습니다. 승인 건수, 승인 수당 총액과 월별 합계도 함께 기록합니다.
2. 새 PC에 프로그램을 설치하고 운영 관리 → 설정 → 백업·복원에서 JSON 복사본을 선택합니다. 요구조건 검사 → 미리보기의 표별 전후 건수와 경고 → 확인 문구 ‘교체’ 입력 → 복원 순서로 진행합니다. 교체 전 새 PC의 현재 DB도 자동 JSON 백업으로 보존합니다.
3. 구판에 없던 사용자 정의 근무코드 영역은 자동 준비합니다. 구판 PC의 재분석 진행 상태는 가져오지 않고 새 PC에서 미승인 실적을 다시 확인하도록 요청합니다. 이미 승인된 계산 금액과 과거 이력은 재계산하지 않습니다. 복원 후 처음 실적을 열 때 미승인 자료가 재분석될 수 있습니다.
4. 계정도 구판 JSON의 계정으로 교체됩니다. 복원 후에는 기존 운영 PC에서 사용하던 아이디·비밀번호를 사용합니다. 새 설치 시 지정한 관리자 비밀번호와 다를 수 있습니다. 기존 관리자 로그인 수단을 확인한 뒤 교체하세요.
5. 인력·근무지·시급 이력·월별 근무표·승인 건수·승인 수당 총액과 월별 합계를 원본과 대조합니다. 프로그램을 종료·재실행하고, 내장 양식 1·2의 새 근무표 Excel 생성 및 품의서·별첨1·별첨2의 A4 생성도 확인합니다.
6. 새 PC에서 JSON 백업을 새로 만들어 별도 저장소에 보관합니다. 복원 문제가 생기면 새 PC의 교체 전 자동 백업으로 되돌릴 수 있습니다. 새 JSON3를 구판 프로그램으로 가져오는 방식으로 되돌리지는 마세요. 구판 프로그램·DB·원본 JSON과 업무 파일은 검수가 끝날 때까지 보존합니다.

### 근무표 양식과 이미 작성한 Excel 원본

근무표 양식 1·2와 품의서·별첨의 기본 레이아웃은 설치 파일에 내장됩니다. 과거 템플릿 Excel을 옮기지 않아도 이관한 인력·근무지·근무패턴으로 새 근무표를 생성할 수 있습니다.

JSON은 DB 자료를 담으며 이미 생성·배포·회수한 Excel 원본이나 외부 첨부 파일의 바이트를 포함하지 않습니다. 기존 PC의 대기·승인·보관 폴더, 과거 근무표와 필요한 증적 파일을 별도로 복사하고 파일명·크기·SHA-256 목록을 보관하세요. 복사할 때 파일명과 수정 시각을 보존합니다.

새 PC의 운영 관리 → 설정에서 승인완료 폴더를 지정하고, 그 아래 `2026년/3월`처럼 연도·월 폴더 구조를 유지해 승인 원본을 복사합니다. JSON 복원 후 프로그램을 다시 시작하거나 실적 관리에서 다시 불러오면, 이전 PC 경로가 없고 파일명·월·크기·수정 시각·전체 원본 행이 일치하는 유일한 보관본을 기존 승인 기록에 연결합니다. 승인 ID·금액·계산·이력을 유지하며 다시 승인하지 않습니다. 실적 관리에서 ‘승인 완료 보관본’과 근무월을 선택하고, ‘근무일’로 날짜를 좁혀 ‘원본 열기’를 확인하세요. 근무일을 지우면 해당 월 전체로 돌아가고, 다른 월의 날짜를 고르면 근무월도 함께 바뀝니다.

이전 경로가 아직 존재하거나 같은 이름의 보관본이 여러 개 있는 경우, 내용·수정 시각이 다르거나 접근할 수 없는 경우, 승인완료 폴더 밖을 가리키는 링크인 경우에는 자동 연결하지 않습니다. 원본 미발견 안내가 남으면 기존 PC의 원본과 사본을 대조하고 중복 사본·폴더 설정을 확인하세요. 연결하려고 같은 실적을 다시 접수·승인하거나 JSON의 경로와 승인 내용을 직접 고치지 마세요. 미승인 재분석과 과거 원본 열기까지 확인한 후 이관 검수를 마칩니다.

개발 검증용 도구 `scripts/verify-v3-json-migration.mjs`는 V1 39표·40표 입력의 SHA-256/행 수를 고정하고 표별 원문·월별 금액·새 JSON3 왕복·교체 전 자동 백업의 실제 복구를 격리 DB에서 검증합니다. 특정 과거 운영자의 이름이나 고정 금액을 성공 조건으로 사용하지 않습니다. 사번 없는 미승인 실적의 안전 제외가 필요하면 검토한 정확한 행 ID 목록을 `--expected-removed-entry-ids`로 지정해야 하며, 승인·계산 이력이 연결된 행은 복원을 중단합니다.

시작하지 못하면 실행 창의 안내를 먼저 확인합니다. 크롬이 없다면 크롬을 설치하고 다시 실행합니다. 이미 실행 중이라는 안내가 나오면 기존 실행 창을 확인합니다. 이 프로그램은 로컬 주소 http://127.0.0.1:8734 에서만 동작합니다. 다른 PC에서 접속하는 서버나 자동 업데이트 기능은 제공하지 않습니다.

EXE로 설치했다면 프로그램 실행 창에서 Q로 종료한 뒤 Windows의 설치된 앱에서 ‘교대근무관리 시스템’을 제거합니다. DB와 업무 자료 폴더는 유지합니다. 프로그램 폴더에 사용자가 별도로 넣은 파일도 자동 삭제하지 않습니다. ZIP으로 설치했다면 Q로 종료한 후 프로그램 설치 폴더와 바탕 화면 바로가기만 삭제합니다. 자료 폴더는 백업을 확인하기 전까지 보관하세요.

ZIP의 SHA256과 파일 매니페스트는 배포 파일의 손상·변경을 확인하기 위한 것입니다. Windows 코드서명된 설치 프로그램은 아닙니다. 실행 전 ZIP은 프로젝트의 공식 릴리즈에서 받아 주세요.

1.0.3의 공휴일 화면에서 ‘한국 공휴일 동기화’는 오른쪽 미리보기만 불러옵니다. ‘적용하기’를 눌러야 선택 연도에 저장하고, 기존 목록에만 있는 날짜는 유지합니다. 기본 출처는 Nager와 Google 대한민국 공휴일 일정이며, 보완 자료 미제공 연도·통신 실패에서는 저장하지 않습니다. 임시공휴일 등의 최신 지정 내용을 적용 전에 확인해 주세요. 일반 토·일 정규 편성은 공휴일 수당을 만들지 않으며, 공휴일과 겹친 토·일은 해당 요일의 설정 시간을 사용합니다. 실제 근무분이 있는 기본·연장·야간 배율이 하나라도 0이면 부분 지급 승인도 중단합니다.

## 실행할 때 자동으로 업데이트하기

1.0.4를 처음 설치한 뒤에는 기존 바탕 화면 바로가기를 계속 사용합니다. 새 정식 버전이 있으면 실행 창에서 내려받아 검증하고 새 버전으로 시작합니다. 업데이트 도중 실행 창을 닫지 마세요. 진행 중인 업무를 바꾸지 않도록 프로그램이 켜져 있는 동안에는 업데이트하지 않습니다.

업데이트는 프로그램 파일만 별도의 버전 폴더에 준비하고 같은 DB·업무 자료 폴더를 사용합니다. 인터넷 연결이나 다운로드·검증·새 버전 시작에 문제가 생기면 사용 가능한 기존 버전으로 실행합니다. 한 번 정상 실행한 새 버전은 인터넷 연결이 없어도 다시 사용할 수 있습니다. 자료 폴더를 지우거나 JSON을 다시 가져올 필요가 없습니다.

자동 적용은 같은 DB 구조를 사용하는 호환 버전에 한합니다. DB 구조 변경을 포함하는 버전은 별도 백업·설치 안내를 따릅니다. 최초 1.0.4 설치 및 구판 JSON 복원은 사용자가 직접 진행합니다. HTML 파일을 단독으로 여는 방식이 아니라 설치된 프로그램의 바로가기로 실행해야 합니다.
