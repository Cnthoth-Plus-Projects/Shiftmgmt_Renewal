## 5. 창구 규약 (`docs/api-convention.md` — 1-3 구현의 기준. 1-1은 문서 + 헬퍼 뼈대만)

1. **주소**: `POST /api/<채널명>` — 채널명은 **별첨 `02-창구-계약표-111-v0.1.md`** 의 111행(= `src/preload/index.ts` invoke 111 = `register-*.ts` handle 111) 그대로(예 `employees:list`). 표에는 채널·메서드·계약 인수(타입)·계약 반환형·가드·권한 동작·활동 기록·전송 특이·핸들러 파일이 있다.
2. **요청**: `Content-Type: application/json`, 본문 = 인수 **JSON 배열**. 선택 인수(`query?`)를 안 넘길 때는 **배열에서 생략**한다(`[]`) — 화면 껍데기는 뒤쪽 `undefined`를 잘라내고 보낸다(JSON `null`로 바뀌어 원본과 달라지는 것을 막기 위해). 1 MB 상한.
3. **응답**: 계약 반환형 JSON **그대로** — 110개는 `BridgeResult<T>`(`{ ok: true, data }` / `{ ok: false, errorCode, message }`, `contracts.ts:869-880`), **`app:get-version`만 JSON 문자열**(`"0.1.0"`, `contracts.ts:883`). HTTP 상태: 200(계약 결과, 실패 결과도 200) · 400 `BAD_REQUEST`(본문·호스트 오류) · 401 `UNAUTHORIZED`(세션 없음·만료) · 403 `FORBIDDEN`(Origin/Fetch Metadata) · 404 `NOT_FOUND`(채널 없음) · 413 `PAYLOAD_TOO_LARGE` · 415 `UNSUPPORTED_MEDIA_TYPE` · 500 `INTERNAL_ERROR`(예외 → `getErrorMessage`) — **비 200도 본문은 `BridgeFailure`**(위 `errorCode` + 한국어 `message`).
4. **세션**: `auth:sign-in` 성공 시 서버가 `crypto.randomBytes(32).toString("hex")` 세션 id 발급(로그인마다 새로) → `Set-Cookie: sm_session=<id>; HttpOnly; SameSite=Strict; Path=/`. 서버 메모리 `Map<id, { session: AuthSession, issuedAt, lastSeenAt }>`. 만료·갱신·로그아웃 판정은 원본 `auth-service.ts`·`ipc-auth-guard-service.ts`의 규칙을 **그대로**(1-3a 지시서에서 줄 번호로 고정) · `auth:sign-out`이 삭제 · 프로그램 재시작 = 전부 로그아웃(원본과 같은 단일 프로세스 의미).
5. **가드·활동 기록**: 원본 `withSession`·`withActionPermission`·`withAdmin`·`withAccessHistory`(`main.ts:78-119`)와 `recordSuccessfulActivity`(`main.ts:126-170`)를 **같은 이름·같은 판정**으로 서버 한 곳(`src/main/http/session.ts`, 1-3)에 옮긴다. 채널별 가드는 별첨 계약표 열이 정본(withAdmin 40 · withSession 35 · withActionPermission 22 · withAccessHistory 1 · 없음 13).
6. **파일 주고받기**(계약표 「전송 특이」 열): 열기 대화상자 채널 = `multipart/form-data` 업로드(Content-Type 예외) → `<dataDir>/uploads/<yyyyMMdd-HHmmss>-<원래이름>` 저장 → 그 경로를 서비스에 전달 / 저장 대화상자 채널 = 서비스가 만든 파일을 `Content-Disposition: attachment`로 내려주거나 `<dataDir>/exports/`에 저장하고 경로를 응답에 실음 / 경로 열기 채널 = 경로만 응답. 1-3c에서 채널별로 확정.
7. **화면 껍데기**(`src/web/bridge/app-bridge.ts`, 1-3b): `window.appBridge`에 111개 메서드를 **같은 이름·같은 반환형**으로. 네트워크 실패 → `{ ok: false, errorCode: "NETWORK_ERROR", message: "서버에 연결할 수 없습니다. 프로그램이 켜져 있는지 확인하세요." }` · 응답이 JSON이 아니거나 형태가 어긋남 → `{ ok: false, errorCode: "INVALID_RESPONSE", message: "서버 응답을 읽을 수 없습니다." }` · `getAppVersion`은 문자열을 그대로 돌려준다(실패 시 예외 대신 `""`이 아니라 **거부(reject)** — 원본과 같은 형태).
8. `/api/health`만 GET 허용(브라우저 주소창 확인용). 그 밖 GET `/api/*`는 404.
