# DEC-001 — 수당 지급 대상 신원 게이트

- Status: ACTIVE / 구현 대기
- Type: BUSINESS_RULE + DATA
- Owner: USER
- Source: USER_EXPLICIT, 2026-09-19
- Scope: 실적 인테이크, 실적 승인, 수당 계산, JSON/Access 복원

## Context

Phase 2-6 감사에서 Pool 법정공휴일 1건과 사번 없는 비BP 법정공휴일 1건이 실제 승인 이력 없이 승인완료로 보였다. BP 인력은 실적·승인·계산이 없었다. 기존 제품 규칙은 Pool의 대체근무만 제외했지만 Access 이관은 모든 Pool 행을 지급 대상에서 제외해 경로별 판정이 달랐다.

## Decision

1. Pool은 대체·법정휴일·연장을 포함한 모든 근무 유형에서 수당 지급 대상이 아니다.
2. BP는 수당 지급 대상이 아니며 실적·수당 범위에 포함하지 않는다.
3. 지급 가능한 실적은 사번이 필수다. 외부 사번이 없을 수 있는 인력은 BP뿐이지만 BP는 실적·수당 전에 제외한다.
4. 사번 없는 과거 미승인·미계산 실적은 원본 백업을 보존하고 V4 복원 대상에서만 삭제한다. 승인·계산·숨김 이력이 연결돼 있으면 자동 삭제하지 않고 복원을 중단한다.
5. 이미 승인·계산된 결과는 삭제하거나 새 규칙으로 재계산하지 않는다.

## Rationale

사용자가 세 항목을 명시적으로 확정했다. 지급 신원은 사번으로 추적돼야 하고, Pool/BP 제외 판정은 인테이크·승인·계산·복원 어느 경로에서도 같아야 한다. 동시에 기존 금액 이력과 V3 원본은 보존해야 한다.

## Rejected alternatives

- Pool의 대체근무만 제외: 법정휴일 행이 다시 지급 대상으로 나타나 사용자 결정과 충돌한다.
- 무사번 행에 임의 사번·시급 부여: 실제 신원과 근거를 창작한다.
- 승인·계산 연결 여부와 무관하게 일괄 삭제: 금액·결재 이력을 조용히 훼손한다.
- V3 운영 JSON 직접 수정: 원본 증거와 롤백 기준을 잃는다.

## Consequences

- Pool/BP 행은 모든 승인·수당 대상 집계에서 빠진다.
- 새 무사번 비BP 실적은 저장되지 않고 제외 경고가 남는다.
- 현재 운영 백업의 무사번 행 1건은 V4 복원 결과에서 제거되며, 해당 파일의 파생 메타데이터와 미리보기만 일관되게 보정된다.
- 기존 승인·계산 263건과 총액 56,076,024원은 바꾸지 않는다.

## Do not infer

- BP를 인력 관리나 근무표에서 삭제한다는 뜻이 아니다.
- Pool 근무 이력 자체를 모두 삭제한다는 뜻이 아니다. 지급 대상에서 제외한다.
- 기존 승인·계산 결과를 소급 삭제하거나 재계산한다는 뜻이 아니다.

## Revisit when

사용자가 Pool 또는 BP를 지급 대상으로 바꾸거나, 외부 사번 없는 인력을 수당에 포함해야 하는 별도 신원 체계를 승인할 때 다시 검토한다.
