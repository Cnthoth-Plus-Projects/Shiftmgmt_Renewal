- 이 표는 승인된 Plan Task 안의 단계이며 별도 작업 추가 허가가 아니다. 구현 전에는 검증기 자체/fixture·기존 소스 가능성을 확인하고, 실제 새 producer/reader·변경 binding·candidate 회귀는 구현 후 실행한다. 아직 없는 코드의 성공을 IMPLEMENT 발행 선행조건으로 두지 않는다.

## 10. 성공 조건

- [ ] 요구사항 R1~Rn 전부 구현 위치와 실행 증거가 있다.
- [ ] 수정 파일 집합이 allowlist와 정확히 일치한다.
- [ ] 정적 검사·빌드·관련 시험이 기대값으로 통과한다.
- [ ] 음성 시험 N1~Nn이 잘못된 동작을 실제로 차단한다.
- [ ] 보호 경로·불변조건·기존 사용자 변경이 보존된다.
- [ ] UI 작업이면 실제 실행·클릭·키보드·캡처·콘솔 검사가 통과한다.
- [ ] 아래 회신 양식에 재현 가능한 전체 증거가 있다.

## 11. 즉시 중단 조건

- 지시·소스·테스트가 서로 충돌한다.
- 허용 목록 밖 파일이나 새 의존성 변경 없이는 구현할 수 없다.
- 기준 커밋/초기 상태/보호 SHA가 다르다.
- API·DB·계산·권한·아키텍처 결정을 새로 해야 한다.
- 시험을 약화하거나 fallback/placeholder를 넣어야만 통과한다.
- 검증 환경 또는 필수 도구가 없어 성공 조건을 확인할 수 없다.
