# 메뉴 공통 구현·수용 기준

사용자 승인: 2026-10-27 인력 관리 실제 화면 승인 및 이후 메뉴에도 같은 기준 적용 지시. UI-02 이후 모든 화면 Task에 적용한다. 기존 제품 불변조건·기능 명세·권한 정책은 유지한다.

## 화면과 테이블

**사용자 추가 확정(2026-10-28): 테이블이 있는 모든 메뉴의 화면 골격은 승인된 인력관리 화면을 기준으로 통일한다.** 단순한 색상 통일이 아니라 KPI·검색 영역과 표·상세 영역의 배치 구조를 동일하게 적용한다.

1. 셸의 제목 아래 **전체 폭 KPI 영역 → 전체 폭 검색·필터·작업 버튼 영역 → 표/상세 본문** 순서로 구성한다. 셸에 있는 메뉴 제목을 본문에 반복하지 않는다. 인력 관리와 동일하게 본문 여백16px·영역 간격12px, KPI는 작은 카드 안에서 이름과 수치를 좌우로 배치한다. KPI 개수는 업무에 맞추되 카드 높이와 본문 시작 비율을 맞춘다. KPI와 검색을 좌측 표 열 안에 넣고 상세만 페이지 상단에 올려놓지 않는다.
2. 넓은 화면의 본문은 `minmax(0, 1fr) 380px`의 두 열을 기준으로 한다. 좌측 표 카드와 우측 상세 카드는 **같은 본문 행에서 상단과 하단을 맞춘다.** 우측 상세는 KPI/검색과 나란히 시작하거나 표의 헤더보다 위로 올라가지 않는다.
3. KPI·필터와 하단 상태줄을 제외한 가용 높이를 본문 양쪽에 채운다. 페이지 이동은 표 카드 하단에 항상 보이게 두고, 상세 내용이 길면 카드 내부에서 스크롤한다. 전체 화면 스크롤 때문에 페이지 버튼이 상태줄 아래로 가려지지 않게 한다. 접기/펼치기·마지막 페이지·선택 변경 때 카드 외곽 크기와 상세 시작 위치를 유지한다.
4. 좁은 화면은 표를 읽을 수 있는 폭으로 확보하고 상세를 명확한 모달/반응형 전환으로 제공한다. 상세 기능이 없는 표 메뉴는 같은 KPI/필터/본문 순서를 유지하며 본문 표를 전체 폭으로 쓴다. 마법사·비표 폼은 업무별 흐름을 유지한다.
5. 구현 참조는 `src/web/screens/workforce.ts:186`의 `renderMainLayout`(KPI, 별도 toolbar/listWrapper, contentGrid 내부 table/detail)과 `src/web/workforce.css:66` 및 `:585`의 높이·폭 구조다. 인력관리 파일 자체를 복사 덮어쓰거나 수정할 필요는 없으며 각 메뉴의 기존 허용 파일 안에서 구조를 적용한다. 실제 창 크기에서 표/상세 top·bottom 차이와 푸터/상태줄 겹침을 측정해 확인한다.

- 실제 창 너비를 사용하고 조밀하게 배치한다. 의미 있는 KPI·검색·필터는 실제 조회 자료로 구성한다. 근거 없는 숫자·무동작 장식은 만들지 않는다.
- 인원/항목 목록은 데스크톱에서 표의 가용 높이·실제 행·그룹 제목·가로 스크롤바 높이를 측정해 온전히 들어가는 최대 행 수로 페이지를 나눈다. 다음 한 행(그룹 변경 시 제목 포함)이 들어갈 수 있는 빈 공간을 남기지 않는다. 화면이 좁거나 측정 전에는10개씩 표시한다. 세로 무한스크롤로 대체하지 않는다. 필터/정렬을 전체 자료에 적용한 뒤 페이지를 나눈다.
- 그룹 목록은 전체 그룹을 먼저 정렬한다. 페이지 경계에서는 전체/현재 페이지 건수와 ‘이어서’를 표시하고 같은 그룹의 접기 상태를 공유한다. 페이지마다 따로 그룹을 만들지 않는다.
- 컬럼 폭·표 카드 크기는 접기/펼치기와 마지막 페이지에서도 안정적이어야 한다. 식별자 컬럼을 왼쪽에 유지한다. 좁은 화면의 가로 이동은 허용하되 식별자는 확인할 수 있어야 한다.
- 긴 문자열은 화면을 밀지 않게 처리하고 원문은 상세/편집/툴팁으로 확인할 수 있게 한다. 상세는 목록 아래로 밀리지 않는 우측 카드(기준380px) 또는 명확한 모달로 제공한다. 작은 화면에는 적절히 전환한다.

## 공통 페이지네이션 — 사용자 승인 2026-10-28

- 테이블이 있는 모든 이후 메뉴는 `src/web/pagination.ts`의 `renderPagination`을 재사용한다. 근무지/인력 목록의 다른 번호·이전다음 구현을 복사하지 않는다. 스타일은 `common-controls.css`의 `pagination-footer`, `pagination-controls`, `pagination-button`을 사용한다.
- 공통 표시: **« ‹ 페이지 번호/… › »**. 각각 첫 페이지·이전 페이지·다음 페이지·마지막 페이지로 이동한다. 현재 번호는 채운 강조색과 aria-current, 모든 이동 버튼에는 한국어 접근성 이름과 툴팁을 붙인다. 첫/끝 이동 불가 시 disabled, 빈 결과에는 번호를 만들지 않고 이동 버튼을 비활성화한다.
- 번호는 전체 데이터의 페이지 수와 현재 위치에 따라 동적으로 만든다.9페이지 이하면 전체 번호를 표시한다.10페이지 이상이면 처음 두 번호·마지막 두 번호와 현재 번호±1을 유지하고 사이를 …로 생략한다. 처음/끝 근처에서는 첫5개/끝5개를 표시한다. 번호와 생략은 최대9개 토큰, 이동 버튼은 별도4개로 제한한다. 예: 전체17페이지 중5페이지는 **« ‹ 1 2 … 4 [5] 6 … 16 17 › »**. 생략 기호는 클릭 버튼으로 만들지 않는다.
- 치수도 공통 CSS를 따른다. 버튼 높이28px·최소 너비28px·가로 안쪽 여백7px·모서리5px·버튼 간격4px, 생략 기호 최소 너비20px. 하단 영역은 안쪽 여백8px 10px·영역 간격8px·글자12px로 두고 결과/범위는 왼쪽, 이동 버튼은 오른쪽에 정렬한다. 좁은 폭에서는 카드 밖으로 넘치지 않게 줄바꿈한다. 메뉴별 버튼 치수나 색상을 별도로 덮어쓰지 않는다.
- 표 카드 하단에 검색 결과 수·현재 범위·현재/전체 페이지를 표시한다. 검색/필터는 전체 조회 자료에 적용하고 새 조건은1페이지, 자료 축소는 유효한 끝 페이지로 보정한다. 번호/처음/끝/이전/다음은 실제 표시 자료와 상세 선택을 갱신한다.
- 페이지당 행 수 정책과 공통 컨트롤은 분리한다. 근무지·인력은 공통 `paginateGroupsForHeight`/`measurePaginationBody`로 가용 높이와 그룹 제목을 포함해 분할한다. 소수점 CSS 높이를 유지하고 가로 스크롤바는 제외하며, 목록 세로 스크롤과 다음 행 잘림을 허용하지 않는다. 화면 높이 변경 시 페이지 수/표시 범위/현재 페이지를 함께 갱신하고 선택 대상을 유지한다. 접기/펼치기는 기존 페이지 경계와 그룹 접기 상태를 유지한다.
- 사용자 확인용 Chrome은 viewport=null로 실제 창 크기를 사용한다. headless 검사용 고정 크기를 사용자 창에 적용하지 않는다. 전체 폭 KPI → 전체 폭 검색·필터 → 좌 표/우380px 상세 → 표 하단 공통 페이지 이동의 골격을 이후 메뉴 Task 지시서와 검수에 포함한다.
- 완료 전0/1/마지막 일부/다수 페이지·검색 축소·번호 직접 이동·처음/끝·화면 높이 변화와 넘침을 확인한다. 실제 사용 샘플50개 이상과 별도로 대량 페이지는 격리 컴포넌트에1001개 등 시험 자료를 대입해 확인할 수 있다. 페이지 시험 때문에 운영 DB에 자료를 추가하지 않는다.

## 공통 입력·모달

- 제품의 `src/web/common-controls.ts`와 `common-controls.css`를 그대로 재사용한다. 모든 메뉴/모달의 단일 선택과 날짜 입력은 같은 디자인·키보드·포커스·disabled·날짜 범위 규칙을 사용한다. 메뉴마다 별도 선택 메뉴나 달력을 만들지 않는다.
- 라벨과 문구는 한국어, 이해하기 쉬운 업무 용어를 사용한다. ‘종료/해제/삭제/교체’는 정확한 대상·결과·마지막 적용일·대안을 설명한다. 변경/갱신을 종료와 혼동하게 하지 않는다.
- 확인은 공용 질문 모달을 사용한다. Esc·Tab/ShiftTab·취소·복귀 포커스·중복 클릭 잠금을 보장한다. 권한 잠금과 처리 중 잠금을 구분한다.
- 로딩/정상 빈 상태/조회 실패/권한 없음/처리 중을 구분한다. 실패를0건이나 정상 빈 자료로 표시하지 않는다. 선택 대상은 현재 필터/페이지와 일치해야 한다.
- 화면/탭/모달/세션의 세대가 바뀐 뒤 늦은 응답이 새 화면을 수정하거나 후속 요청·포커스·로그아웃을 일으키지 않아야 한다.

## 실제 사용 확인용 시험 자료

- 목록이 있는 메뉴는 실제 저장·조회되는50개 이상 자료를 준비한다. 기본55개로 창 높이에 따른 여러 페이지와 마지막 잔여 항목을 확인한다. 관련 상세/변경 이력도 여러 건 만들어 과거·현재·예정·장문·상태 차이를 확인한다.
- 고정된 문서 종류·설정 항목 수를50개로 억지로 늘리지 않는다. 해당 상세 이력을50개 이상 준비해 페이지 이동을 확인한다. 읽기 전용 배포 이력은 격리 실행의 실제 manifest 자료로 시험하고 운영 이력으로 가장하지 않는다.
- 운영 DB와 V3.4 원본은 사용하거나 수정하지 않는다. 새 TEMP 데이터 경로에서 기존 저장 API/정식 가져오기 경로로 생성한다. 실적 시험 자료는 엑셀 인테이크를 따른다.
- 실제 사용자·금액·공휴일·릴리즈로 오인하지 않도록 시험 자료임을 설명한다. BP/Pool 미지급 등 기존 정책은 시험 자료에도 적용한다. 암호·복구키·세션 비밀값은 로그·캡처에 남기지 않는다.
- 메뉴 구현이 보이면 실제 Chrome을 일찍 열고 준비/검수 상태와 URL을 알린다. 완료 때 해당 메뉴를 선택한 채 유지한다. 사용자 실제 확인 전에는 사용자 승인으로 기록하지 않는다.
