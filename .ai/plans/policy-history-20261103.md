# 정책 적용 기간·버전 이력 구현 계획

상태: 사용자 구현 의사에 따른 설계안. 제품 정책 기능은 아직 구현하지 않음.
Task: POLICY-HISTORY-01. 현재 UI-ADMIN-01-SETTINGS 화면 보완을 닫은 뒤 순차 진행한다.
정상 역할: Sol 설계·검수 / Gemini 구현. Gemini 제출0회(최초0/재시도0/누적0).

## 1. 사용자가 얻게 될 동작

적용일 하나를 덮어쓰는 대신, 정책 종류별로 기준 내용과 적용 시작일을 함께 보존한다. 실적의 근무일에 해당하는 정책을 선택한다.

| 버전 예시 | 적용 근무일 | 보존할 내용 |
|---|---|---|
| V1 | 6월30일까지 | 종전 판정 기준 |
| V2 | 7월1일~8월31일 | 7월부터 적용한 기준 |
| V3 | 9월1일부터 | 9월부터 실제로 달라지는 기준 |

9월 정책을 추가해도 V2의 7~8월 적용은 유지한다. 날짜만 입력한다고 새로운 계산법이 생기지는 않는다. 기준 내용과 지원되는 판정 방식을 함께 지정한다. 프로그램 버전과 정책 버전은 별도로 표시한다.

1차 범위는 기존 날짜 필드에 대응하는 두 종류다.

- 대체근무수당 대상 판정: 기존 기준 / 현재 구현된 새 제외 기준.
- 실제 근무자 판정: 기존 방식 / 변경 후 근무자 우선 방식.

두 정책은 적용일이 다를 수 있으므로 종류별 이력을 분리한다. 두 종류에 동시에 하나의 날짜를 강제하지 않는다. 연속 야간·최소 휴식·주간 시간·휴무 확인 네 경고 설정은 현행 기능을 유지한다. 새로운 수당 공식·금액·법정 요율은 이번 기능에서 만들지 않는다. 이후 별도 기준이 생기면 해당 판정 구현을 추가하고 버전으로 연결한다. 사용자가 임의 수식이나 코드를 입력하는 방식은 제공하지 않는다.

## 2. 화면과 사용자 흐름

운영 관리 → 설정 → 근무·수당 기준에서 두 정책을 각각 ‘현재 기준 / 다음 예정 기준 / 정책 이력’으로 확인한다. 현재의 날짜 입력만으로 저장하는 방식은 정책 관리 흐름으로 대체한다.

새 정책 등록 흐름:

1. 정책 종류를 선택하고 ‘새 정책 추가’를 누른다.
2. 지원되는 판정 기준, 적용 시작일, 변경 사유를 입력한다. 이전 기준과 달라지는 내용을 나란히 보여준다.
3. ‘영향 확인’에서 적용 근무일 구간과 관련 대기 실적을 확인한다. 승인 완료 실적은 별도 수량으로 표시하고 그대로 보존된다고 안내한다. 영향 조회 자체는 정책·실적·계산을 저장하지 않는다.
4. 확인 화면에서 등록한다. 등록 기준과 이력을 한 번에 저장하고, 영향받는 대기 실적의 재판독을 표시한다.
5. 이력 목록에 새 버전과 적용 기간이 표시된다. 기존 버전의 끝은 다음 버전 시작 전날로 자동 계산한다.

Dense 이력 표의 열은 버전 / 상태(예정·적용 중·종료) / 적용 기간 / 기준 요약 / 등록자·등록 시각 / 상세보기다. 페이지네이션을 사용하고 긴 기준 설명·사유·변경 전후는 상세창에서 읽는다. 실적 상세에서도 실제 적용된 정책 종류·버전·근무일 기준을 확인할 수 있게 한다.

상태 ‘예정’은 화면 조회 날짜에 따른 안내이며, 실제 판정은 항상 실적의 근무일을 사용한다. 예를 들어 9월1일 적용 정책을 8월에 등록하고 9월 근무를 읽으면 해당 정책을 선택한다. 기준 적용을 위해 자정 예약 작업에 의존하지 않는다.

## 3. 새 정책과 정정의 구분

- **새 정책 추가:** 특정 근무일부터 기준이 달라질 때 사용한다. 이전 정책과 사용 이력은 보존한다.
- **예정 정책 정정·취소:** 아직 실적 승인에 사용되지 않은 예약 정책에 허용한다. 변경 사유를 필수로 받고 원래 값·변경 값·작업자를 이력에 남긴다. 취소는 삭제가 아니라 취소 사건으로 남긴다.
- **승인에 사용된 정책:** 직접 수정·삭제를 잠근다. 변경은 새 정책으로 추가한다. 승인된 금액과 당시 판정 기준은 유지한다.

같은 종류·같은 시작일의 중복 활성 정책과 모호한 기간 중첩을 거부한다. 화면에는 ‘날짜 오입력 정정’과 ‘기준 변경’을 서로 다른 행동으로 설명한다. 기본 입력은 오늘·미래 날짜이며, 과거 적용이 필요한 경우에는 영향 확인·사유를 필수로 하고 이미 승인된 구간을 바꾸지 않는다는 결과를 분명히 보여준다. 이미 사용한 정책의 과거 적용일을 직접 바꾸는 기능은 1차 범위에 넣지 않는다.

## 4. 저장·판정·이력 연결

- 정책 종류별 불변 기준 레코드: 정책 ID, 표시 버전, 판정 구현 식별자, 기준 값 스냅샷, 적용 시작일, 등록자·시각·사유를 보관한다. 기간 끝은 다음 유효 시작일에서 파생한다.
- 변경 사건은 추가 방식으로 기록한다. 예약 정정·취소도 원본과 변경 전후를 보존한다. 현재 목록을 만들기 위한 상태와 감사 사건을 구분한다.
- 실적 파일을 읽을 때 근무일로 정책을 선택하고, 선택된 정책 ID·버전·판정 근거를 실적에 연결한다. 승인 시에는 이 기준과 계산 결과를 함께 스냅샷으로 고정한다.
- 승인 전에 정책이 바뀌거나 다른 관리자가 같은 정책을 수정하면 이전 화면의 내용으로 조용히 저장하지 않는다. 영향 미리보기의 기준 지문과 등록/승인 시점의 기준을 대조하고 다시 확인하도록 안내한다.
- 정책 등록·이력 기록·재판독 표시를 하나의 트랜잭션으로 묶는다. 영향받지 않는 근무일의 대기 실적은 변경하지 않는다. Pool·BP 제외, 사번 필수, 승인·계산 트랜잭션 등 기존 불변식을 유지한다.
- 서버가 관리자 권한과 기간/기준을 검증한다. 프런트 표시만으로 잠그지 않는다.

## 5. 기존 자료를 옮기는 원칙

현재 두 적용일과 실제 지원 기준으로 ‘도입 당시 기준’을 초기 등록한다. 기존 설정의 날짜 변경 내역을 복원했다고 표시하지 않는다. 알 수 없는 과거 버전은 추정 생성하지 않는다.

기존 승인 건의 계산·판정 스냅샷은 그대로 보존한다. 당시 정책 ID를 정확히 연결할 자료가 없으면 ‘이전 기록’으로 표시하고, 근거 없이 새 버전을 소급 연결하지 않는다. 대기 실적은 초기 정책 전환 전후 판정이 일치하는지 비교한다.

JSON 백업·복원과 기존 백업 가져오기도 함께 반영한다. 새 정책·사건 이력이 백업에서 빠지지 않도록 하고, 이전 백업에는 초기 변환 규칙을 적용한다. 승인 금액·건별 합계가 변하지 않는지 대조한다. 운영 원본·실제 설치 PC의 전환은 별도 실행 승인 범위다.

## 6. 구현 순서와 검수 기준

동일 Task 안에서 의존 순서대로 진행하며 Gemini 최초1+재시도1 한도를 단계마다 초기화하지 않는다. 최종 구현 패킷에서 실제 수정 파일 목록과 기존 필수 시험을 고정한다.

1. **기간 저장과 기존 자료 전환:** 정책·사건 저장, 초기 변환, JSON 백업 호환, 관리자 검증. 기존 승인 결과를 그대로 읽는지 먼저 검문한다.
2. **실적 판정과 승인 연결:** 근무일별 정책 선택, 영향 미리보기, 대기 재판독 범위, 승인 스냅샷·동시 수정 검증을 연결한다.
3. **운영 화면:** 두 정책의 현재/예정 표시, Dense 이력·페이지네이션, 등록·정정·취소·상세보기, 실적의 적용 버전 안내를 구현한다.

예상 수정 영역: shared의 정책 판정/bridge 계약, sqlite·정책 저장·설정 서비스, 실적 파서·승인 스냅샷·정책 영향 조회, 운영 routes/화면, JSON 백업·복원, 관련 기존 시험과 UI 검문. 현재 UI-ADMIN-01의6파일 허용목록을 정책 구현에 확대 사용하지 않는다. 정확한 파일 경계는 구현 패킷에 별도로 고정한다.

수용 검문:

- 6월30일 / 7월1일 / 8월31일 / 9월1일 경계와 두 정책의 다른 시작일.
- 9월 새 버전을 추가해도 7~8월 판정이 유지됨.
- 승인 금액·직원별 합계·판정 스냅샷 보존.
- 예약 정책 정정/취소의 원본·변경 전후 이력 보존, 사용 정책 직접 수정 거부.
- 중복 시작일·권한 없음·미리보기 이후 동시 변경·오래된 화면의 등록/승인 거부.
- 기존 자료 초기 전환 및 JSON 백업 왕복 후 정책/이력/금액 보존.
- 등록 미리보기와 최종 결과 연결, Dense 표의 페이지 이동·작은 화면·키보드 접근.

## 현 상태와 범위

이 문서는 정책 이력의 구현 계획이다. 현재 제품에 정책 기간 이력·등록 API·새 DB 표를 추가하지 않았다. 동시에 요청한 시스템·감시 디자인 보완은 기존 UI-ADMIN-01-SETTINGS에서 별도로 반영·검수한다.
