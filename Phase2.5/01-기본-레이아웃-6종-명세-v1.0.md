## 3. 좌표·크기·스타일 표기 규칙

### 3.1 Excel

- `canvas.unit = "cell"`.
- `x`, `y`는 1부터 시작한다. `A1 = (1,1)`, `BS80 = (71,80)`이다.
- `width`, `height`는 블록이 차지하는 열 수와 행 수다.
- 범위는 양 끝을 포함한다. `B19:D20`은 `x=2, y=19, width=3, height=2`다.
- 열 폭은 ExcelJS `column.width`, 행 높이는 point 단위 `row.height` 값이다.
- 명시하지 않은 열·행은 해당 시트의 `defaultColWidth`·`defaultRowHeight`를 쓴다.
- 병합은 이 문서에 적은 범위만 만든다. v1.0에서 사용자가 병합이나 행 높이를 바꾸는 예외는 없다.

### 3.2 PDF

- `canvas.unit = "mm"`; 원점은 실제 용지의 왼쪽 위다.
- 고정 블록은 `layoutMode="absolute"`, 세로로 내용에 따라 밀리는 블록은 `layoutMode="flow"`다.
- 흐름 블록의 `y`와 `height`는 최소 시작점·최소 높이이며, 실제 아래쪽은 데이터 행 수에 따라 늘어난다.
- `flowOrder`, `pageBreakBefore`, `repeatHeaderOnPageBreak`, `autoHeight`는 값 바인딩처럼 보호한다. 사용자가 임의로 순서를 바꾸지 못한다.
- CSS의 `px` 값은 96dpi CSS pixel 기준으로 그대로 재현한다. 임의로 mm로 반올림하지 않는다.

## 4. 공통 편집·보호 계약

### 4.1 속성 부호

- `E`: 편집 가능
- `E*`: 정적 문구나 정적 시각 속성만 편집 가능. 데이터로 채워지는 값은 보호
- `P`: 보호. 저장과 미리보기에서 모두 거부
- `N/A`: 그 블록에 해당 속성이 없음

모든 문서의 공통 보호 속성은 `row-order`, `value`, `binding`, `row-height`, `merge`다. **행 높이·병합 허용 예외는 0개**다.

3. `allowance-pdf.proposal.criteria` — 왼쪽 대상 기준 카드와 오른쪽 총 지급 카드의 2열 grid (`1fr : minmax(220px,0.42fr)`, gap 14px).
4. `allowance-pdf.proposal.regular-table` — 근무지별 정규 지급 7열과 합계.
5. `allowance-pdf.proposal.early-table` — 조기 지급 7열과 합계, 없으면 `해당 없음`.
6. `allowance-pdf.proposal.footer` — 지급 요청일·세부내역.

표 행이 많으면 `regularSiteCount + earlyPayoutSiteCount + (early>0 ? 2 : 0)` 점수로 압축한다. 11 이상은 compact, 15 이상은 compressed다. compact는 주요 간격과 padding을 줄이고, compressed는 절 제목 14px·표 10px·결재 공간 60px까지 줄인다. 이 임계값과 순서는 보호한다.

2쪽 흐름 순서:

1. `allowance-pdf.proposal.chart-title`
2. `allowance-pdf.proposal.chart-note`
3. 4열 요약 카드: 총 지급, 정규 지급, 퇴사자 선지급, 대상 인원
4. 2열 차트 grid `1.25fr : 0.9fr`, gap 14px
5. 왼쪽 근무지별 가로 막대 — 지급액 내림차순, 최대 8줄(넘으면 마지막을 `기타 N개 근무지`로 합침)
6. 오른쪽 근로유형별 도넛 — 180px 원, 내부 118px, 범례

막대 높이 10px, 색 `#3758b0 → #8da2de`; 가장 큰 금액을 100%로 하고 0이 아닌 표시 폭 최솟값은 10%다. 차트 값·정렬·합계는 보호한다.

## 12. 파일명·중복 규칙

- 근무표: `{year}년/{monthNumber}월/{year}_{monthNumber}_{siteName}.xlsx`
- 수당 문서: 각 설정 폴더 아래 `{year}년/{month2}월/{year}_{month2}_{품의서|별첨1|별첨2}.{xlsx|pdf}`
- 대시보드 단일 차트: `{chartKey}_{chartTitle}_{YYYY-MM-DD-hh-mm-ss}.pdf`
- 대시보드 보고서: `{title}_{YYYY-MM-DD-hh-mm-ss}.pdf`
- 같은 이름이 이미 있으면 확장자 앞에 `_dup01`, `_dup02` 순으로 붙인다.
- 파일명에 쓸 수 없는 문자는 생성기가 안전한 문자로 치환한다. 출력 파일명 규칙은 레이아웃 정의에 포함하지만 데이터 값과 중복 방지 규칙은 보호한다.

## 13. 구현·검증 인수 조건

Phase 2.5-2 이후 다음을 모두 만족해야 한다.

1. 샘플 파일과 `source_path`가 없어도 7개 저장 키의 기본 정의만으로 출력된다.
2. Excel은 시트 이름, 사용 범위, 셀 값, 병합, 폭, 높이, 글꼴, 정렬, 테두리, 채움, 숫자 형식, 인쇄 설정을 대조한다.
3. 근무표는 template1·template2 각각 배포 → 수정 → 회수 → 해석 결과가 기존과 같다.
4. `DATE`, `변경 사유`, 휴일 분홍색, 대체·연장 상대 좌표, 레이아웃 판 식별자는 저장 검증에서 보호한다.
5. Pool·BP·사번 없는 비BP가 수당 문서에 한 건도 들어가지 않는 음성 시험을 둔다.
6. 품의서 Excel은 정규 0/1/여러 근무지와 조기 0/1/여러 근무지에서 좌표·병합이 겹치지 않는다.
7. 별첨1은 보조 시트를 출력하지 않고, 상세/소계/합계/조기/요율 안내의 동적 좌표가 맞는다.
8. `proposal-pdf` 한 번의 실행이 품의서·별첨1·별첨2 PDF 3파일을 모두 만든다.
9. PDF는 설치된 Chrome headless로 A4 방향·여백·쪽 나눔·반복 머리글·한국어 글꼴을 실제 렌더링해 확인한다.
10. 캔버스 저장·미리보기는 `blockCapabilities`를 적용하고 행 높이·병합·행 순서·값·바인딩 변경을 거부한다.
