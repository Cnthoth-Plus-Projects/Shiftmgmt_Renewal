## 1. 범위와 현행 실측

사용자 결정 R-15는 **DB 백업·복원만 JSON 단일화**한다. 근무표 회수·문서 생성 등 업무 Excel/PDF 경로는 유지한다. 기존 `database-backup-service.ts`는 현재 JSON과 Excel을 항상 만들고 설정된 Access 원본도 복사한다. `database-migration-service.ts`는 `.json`과 `.accdb`를 모두 허용한다. JSON 복원은 현재 살아 있는 스키마의 일반 표를 동적으로 순회하므로, 과거 R-15 메모의 “31개만 복원”은 현행 코드에 적용되지 않는다. 다만 `app_setting_entries`를 건너뛰고 현재 설정을 재저장하므로 업무 정책값까지 잃을 수 있다.

JSON 백업은 **DB 행**의 백업이다. 일반 39표에 들어 있는 `app_users` 계정·권한은 복원 대상에서 교체되지만, `performance_files.file_path` 등 행이 참조하는 실제 파일 바이트는 포함되지 않는다. 기기 간 이동 시 외부 파일을 별도로 보존·배치해야 할 수 있다. 이번 단계는 파일 자체 복사나 경로 추측 변환을 추가하지 않고, 미리보기에서 이 한계를 알린다.

Phase 2-2 기준은 **40표 스키마, 일반 표 39개의 내용 대조**, `app_setting_entries` 별도 변환이다. 사번 없는 DEC-001 실적 1건은 승인된 예외 조건에서만 복원 대상에서 제거한다. 원본 JSON은 바꾸지 않으며 연결된 승인·계산·숨김 참조가 있으면 중단한다. 5-4 적용 스크립트의 JSON 백업 규칙은 미래 단계에 전달하며, 이번 단계에서 설치 프로그램의 원시 사용자 데이터 백업 스크립트를 임의로 바꾸지 않는다.

## 2. 공개 계약

`04-api-contract.md` §4.3을 그대로 구현한다. DB 채널 4개의 **이름·관리자 가드**는 유지하고 JSON 전용 입출력으로 좁힌다. 파일 선택 채널만 `operations:select-migration-file` → `operations:select-json-backup-file`로 1:1 교체한다. 채널 총수 **107**과 DB 외 **96개 불변 채널**은 유지한다. 파일 선택 대화상자에서 호출자 지정 필터로 `.accdb`를 다시 열 수 없게 한다. 업무용 `operations:select-spreadsheet-file`은 보존한다.

백업은 40표를 담은 JSON 하나만 생성하고 경로·원본 바이트의 SHA-256·스키마 판·표/행 수를 반환한다. 같은 초에 연속 실행해도 기존 파일을 덮어쓰지 않으며, 완성 전 파일을 정상 백업처럼 노출하지 않는다. 과거 `.xlsx`·`.accdb` 백업 파일/폴더를 자동 삭제하지 않는다. 제안 계약은 기존 `schemaVersion: 1` 파일을 계속 읽고 API에는 문자열 `"1"`로 표시한다. 이 형식에는 독립적인 내장 체크섬이 없으므로 “체크섬 검사”의 정확한 의미는 **원본 바이트 SHA-256 산출과 미리보기/실행 간 동일성 검사**이며, 손상 여부를 SHA만으로 독립 인증했다고 주장하지 않는다.

검사 단계는 읽기 실패/잘못된 JSON, 지원하지 않는 schemaVersion, 필수 40표 누락, 잘못된 표 행 형식과 중복·불명확한 설정 키를 각각 거부하고 **현재 DB를 변경하지 않는다**. 미리보기는 40표 모두의 현재/복원 후 행 수, 변환 경고, 원본 SHA 및 만료 시각이 있는 일회용 토큰을 돌려준다. 실행은 `backupFilePath`·`backupSha256`·`previewToken`·정확한 확인 문구 `교체`를 모두 대조한다. 파일 내용/현재 DB 변경, 토큰 만료·재사용·불일치 시 자동 백업이나 교체 전에 거부한다.

정상 실행은 같은 원본 바이트를 사용해 임시 DB에 복원·검증하고, **현재 DB의 JSON 사전 백업이 완성·검증된 후** 기존 원자적 교체·실패 롤백 경로로 반영한다. 백업 실패나 임시 DB 검증 실패는 운영 DB를 그대로 둔다. 원본에 없는 필수 표, 알 수 없는 비어 있지 않은 표, 복원 불가능한 데이터/열을 경고만 남기고 버리는 동작은 허용하지 않는다. 승인된 DEC-001과 설정 변환만 예외다.

미리보기 성공은 현재 HTTP 경로에서 `access_logs`에 활동 이력을 **미리보기 서비스가 끝난 뒤** 기록한다. 따라서 토큰을 사전 상태에 묶으면 자기 자신이 즉시 무효화된다. 구현은 활동 기록 뒤 현재 40표 상태를 다시 읽어 반환할 `currentRowCount`와 토큰의 상태 지문을 확정해야 한다. 그 사이 업무 데이터가 바뀌면 재미리보기하도록 거부한다. 지문은 행 수만이 아니라 내용 변경도 감지해야 한다. 실행 시에도 사전 백업을 기다리는 동안 다른 쓰기가 발생했다면 교체 직전 재확인해 중단한다.

## 3. `app_setting_entries` — 사용자 승인 정책

`04-api-contract.md:493`이 요구한 별도 승인을 2026-09-27 사용자의 “응 진행하자”로 받았다. 현재 코드처럼 표 전체를 무시하면 4개 근무표 경고 기준과 2개 수당 정책 적용일이 백업 값으로 복원되지 않는다. 사용자 승인 기준은 **업무 데이터·규칙은 선택한 JSON에서, 저장 폴더는 복원하는 기기의 설정에서** 가져오는 것이다.

여기서 **설치 대상 PC**란 배포된 프로그램에서 관리자가 JSON 복원을 실행하는 기기다. 개발 PC의 데이터를 설치 파일에 자동 포함하거나 다른 기기로 전송한다는 뜻이 아니다. 예를 들어 A 기기의 JSON 백업을 새 B 기기에 선택해 복원하면, 직원·근무·승인 같은 업무 데이터는 선택한 JSON에서 오고, 폴더 경로는 B 기기에 설정된 값 또는 B 기기의 기본값을 사용한다. B가 처음 설치된 기기라면 “기존 경로 유지”는 A나 개발 PC의 경로를 가져오는 것이 아니라 **B의 초기 기본 경로 사용**을 뜻한다.

| 분류 | 키 | 승인 복원값 |
|---|---|---|
| 설치 대상 기기의 경로 | `pending_dir`, `approved_dir`, `schedule_export_dir`, `allowance_proposal_export_dir`, `allowance_attachment1_export_dir`, `allowance_attachment2_export_dir`, `database_backup_dir` | 복원 실행 기기에 설정된 값 또는 그 기기의 기본값 |
| 이번에 선택한 입력 | `migration_file_path` | 선택한 JSON 백업 경로 |
| 설치 대상 기기의 운영 설정 | `holiday_api_base_url`, `database_backup_schedule`, `database_backup_time`, `update_last_seen_patch_note_version`, `update_last_skipped_version`, `substitute_allowance_policy_reparse_marker` | 복원 실행 기기의 값(없으면 그 기기의 기본값). 정책 날짜가 바뀌면 재해석 표지는 기존 서비스 규칙에 따라 새로 설정 |
| 업무 규칙 | `schedule_consecutive_night_limit`, `schedule_minimum_rest_minutes`, `schedule_require_weekly_holiday`, `schedule_weekly_max_minutes`, `substitute_allowance_policy_effective_from`, `changed_slot_priority_effective_from` | 백업의 값 |

키 중복·알 수 없는 키는 무시하지 않고 중단한다. 업무 규칙 6키가 원본에 없다면 대상 기기 값을 조용히 대신 쓰지 않고 복원 불가로 알린다. 빈 문자열인 정책 시작일은 유효한 값이다. 승인된 키별 변환을 사전에 계산하고 미리보기의 `app_setting_entries` 행 수·경고에 반영한다. 적용 시 설치 대상 기기의 환경값을 보존하되 다른 39표를 승인된 DEC-001 예외 외에는 정확히 복원한다. 현재 대상의 정책 시작일과 JSON 값이 달라졌다면 기존 `app-settings-storage-service.ts`의 대기 파일 재해석 표지 규칙을 유지한다. 설정값의 `updated_at`은 변환 결과로 별도 기록·검증하고, 원본 JSON은 바꾸지 않는다. source/target 키별 차이를 시험과 검증 스크립트로 증명한다.
