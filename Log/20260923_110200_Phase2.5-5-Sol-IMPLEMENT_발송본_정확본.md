## 6. Sol의 코드 전략 — 이 순서대로 구현

### 6.1 도메인·검증부터 연다

1. `document-layout.ts`에 PDF compatibility와 ordered 7-key 상수를 추가한다. Excel 5-key 상수는 유지한다.
2. definition service에 설계 §5의 `proposal-pdf` 3 outputs와 dashboard 1 output을 추가한다.
3. validation을 output loop로 바꾼다. 모든 오류 path가 실제 `outputs[i]`를 가리켜야 한다.
4. capability를 모든 output의 block으로 평탄화하고 title+logo 조합을 지원한다.
5. `cell`은 정수, `mm`은 유한 실수; canvas/flow/page 구조는 보호한다. PDF flow collision은 검사하지 않는다.
6. storage/preview gates를 ordered 7-key 집합으로 바꾼다.

정확한 block ID·좌표·pattern·column weights는 구현 설계 §5를 복사한다. PDF용 저수준 JSON은 만들지 않는다.

### 6.2 공용 파일명과 로고를 정리한다

1. Excel render service의 token 타입에 `name`, `timestamp`를 추가하고 kind별 validator와 공용 path resolver를 재사용한다.
2. 수당 PDF pattern은 `{year}년/{month2}월/{year}_{month2}_{문서}.pdf`다. `{month}`를 새 token으로 만들지 않는다.
3. dashboard pattern은 `{name}_{timestamp}.pdf`; 파생 `name`과 timestamp는 보호 데이터다.
4. logo service가 PNG buffer/data URL을 제공하게 하고 allowance PDF의 `nativeImage` 정규화·별도 탐색을 삭제한다.

### 6.3 공용 Chrome renderer를 만든다

1. CommonJS 빌드에서도 native ESM import가 유지되는 loader로 `find-chrome.mjs`를 읽는다.
2. finder 규칙을 복사하거나 다른 실행 파일 후보를 만들지 않는다.
3. `page.setContent` → `document.fonts.ready` → exact `page.pdf` options를 쓴다.
4. route interception으로 외부 request를 막고 timeout을 30초로 묶는다.
5. PDF header/length를 검증한 뒤 bytes만 반환한다.
6. same-directory `wx` temp + exclusive final commit을 별도 함수로 두고 cleanup한다.

### 6.4 allowance 3파일을 연결한다

1. 기존 계산·표/차트 HTML 생성은 보존한다.
2. wrapper에 block ID를 붙이고 built-in 대비 active delta를 inline CSS/attribute/colgroup으로 적용한다.
3. 기본 definition에서는 현재 HTML/CSS가 의미상 동일해야 한다.
4. export service PDF 분기가 active `proposal-pdf` snapshot과 세 member pattern을 사용하게 한다.
5. 세 HTML을 모두 bytes로 렌더한 뒤 batch commit한다. 성공 전 export DB record를 쓰지 않는다.

### 6.5 dashboard를 복구한다

1. V3.4 service에서 XLSX writer와 기존 test 의미만 이식한다.
2. Electron PDF 구현은 가져오지 않고 active dashboard definition + 공용 renderer로 작성한다.
3. chart columns 0은 거절, rows 0은 허용한다. report sections 0은 거절하고 section rows 0은 허용한다.
4. image data URL을 전체 선검증한다: PNG/JPEG만, canonical base64, 실제 signature, 최대 10MiB.
5. 동적 문자열을 모두 escape하고 script/외부 URL을 생성하지 않는다.
6. core route는 `runIpcSaveDialogResultAction`/`runIpcResultAction` 계열과 다른 route의 `trackSuccess` 모양을 따라 성공만 기록한다.

### 6.6 production preview를 연결한다

1. allowance synthetic data로 writer 한 번을 불러 PDF 3개를 만든다.
2. dashboard synthetic 2-section PDF로 page-break와 빈/비빈 표를 같이 검증한다.
3. artifact 순서와 media type을 definition과 일치시킨다.
4. 기존 UUID/TTL/containment/symlink cleanup을 완화하지 않는다.

### 6.7 의존성과 문서를 마지막에 맞춘다

1. package에서 playwright를 dependencies로 이동, electron 제거 후 lock만 기계적으로 동기화한다.
2. vendor 3파일을 삭제한다.
3. smoke를 정확히 80으로 바꾸고 codebase map 네 항목을 실제 상태로 고친다.

### 6.8 최소 변경 원칙

- 요구사항과 직접 연결되지 않은 이름 변경·정렬·포맷 변경을 하지 않는다.
- 전체 파일 재생성보다 필요한 hunk를 바꾼다.
- existing tests를 삭제·skip·only 처리하지 않는다.
- 구현이 시험을 만족하게 하며, 시험을 구현 결과에 맞춰 약화하지 않는다.
- 공개 계약 변경이 필요해 보이면 구현하지 말고 `BLOCKED`로 반환한다.

## 7. 필수 불변조건과 함정

- data URL MIME만 믿고 SVG/HTML/fake bytes를 통과

- preview에서 fake bytes나 별도 renderer 사용

- Electron vendor만 지우고 import/lock 잔재를 남김
- 기존 42-path 작업 트리를 자기 작업으로 간주해 재생성/정리
