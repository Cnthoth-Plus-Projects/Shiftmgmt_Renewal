## 4. 결함 대조

### D25-2-004 — runtime complete schema validator 실패

`src/main/services/built-in-excel-layout-service.ts`의 validator는 상위 object와 허용 key 일부만 확인하고, 실제 소비되는 중첩 필드 타입·enum을 검사하지 않는다.

확인된 구현:

- `worksheet.properties`, `views[]`, `pageSetup`, `pageSetup.margins`, `headerFooter`는 object/array 여부만 확인한다.
- tagged value는 formula 문자열 또는 richText 배열 존재 정도만 확인한다. formula `result`, richText part, date, hyperlink, error의 타입과 조합은 확인하지 않는다.
- `font`와 `alignment`는 알려진 key인지까지만 확인하고 각 값의 타입·enum을 확인하지 않는다.
- `border`는 side 자체의 object 여부, `style` enum, nested color를 확인하지 않는다.
- `fill`은 `type`만 제한하고 pattern/gradient/degree/stops와 중첩 stop을 확인하지 않는다.
- `protection.locked/hidden`의 boolean 타입을 확인하지 않는다.
- 관련 음성시험은 `font` 전체를 문자열로 바꾸거나 `formula` 자체를 숫자로 바꾸는 얕은 손상만 검사해 중첩 손상을 놓친다.

독립 실행에서 아래 13개 손상 입력이 모두 `ACCEPTED` 됐다.

```text
ACCEPTED worksheet.properties.defaultColWidth
ACCEPTED worksheet.views[0].state
ACCEPTED worksheet.pageSetup.orientation
ACCEPTED worksheet.headerFooter.differentFirst
ACCEPTED cell.value.formula.result
ACCEPTED cell.value.richText.text
ACCEPTED cell.value.date
ACCEPTED cell.value.hyperlink
ACCEPTED cell.font.bold
ACCEPTED cell.alignment.horizontal
ACCEPTED cell.border.top.style
ACCEPTED cell.fill.pattern
ACCEPTED cell.protection.locked
```

대표 실제 손상 값:

```text
worksheet.properties.defaultColWidth = "bad"
worksheet.views[0].state = "sideways"
worksheet.pageSetup.orientation = "diagonal"
worksheet.headerFooter.differentFirst = 1
cell.value.formula.result = Symbol("bad")
cell.value.richText[0].text = 123
cell.value.date = 123
cell.value.hyperlink = 1
cell.font.bold = "yes"
cell.alignment.horizontal = "sideways"
cell.border.top.style = 123
cell.fill.pattern = 123
cell.protection.locked = "yes"
```

기대 결과는 layout key와 실제 field path를 포함한 한국어 오류였으나 실제 결과는 전부 수락이다. **D25-2-004 FAIL**.

### D25-2-005 — generator 동등 validator 실패

`scripts/generate-built-in-excel-layouts.mjs`의 `validateLayoutSchema`가 runtime validator의 얕은 구현을 그대로 반복한다.

동일한 13개 손상 입력을 generator validator에 직접 주입한 결과도 전부 `ACCEPTED`였다. 잘못된 layout이 메모리에 들어오면 schema 단계에서 차단되지 않으므로 “모든 schema 검증 후에만 staging” 계약을 충족하지 못한다. **D25-2-005 FAIL**.

### D25-2-003 — full parity helper 불완전

recursive 비교로 상당 부분 개선됐고 theme 변조 음성시험은 동작한다. 그러나 지시된 full equality 계약과 다음 차이가 남는다.

- formula는 primitive를 그대로 보존하지 않고 `String(obj.formula)`로 강제 변환한다.
- formula `result: null`은 보존하지 않고 누락한다. 명세는 `undefined`만 제외하도록 했다.
- 빈 object는 `undefined`로 축약해 `{}`와 필드 부재를 같게 본다.
- column/row는 표본 필드가 `undefined`이면 generated 쪽의 예기치 않은 width/hidden/outline 값을 검사하지 않는다.
- pageMargins는 표본 쪽이 `undefined`이면 generated 쪽의 예기치 않은 값을 검사하지 않는다.
- headerFooter는 일부 text field가 truthy일 때만 전체 비교해 flag-only 차이를 놓칠 수 있다.

따라서 “실제 전체 field deep equality” 주장은 과장되어 있으며 **D25-2-003 FAIL**이다.

### D25-2-008 — attachment2 canonical 값과 styleSpec

writer는 canonical `별첨2/B1/G2/row5`를 유지하고 동적 작성 뒤 `applyDocumentTemplateStyleSpec`을 호출한다. 실제 write/reopen 테스트에서 noncanonical `Z99/F99/9`는 값 배치에 쓰이지 않고 G2 fill/alignment와 D2:F2 merge가 반영된다. **D25-2-008 PASS**.

다만 회신의 “test 14” 표현과 달리 해당 styleSpec 검증은 `allowance-document-export-service.test.ts`의 첫 종합 export 시험에 추가됐다. 기능 결과는 확인했으나 회신의 시험 위치 설명은 정확하지 않다.

### D25-2-011 — definition 격리

validated static definition을 JSON-safe deep clone으로 반환하며, 기존 test 8에서 반환 객체와 첫 workbook 변조가 다음 호출에 누수되지 않음을 확인한다. **D25-2-011 PASS**.
