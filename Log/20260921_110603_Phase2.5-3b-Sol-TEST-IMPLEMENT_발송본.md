## 6. Sol의 코드 전략 — 순서 고정

### 6.1 신규 helper

`src/test-utils/document-layout-semantic-snapshot.ts`에 현재 `extractWorksheetSemanticSnapshot`을 옮긴다.

- `node:crypto`와 필요한 ExcelJS type만 import한다.
- cell value/formula/numFmt/font/alignment/border/fill/protection, merges, row height/hidden/outlineLevel, column width/hidden/outlineLevel, worksheet properties/views/pageSetup/headerFooter, image `type/tl/br/editAs`를 현재 의미 그대로 유지한다.
- embedded image는 `imageId`, workbook media, `buffer`가 없으면 `SNAPSHOT_IMAGE_MEDIA_FAILED`처럼 검색 가능한 오류를 throw한다. 빈 값으로 삼키는 `catch {}`를 두지 않는다.
- image마다 SHA-256, extension, media kind와 extension에서 파생한 MIME content type을 반환한다. `png→image/png`, `jpeg→image/jpeg`, `gif→image/gif`; 알 수 없는 extension은 throw한다.
- `describe`, `it`, `test`, `expect`, `vi`, hook, temp directory, product service import를 넣지 않는다.
- 파일명이 `.test.ts`가 아니고 `src/main`/`src/shared` 밖이므로 Vitest 자동 수집과 production server build 양쪽에서 제외된다. 이 위치를 바꾸지 않는다.

### 6.2 preview test

1. 현 파일의 `node:crypto` import와 helper 본문 전체를 제거한다.
2. `../../test-utils/document-layout-semantic-snapshot`을 static import한다.
3. 기존 E2 5키 2회 생성 시험 안에서 두 snapshot equality를 유지한다.
4. proposal/attachment1/attachment2에는 각 run의 image가 1개이고 media hash가 64자 lowercase hex, extension `png`, media kind `image`, content type `image/png`임을 직접 단언한다. schedule 2키는 image 0개를 단언한다.
5. 같은 E2 시험 안에서 image media lookup을 강제로 실패시킨 workbook을 helper에 넣어 `SNAPSHOT_IMAGE_MEDIA_FAILED`가 전파되는지 단언한다. 새 `it`을 추가하지 않는다.

### 6.3 renderer test
