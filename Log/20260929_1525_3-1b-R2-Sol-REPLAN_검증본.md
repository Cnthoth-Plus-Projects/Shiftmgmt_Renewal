## 3. 차단 결함 R31-R2-09 — 15초 제한이 적용되지 않음

`scripts/ui-checks/shell.mjs:322-326`은 `page.waitForFunction(fn, { timeout: 15_000 })`으로 호출한다. 설치된 `playwright-core/types/types.d.ts:702`의 호출 형식은 `waitForFunction(pageFunction, arg?, options?)`다. 따라서 두 번째 객체는 함수 인자로 전달되고 **세 번째 options의 timeout은 비어 있다**. `15_000`이 실제 시간 제한이 아니므로 R31-R2-08 / N-R2-04의 최대 15초 실패 조건은 구현되지 않았다. 최종 셸 PASS manifest는 상태줄이 정상적으로 숫자로 바뀐 사례만 보여 주며 제한 시간을 검증하지 않는다.

Sol이 설치 Chrome으로 외부 서버·DB 없이 인자 위치를 독립 재현했다. 페이지 기본 제한을 800ms로, 같은 잘못된 두 번째 인자의 제한을 100ms로 지정해 항상 false인 함수를 기다리자 **806ms** 뒤 `Timeout 800ms exceeded`가 났다. 100ms 객체가 제한 시간으로 쓰이지 않았다는 실측이다. 다음 계획에서는 세 번째 인자로 `undefined, { timeout: 15_000 }`을 전달하고, 일부러 상태줄이 숫자로 바뀌지 않는 음성 시험에서 실제 경과·FAIL을 기록해야 한다. 숨은 기본 제한이나 고정 sleep에 의존하면 안 된다.

Sol은 비밀값 노출을 늘리지 않기 위해 해당 이미지를 열거나 값을 출력하지 않았다.

다음 재계획은 복구 시험에서 임시 비밀번호가 화면에 실제로 표시됐는지 **값을 출력하지 않고** 검사하고, 메모리에서 재로그인에 사용할 값을 읽은 다음, 새 캡처에는 그 표시 영역을 가리거나 비밀이 보이지 않는 별도 화면만 담도록 명확히 지정한다. 과거 생성된 민감 캡처의 보존·접근 제한·처리는 별도 감사 항목으로 남긴다. 원본 이미지나 값은 핸드오프·보고에 싣지 않는다.
