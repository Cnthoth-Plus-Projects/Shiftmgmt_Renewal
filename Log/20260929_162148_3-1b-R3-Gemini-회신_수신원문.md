## 5. Sol의 파일별 코드 전략

### 5.1 기존 구조·데이터 흐름

진입점은 `login.mjs`의 `caseArg === "recovery"`와 `caseArg.startsWith("post-change-race-")`, `shell.mjs`의 5개 API 상태줄 비교다. `window.appBridge` 서버 응답이 제품 데이터 정본이며, 테스트는 실제 Chrome·격리 DB를 사용한다. `capture`는 공용 `runScreenCheck`가 manifest를 기록하는 기존 함수를 그대로 쓴다. 공용 helper에 마스킹 기능을 추가하지 않는다.

### 5.2 순서 있는 최소 변경

1. **복구 캡처를 먼저 고친다.** 이후에야 `--case=recovery`를 실행할 수 있다. `.temp-password-value`가 실제로 보이고 비어 있지 않은지 확인해 값을 로컬 변수에 읽는다. 값을 출력하거나 캡처하지 않는다. 같은 요소의 `textContent`를 명시적 가림 문구(예: “임시 비밀번호는 시험 캡처에서 가렸습니다”)로 바꾼 뒤 그 가림 문구가 DOM에 있는지 확인한다. 그 다음 기존 `capture`로 새 이름 `recovery-temp-password-redacted`를 찍는다. 로컬 변수의 원래 값으로 기존 재로그인·필수 변경 흐름을 계속 실행한다. 제품 화면 소스나 공용 캡처 helper를 수정하지 않는다. 이는 **시험 캡처용 DOM 가림**이며 복구 성공 여부를 가짜로 만들지 않는다. 과거 raw PNG를 RED 재현용으로 다시 만들지 않는다.
2. **로그인 경합 대기 2곳만 고친다.** `login.mjs`에서 `window.__sessionPromiseSettledCount >= 2`를 기다리는 기존 두 호출의 `{ timeout: 10_000 }`을 세 번째 인자로 옮긴다. 응답 도착·L1 입력/배너·새 `signIn` 계수·`changePassword` 1회 단언을 그대로 둔다.
3. **셸 대기 1곳만 고친다.** `shell.mjs`의 `#sb-pending` 숫자 조건 호출에서 `undefined, { timeout: 15_000 }`을 세 번째 인자로 전달한다. 시간 초과 시 마지막 UI 문구와 함께 FAIL하는 기존 catch를 유지한다. 이후 `listPendingFiles` API 결과와 UI 숫자의 정확한 일치 검사, DB/동기화/감시/업데이트 4개 API 검사도 그대로 둔다.
4. **최소 diff를 감사한다.** 이번 두 파일의 preflight·기존 시나리오 본문 전체를 재압축하거나 파일 크기를 맞추지 않는다. R2에서 발생한 489줄 시험 파일 diff를 이유 없이 더 키우지 않는다. 지시한 4개 호출점과 필요한 검사 문구 외 수정이 필요하면 `BLOCKED`로 돌려보낸다.

### 5.3 과거 실패의 사실/미확인 구분

R2 중간 FAIL은 `logoutAndBackToL1`의 15초 대기 실패이며 그 전에 두 캡처가 저장됐다. Tab/Enter 원인은 미확인이다. 새 실행에 FAIL이 생기면 경로·첫 오류·실행 시각·실제 캡처 파일명을 모두 보고하고, 원인 근거가 없으면 `UNKNOWN`이라고 쓴다. 최종 PASS가 중간 FAIL을 지우지 않는다.

## 8. 착수 게이트·중단 조건·회신

착수 전 `main`·전체 HEAD, 87경로 상태 SHA, 부록 A 모든 파일 SHA/`DELETED`를 실측한다. 2 허용 파일 시작 SHA와 `login.ts` 보호 SHA가 다르면 수정 없이 `BLOCKED`. 새 의존성·API/DB·제품 UI 수정이 필요하면 `BLOCKED`. 과거 민감 PNG의 처리를 Gemini가 임의 변경해야만 요구사항을 충족할 수 있다고 판단되면 `BLOCKED`로 충돌을 설명한다. 지시·소스·시험의 모순, 격리 Chrome 부재, 비밀 마스킹 실패, timeout 음성 시험 실패도 `BLOCKED` 또는 구현 중이면 `FAILED`다. 반복 자가 수정·시험 완화로 숨기지 않는다.

성공 조건: R31-R3-01~05 전부 위치와 실행 증거, 시간 제한 음성 probe RC 0, 최종 13 manifest PASS와 새 가림 이미지 존재, 보호 85경로 불변, 수정 제품 파일은 두 UI 스크립트만, 정적/전체/빌드 게이트 통과, 미보고 FAIL 0. 이 패킷은 과거 R2 원문 민감 증거를 새로 생성·삭제하는 권한이 아니다. Sol의 독립 검증 전에는 3-1b 완료나 3-1c 착수를 선언하지 않는다.

`## 회신`에는 판정, 초기 87상태 지문/부록 A 전건, R31-R2-09·10 원인→수정 위치→재현→결과 및 R31-R3-01~05, 두 허용 파일 전후 전체 SHA·diff, 85 보호 경로 불변, 명령 RC·시험 수·시각, timeout probe 실제 경과, 최종 13개와 중간 FAIL **모든** manifest 실제 경로·상태·Chrome/viewport/격리 폴더·오류 수·manifest가 기록한 실제 캡처 파일명, 복구 캡처 가림 확인·과거 raw 이미지 불변, 서버/임시 파일 정리, 미해결/UNKNOWN을 적는다. 비밀값과 민감 이미지는 회신에 싣지 않는다.
