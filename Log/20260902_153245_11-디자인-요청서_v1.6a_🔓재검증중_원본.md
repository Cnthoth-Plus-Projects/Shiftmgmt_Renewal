# B. 제품 배경

## B-1. 이 프로그램이 하는 일

교대근무 사업장의 **근무표를 만들어 배포하고 → 실제 근무 실적을 엑셀로 회수해 승인하고 → 연장·야간·휴일·대체 수당을 계산해 → 품의서와 별첨 서류를 만들어 내는** 프로그램입니다.

```
[준비]  ① 근무지 등록(조 구성·근무패턴·근무시간) → ② 인력 등록·배정·시급 등록
[운영]  ③ 근무표 생성 → ④ 근무표 배포(엑셀) → ⑤ 현장에서 실제 근무 손으로 기록
        → ⑥ 기록된 엑셀을 대기 폴더에 넣음 → ⑦ 프로그램이 자동으로 읽어 실적 행 생성
        → ⑧ 실적 승인 → ⑨ 승인과 동시에 수당 자동 계산
[정산]  ⑩ 수당 승인 → ⑪ 품의 승인(월 단위) → ⑫ 품의서·별첨1·별첨2 출력 → ⑬ 대시보드 집계
```

## B-2. 사용자

| 항목 | 내용 |
|---|---|
| 누구 | **비기술 한국어 운영자**(현장 운영자·사장). 개발 지식 없음 |
| 환경 | 윈도우 설치형, 사무실 PC, **마우스 + 키보드**. 터치 없음 |
| 화면 | **1440×900 기준** |
| 사용 빈도 | 매일. **월말에 집중**(실적 승인·수당 정산) |
| 데이터 양 | **한 달 실적이 수백~수천 행** |
| 성격 | **승인 실수가 곧 금액 사고.** 되돌릴 수 없는 동작이 많음 |

## B-3. 권한 4단계

🔴 **계단식이 아닙니다.** 계획 담당과 승인 담당은 **서로 상하 관계가 아니라 형제**입니다. (실제 코드 확인 결과)

```
                 관리자(admin)  — 전부 가능
                /            \
    계획 담당(planner)      승인 담당(reviewer)     ← 서로 권한이 겹치지 않습니다
                \            /
        사용자(operator) — 기본 권한 (조회 + 아래 주(註)의 실행 창구)
```

| 역할 | 볼 수 있는 화면 | 할 수 있는 것 |
|---|---|---|
| **사용자(operator)** | 홈·대시보드·인력·근무지·근무표·실적·수당 | 조회 + 아래 주(註)의 실행 창구<br>❌ **인력·근무지·패턴 등록/수정, 근무표 배포, 실적·수당·품의 승인은 못 합니다** |
| **계획 담당(planner)** | 위와 같음 | + 직원·시급·배정 등록·수정, 근무지·패턴 등록·수정, **근무표 생성·배포**<br>❌ **실적 승인·수당 승인은 못 합니다** |
| **승인 담당(reviewer)** | 위와 같음 | + **실적 승인·반려·되돌리기·재승인 확정**, **수당 승인·품의 승인**<br>❌ **직원 등록·근무지 등록·근무표 배포는 못 합니다** |
| **관리자(admin)** | 전체 + **운영 관리·활동 이력** | 전부 |

> **주(註) — `operator`도 실제로 실행되는 것이 있습니다 (v1.3 추가, 실제 코드 확인).**
> **수당 계산 실행 · 조기 지급일 지정 · 문서 재출력 · 시급 일괄 미리보기 · 시작 복구 다시 시도** 는 로그인만 되어 있으면 전 역할이 실행합니다.
> 🔴 **그러니 이 버튼들을 `operator` 화면에서 회색으로 그리지 마세요.** 실제 능력보다 좁게 그리는 것이 됩니다.
> 반대로 **시급 일괄의 `[적용]`** 은 `planner·admin`만 되므로, `operator`·`reviewer` 화면에서는 **비활성 + 사유 표시**로 그립니다(미리보기까지는 됩니다).

🔴 **"승인 담당 이상" 같은 표현을 쓰지 마세요.** 화면 문구에는 **역할을 직접 씁니다.**
예: `승인 권한이 필요합니다 (현재 권한: 계획 담당)`

### 🔴 `최근 인테이크` 칸의 문구 규칙

이 칸은 **"감시가 정상이다"를 뜻하지 않습니다.** 프로그램은 감시기가 살아 있는지를 일반 사용자에게 알려줄 방법이 없습니다. 그래서 **중립적으로만** 씁니다.

```
✅  최근 인테이크: 처리 이력 없음
✅  최근 인테이크: 읽는 중 34/120
✅  최근 인테이크: 해석 중
✅  최근 인테이크: 마지막 처리 완료 14:32      ← 시각 함께 표시
✅  최근 인테이크: 오류 1건
❌  ● 정상 감시 중                              ← 금지. 알 수 없는 사실입니다
❌  초록 점 + "이상 없음"                        ← 금지
```

### 🔴 `대기 파일 N개`와 `대기 실적 N건`은 다른 숫자입니다

| 표현 | 뜻 | 어디에 |
|---|---|---|
| **`대기 파일 N개`** | 아직 승인 안 된 **엑셀 파일 개수** | 하단 상태줄 |
| **`대기 실적 N건`** | 아직 승인 안 된 **실적 행 개수** | 홈 · 실적 관리 화면 |

둘 다 "승인대기 N건"으로 쓰면 같은 숫자로 오해됩니다. **단위를 반드시 붙여 주세요.**

- 기존 메뉴 **8개 이름은 그대로** 두고 그룹만 씌웁니다.
- 🔴 **홈을 거치지 않고 각 화면에 바로 들어갈 수 있어야 합니다.** 홈은 안내지 관문이 아닙니다.
- **홈 = 지금 할 일 / 대시보드 = 지나간 집계·차트·순위.** 역할이 다릅니다.

**세로 계산 (표 행 수의 근거)**

```
900 − 상단 제목줄 56 − 하단 전역 상태줄 32 = 본문 812px
812 − 필터바 56 − 표 머리글 40 − 위아래 여백 16 = 표 본문 700px
700 ÷ 40 = 17.5  →  약 17행
```

⚠️ **17행은 목표치이지 확정치가 아닙니다.** 위 계산에는 가로 스크롤바(약 12px), 그룹 머리(근무지별 묶음), 윈도우 창 테두리가 아직 안 들어갔습니다. 실제로는 **15~17행**이 될 수 있습니다. **시안에서 실제로 몇 행이 나오는지 세어 알려 주세요.**

> v1.5 참고 — 사용자 결정(2026-08-31)과 지시서가 확정한 ② 승인 작업 구조(작업공간 탭 48 + 필터·요약 통합줄 56 + ① 접힘 요약줄 40 포함)로 다시 계산하면 **넓게 15행**입니다: 812 − 48 − 56 − 40 − 40 − 16 − 12 = 600 = 40×15. 그룹 머리는 별도 행이 아니라 첫 열 rowspan이어야 15행이 유지됩니다.

**전역 상태줄(하단 32px)** — 이번 리뉴얼의 신설 요소.
- 어느 화면에 있든 **항상 보입니다.** 한 줄로 제한하고, 상세는 눌러서 엽니다.
- 문제가 생기면 해당 항목이 빨갛게 바뀌고, **눌러서 원인 화면으로 바로 이동**합니다.
  예: `● 폴더 감시 중단됨` 클릭 → 운영 관리 > 설정의 폴더 감시 영역  **(이 칸은 관리자에게만 보입니다)**

# E. 설계 원칙 8개 (모든 화면에 예외 없이)

### 원칙 1. 조치 가능한 0에만 이유를 붙인다 ★

| 구분 | 처리 |
|---|---|
| **업무상 이상하거나 조치 가능한 0** | 값 옆에 **한 줄 사유 칩**. 필요하면 다음 행동 버튼 |
| **정상적인 0** (예: 그 날 연장근무가 원래 없음) | 표에는 `0`만. 이유는 **행 상세**에서 |

```
좋음:  수당 0원  [지급 대상 아님 — 대체 투입자가 주간고정조]
좋음:  근무시간 0분  [8월 근무표 없음]   + 아래 안내 + [8월 근무표 만들기]
나쁨:  수당 0원  [아마 정책 때문인 듯]        ← 화면이 지어낸 이유
나쁨:  연장 0분  [연장근무 없음]              ← 정상인 0까지 다 설명 → 표가 뒤덮임
```

🔴 **정상적인 0까지 전부 설명하면 표가 사유 문구로 뒤덮입니다.** 조치 가능한 것만 강조하세요.
🔴 **사유 칩은 행 높이 40px 안에서 한 줄 말줄임**이 되어야 합니다. 긴 설명 때문에 행 높이가 들쭉날쭉해지면 안 됩니다. 전문은 마우스를 올리거나 행 상세에서 봅니다.

### 원칙 2. 확인창 4종 — 빨강은 파괴적 동작에만

| 종류 | 언제 | 버튼 | 보여줄 것 |
|---|---|---|---|
| ① 단순 확인 | 되돌릴 수 있지만 **작업 내용이 사라지는** 경우로 제한 | 기본 | 한 줄 |
| ② **위험 확인** | **실적 승인 · 품의 승인 · 근무표 게시** | **파랑 강조** | 대상 **건수·금액·기간**, 되돌릴 수 있는지, **실행 후 무슨 일이 벌어지는지** |
| ③ **파괴 확인** | **삭제 · 데이터베이스 교체** | **빨강** | ②의 내용 + "되돌릴 수 없음" 명시 |
| ④ 사유 입력 | 반려 · 승인 되돌리기 | 기본 | ②의 내용 + **사유 입력칸(필수)** |

🔴 되돌릴 수 있고 잃을 것도 없는 동작에는 **확인창을 띄우지 마세요.** 확인 피로가 생기면 사용자가 안 읽고 누릅니다.
🔴 **승인과 삭제를 같은 빨강으로 만들지 마세요.** 빨강이 흔해지면 위험 신호가 무뎌집니다.
🔴 **실행이 시작된 뒤에는 Esc로 닫히지 않고 재실행도 안 됩니다.** 진행 표시만 보입니다.

### 원칙 3. 권한 없는 버튼은 "포커스는 가되 눌리지 않게"

```
나쁨:  (버튼이 아예 없음)
나쁨:  일반 비활성 버튼 + 마우스 올리면 툴팁
       → 키보드·화면 낭독기 사용자는 이유를 영영 모름 (비활성 버튼은 포커스를 못 받음)
좋음:  포커스는 받되 눌리지 않는 버튼(aria-disabled) + 이유
       또는 버튼 옆에 항상 보이는 설명
       예: [승인]  승인 권한이 필요합니다 (현재 권한: 계획 담당)
```

**적용 범위**: 지금 권한으로 **들어갈 수 있는 화면 안의 작업 버튼**에만. 관리자 전용 메뉴(운영 관리·활동 이력) 자체는 권한이 없으면 **메뉴에서 안 보이는 게 맞습니다.**

### 원칙 4. 글자가 주인공, 색과 아이콘은 거들기

- 배지 10종에 색·글자·아이콘을 **같은 세기로 넣으면 표가 과밀해집니다.**
- **글자가 주 정보.** 색과 아이콘은 보조.
- **흑백으로 만들어도 구분되면 통과.**
- 장식용 아이콘은 화면 낭독기가 중복해 읽지 않게 처리(`aria-hidden`).

### 원칙 6. 못 쓰는 값을 몰래 바꾸지 않는다 ★★ 가장 중요

| 상황 | 처리 |
|---|---|
| 하루 교대 횟수를 줄여서 **선택했던 근무유형이 사라짐** | 🔴 **자동으로 다른 값으로 바꾸지 마세요.** `현재 설정에서 사용할 수 없는 값`으로 표시하고, **다음 단계 진행을 1-C 검토에서 막고**(1-B에는 저장 버튼이 없음 — v1.5 정정, §H-3), 사용자가 다시 고르게 합니다 |

**왜**: 사용자가 모르는 사이 데이터가 바뀌어 저장됩니다. 이 프로젝트에는 **"데이터를 조용히 잘라내거나 바꾸지 않는다"** 는 절대 규칙이 있습니다.

시안에 필요한 표현: **못 쓰는 값이 선택된 상태**의 모습 — 경고 색 + `사용할 수 없는 값` 라벨 + `다시 선택` 안내. **1-B의 두 이동 버튼(`[이전: 기본 설정]`·`[입력 검토]`)은 활성**이고, 차단은 **1-C `[다음 단계]` 비활성 + 사유**로 표현합니다(v1.5a 정정 — §H-3과 동일. 1-B에는 저장 버튼이 없습니다).

### 원칙 7. 오래 걸리는 작업 — 🔴 "멈춘다"고 약속하는 버튼을 그리지 마세요

**실제 프로그램에 이미 시작된 작업을 중단하는 기능이 하나도 없습니다.** (소스 코드에서 `cancel`·`abort` 검색 결과 0건) 진행 중 화면에 `[취소]`를 그리면 눌러도 아무 일이 안 일어나는 가짜 버튼이 됩니다.

**진행 수치(`34/120`)를 쓸 수 있는 작업도 딱 2개뿐입니다.**

| 작업 | 표시 |
|---|---|
| **엑셀 인테이크**(대기 폴더 자동 읽기) | ✅ `해석 중 34/120` — 실제 수치가 옴 |
| **앱 업데이트 내려받기** | ✅ `내려받는 중 62%` — 실제 수치가 옴 |
| **그 외 전부** (패턴 역추출 · 품의 승인/문서 생성 · DB 교체 · 실적 전체 조회 · 배포 엑셀 생성 · 시급 일괄 적용) | ⚠️ `처리 중…` **불확정 표시만.** 숫자 금지 |

**시안에 그릴 것**

```
✅ 진행 중:  처리 중…                        (또는 인테이크만 34/120)
✅ 진행 중:  주변 버튼이 잠긴 모습
✅ 진행 중:  "중단할 수 없는 작업입니다. 완료될 때까지 이 화면을 유지해 주세요."
✅ 실패:     이유 + [다시 시도]
❌ 실행 중 작업을 멈춘다는 뜻의 [취소]·[중단]   ← 삭제
❌ 인테이크·업데이트 외 작업의 N/M 숫자         ← 삭제
```

🔴 **금지 대상을 정확히 하겠습니다.** 없애야 하는 것은 **"이미 시작된 작업을 멈춘다"고 약속하는 버튼**뿐입니다. 아래는 **그대로 두세요.**

| 그대로 두는 것 | 왜 |
|---|---|
| **실행 전** 확인 모달의 `[돌아가기]` / `[취소]` | 아직 아무것도 시작되지 않았습니다 |
| 저장 전 이탈 모달의 `[계속 편집]` / `[변경 버리고 나가기]` | 작업 중단이 아닙니다 |
| 파일 선택창의 `[취소]` | 윈도우 대화상자입니다 |
| 실패 후 `[다시 시도]` | 같은 작업을 다시 부르면 됩니다 |

**화면을 떠났다 돌아왔을 때**: 인테이크는 상태를 다시 조회할 수 있으니 **진행 상태를 복구해 보여줍니다.** 패턴 역추출·문서 생성·DB 교체는 조회 창구가 없으므로 **실행 중에는 화면을 떠날 수 없게 잠급니다.**

## 🔴 I-1. 1차 검수용 파일에는 **최소한의 JavaScript가 필요합니다**

이 리뉴얼에서 가장 검증하고 싶은 것이 **키보드 조작과 포커스**입니다. 정지된 그림만으로는 확인할 수 없습니다. 아래 4가지는 **실제로 동작해야** 합니다.

| 동작해야 할 것 | 확인 방법 |
|---|---|
| 메뉴·탭 이동과 **보이는 포커스 링** | Tab 키를 눌러 이동해 본다 |
| 실적 표에서 **↑↓ 행 이동 / Space 선택 / Enter 상세** | 마우스 없이 승인 대상 행을 고를 수 있는가 |
| **실행 전 모달** 열기 → 포커스 가둠 → Esc 닫기 → 원래 버튼으로 복귀 | Tab을 계속 눌러도 모달 밖으로 안 나가는가 |
| **포커스 가능한 비활성 버튼**(`aria-disabled`)에 포커스가 가고 이유가 읽히는가 | 권한 없는 버튼에 Tab으로 닿는가 |

애니메이션·데이터 연동·라우팅은 필요 없습니다. **위 4가지만** 되면 됩니다.

**함께 알려 주세요**: 1440×900에서 실적 표가 **실제로 몇 행 보이는지** 세어서 회신에 적어 주세요. (가로 스크롤바·그룹 머리 포함)
