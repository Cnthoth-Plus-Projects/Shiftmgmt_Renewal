**3. 잔여 1 — 셸 6개의 숨김 속성과 포커스 충돌 / 판정 항목 ① DISAGREE**

대상은 `00-shell-1.html` **:526 / :582 / :642**의 S1~S3, `00-shell-2.html` **:528 / :595 / :663**의 S4~S6이다. 모두 다음 형태다.

```html
<main class="page-content" id="main-content-s1" tabindex="-1" aria-hidden="true">
```

빈 셸에 본문 글자·조작 요소가 없다는 설명은 사실이다. 그러나 이번 N2가 그 main을 **포커스를 받는 skip-link 대상**으로 바꿨으므로 기존의 숨김 속성을 그대로 유지하는 것은 타당하지 않다. [W3C ARIA in HTML §4.2](https://www.w3.org/TR/html-aria/#requirements-for-use-of-aria-attributes-in-place-of-equivalent-html-attributes)는 focusable 요소를 aria-hidden 허용 대상에서 제외하며, `tabindex="-1"`도 focusable임을 명시한다.

**실제 관찰을 구분한다:** 포커스 전에는 CDP AX `ignored=true`, 사유 `ariaHiddenElement`. Enter 후 DOM 속성은 여전히 true지만 Chromium은 이를 무시하여 **AX main을 노출**하고, 6/6에서 `Blocked aria-hidden` 경고를 기록한다. 따라서 “현재 Chromium에서도 포커스가 영원히 낭독 트리에서 사라진다”는 판정은 하지 않는다. 키 이동은 성공하지만 브라우저의 오류 보정에 의존하는 속성 충돌이 남아 있다.

**최소 수정:** 이 여섯 main에서만 `aria-hidden="true"`를 제거하고 id·tabindex·기존 내용은 유지한다. 이를 다음 지시서의 허용 hunk에 명시한다. 파일에 쓰지 않은 메모리상 대안 검사에서 **6개 모두 제거 전후 x/y/폭/높이 동일**했다. 본문이나 버튼을 새로 만들 필요가 없으며, HANDOFF §4의 “승인본 배치 변경”이라는 설명도 맞지 않는다. 수정 뒤 6상태의 실제 키·AX·경고를 다시 확인한다. R5처럼 읽을 목록은 있고 조작 요소가 없는 main에서 다음 Tab이 다음 상태로 넘어가는 것은 정상이다.
