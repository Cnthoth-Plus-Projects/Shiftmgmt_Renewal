# 09. 시안 발주서 (화면 인벤토리)

> 새 UX/UI 시안을 요청할 때 그대로 전달하는 문서.
> **여기 적힌 화면과 상태를 전부 덮어야** 개발 단계에서 급조하는 일이 없다.
> ✏️ **정정 이력**: 2026-09-06 (0-18c, 합의표 v1.2 B-5 — Codex AGREE 17:31) §2.2 **수당 관리 행 개정** — "요약+차트+결과표" → 정규/조기 지급 요약 + 결과표 + 계산 근거 + 품의 미리보기/승인 · 문서 출력. **추이·구성 차트는 대시보드 몫**(홈 = 할 일 / 대시보드 = 집계·차트·순위, `10` §4). 수당 관리 시안(A1)이 대시보드(D1)와 같은 카드·도넛·월별 추이를 반복해 정보구조가 겹쳤기 때문. 다른 행은 그대로.

## 1. 제품 성격

| 항목 | 내용 |
|---|---|
| 무엇 | 교대근무 근무표 배포 · 실적 승인 · 수당 계산 데스크톱 프로그램 |
| 사용자 | **비기술 한국어 운영자**(현장 운영자·사장). 개발 지식 없음 |
| 환경 | 윈도우 설치형, 사무실 PC, 마우스+키보드, 화면 1440×900 이상 |
| 사용 빈도 | 매일 사용. 월말에 집중(실적 승인·수당 정산) |
| 데이터 밀도 | **높음.** 한 달 실적 수백~수천 행. 표 중심 |
| 성격 | 업무용 도구. 화려함보다 **정확하고 빠르게 찾고 처리하는 것**이 우선 |

### 감성 방향 (참고)
현재는 흰색 셸 + 파랑 계열 포인트(`#3e56b6`)를 쓴다. **남색(진한 네이비) 배경은 쓰지 않는다**는 기존 결정이 있다(가독성 문제). 새 시안은 자유롭게 제안하되, 표가 많은 화면에서 **글자 대비와 행 구분이 명확한지**를 최우선으로 본다.

## 3. 반드시 포함해야 할 상태

각 화면마다 아래 상태가 필요하다. 빠지면 개발 중에 급조하게 된다.

| 상태 | 왜 필요한가 |
|---|---|
| **로딩** | 수천 행 조회가 몇 초 걸린다 |
| **빈 상태** | "없습니다"가 아니라 **다음에 뭘 하면 되는지** 안내해야 한다 |
| **오류** | 한국어 메시지 + 조치 방법 |
| **권한 없음** | 버튼을 숨기지 말고 **비활성 + 이유 표시** |
| **처리 중** | 되돌릴 수 없는 동작(승인·배포·품의)의 진행 표시 |
| **경고가 붙은 행** | 실적 행마다 경고가 달릴 수 있다 |

## 4. 필요한 공통 컴포넌트

| 컴포넌트 | 요구사항 |
|---|---|
| **데이터 표** | 정렬·검색·필터·그룹 접기·가로 스크롤. **줄바꿈 대신 가로 스크롤** |
| **상태 배지** | 최소 10종: 승인 / 대기 / 반려 / 재승인 대기 / 재승인 완료 / 변경불가 / 수당 미지급 / 법정휴일 / 저장 전 / 정원 참 |
| **필터 바** | 기간(연·월) · 근무지 · 상태 · 검색어 |
| **날짜 입력** | **선택 즉시 반영**(확인 버튼 방식 금지). 연·월만 고르는 형태도 필요 |
| **숫자 스테퍼** | −/+ 버튼 + 직접 입력. 범위 제한 |
| **모달** | Esc 닫기, 포커스 가둠, 크기 3종(작음·보통·큼) |
| **마법사 단계 표시** | 1단계(하위 3단계) → 2단계 |
| **패턴 페인팅 스트립** | 1일차~N일차 칸을 클릭해 근무유형을 칠함. 끝에 추가(+) 칸 1개, 되돌리기 버튼, 가로 스크롤 |
| **시뮬레이션 달력** | 3개월. 날짜 칸마다 조×근무유형을 **색+글자 병기** |
| **조 카드** | 조 이름 + 인원/정원 + 명단 |
| **진행률 표시** | 인테이크·문서 생성 |
| **차트** | 도넛·막대·선 (echarts) |
| **파일 경로 표시** | 생성된 파일 경로 + 폴더 열기 버튼 |

## 5. 제약 사항 (반드시 지킬 것)

### 5.1 가짜 UI 금지 ★
**데이터와 동작이 없는 장식 요소는 시안에 있어도 만들지 않는다.**

과거에 시안에 있었지만 제거한 것들:
- 전화·메시지 버튼 (전화번호 데이터도, 발신 기능도 없음)
- 증명사진 자리 (사진 데이터 없음)
- 가짜 건수·가짜 증감률
- 동작 없는 눈 아이콘·삭제 아이콘
- 상단 통합 검색바 (검색 대상이 정의돼 있지 않음)
- 관리자 메모 카드 (저장할 곳 없음)

**시안 작성 시 판단 기준**: 각 요소에 대해 "이걸 누르면 무슨 일이 일어나고, 그 데이터는 어디서 오는가?"에 답할 수 있어야 한다.

### 5.2 아이콘
- 한 세트로 통일. 현재는 **Material Symbols** 글꼴 사용(유지 권장).
- 손으로 그린 SVG 아이콘을 화면마다 다르게 만들지 않는다.

### 5.3 라벨과 문구
- **모든 화면 문구는 한국어.** 영어 기술 용어를 그대로 노출하지 않는다.
- 오류 메시지는 "무엇이 잘못됐고 무엇을 하면 되는지"까지 쓴다.
- 용어는 01 문서의 용어집을 따른다(운영자가 쓰는 말 기준).

### 5.4 데이터 밀도
- 한 화면에 수백 행이 보여야 한다. **여백을 크게 잡는 디자인은 이 제품에 맞지 않는다.**
- 밀도 조절 토글(넓게/좁게)이 현재 있다. 유지 여부 검토 필요.

### 5.5 접근성
- 모든 조작 가능한 요소는 키보드로 접근 가능(Tab, Enter/Space).
- 색만으로 구분하지 않는다(**색 + 글자** 병기). 근무유형·상태 모두 해당.
- 모달은 Esc로 닫히고 포커스가 갇혀야 한다.

- [ ] 문구가 전부 한국어이고 용어집과 일치하는가
- [ ] 되돌릴 수 없는 동작에 확인 단계가 그려져 있는가
