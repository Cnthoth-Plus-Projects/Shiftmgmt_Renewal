### C1 — 한 블록의 문구 변경이 손대지 않은 다른 블록의 보호 글꼴을 바꾼다

실제 결과:

```text

E19:H19 font.size: 9 -> 11
D18:H18 style: {} -> { font: { name: "맑은 고딕", size: 11 } }
```

원인:

- `applyDocumentLayoutToWorksheet`가 변경이 하나라도 있으면 모든 블록을 캡처·재출력한다.
- 재출력 시 candidate font가 baseline과 같은지 확인하지 않고 모든 셀에 `cb.font`를 덮는다.
- 기본 block font는 사용자 override가 아니라 편집기 대표값인데, 이를 실제 셀마다 강제해 low-level 자산의 9pt/12pt 등 내부 서식 토폴로지를 평탄화한다.

교정:

1. candidate와 baseline의 **속성별 delta**만 사용자 override로 적용한다.
2. font가 바뀌지 않은 블록은 캡처 전 스타일을 셀 단위로 정확히 복원한다. 빈 셀에 새 font/style을 만들지 않는다.
3. 한 블록 변경이 다른 블록의 값·스타일·병합·행 높이·열 너비·이미지에 영향을 주면 실패다.
4. 기본 정의와 동일한 font 객체를 실제 workbook 전체에 다시 칠하는 방식은 금지한다.

필수 회귀:

- 최소 명시 셀 `B18` 12pt, `E19` 9pt, `D18` 빈 style이 유지돼야 한다.

## 3. 완료 증거 공백

### E1 — definition/render 완료 주장이 현재 시험보다 넓다

현재 renderer 시험 7개 중 실제 workbook 시험은 schedule 정적 제목/설명 한 건뿐이다. 다음 회신 주장은 직접 검증되지 않았다.

- 기본 5키 actual output의 값·병합·폭·높이·글꼴·정렬·테두리·채움·숫자 형식·worksheet 설정 100% parity

`hasDocumentLayoutModifications=false`만으로 actual output semantic parity를 시험했다고 보고하지 않는다.

### E2 — 결정성 시험이 전체 semantic snapshot이 아니다

현재 preview 결정성 시험은 attachment1 한 키에서 `1..25행 × 1..15열`의 **cell value만** 비교한다. 병합·서식·이미지·행 높이·열 너비·worksheet 설정을 비교하지 않으며, 25행 뒤의 상세/요율 안내도 보지 않는다.

교정 시험은 최소 다음을 정규화해 두 빈 디렉터리 결과를 비교한다.

- 모든 실제 사용 셀의 value/type/formula/numFmt/font/alignment/border/fill/protection
- 전체 merge 목록
- 실제 row height/hidden/outline, column width/hidden/outline
- worksheet properties/views/pageSetup/headerFooter/printArea
- 이미지 media hash/type와 oneCell anchor/editAs (workbook 내부 imageId 자체는 의미 비교에서 제외 가능)
- 5개 key 전부 또는 공통 helper를 통한 5키 표본

ZIP timestamp/raw bytes만 비교하지 않는다.

### E3 — 무DB·old preview/sourcePath 미호출 주장이 시험으로 입증되지 않았다

현재 preview 시험에는 business DB row count/canonical hash 대조, storage spy, old preview/sample/sourcePath poison spy가 없다. 코드가 현재 직접 호출하지 않는다는 정적 관찰은 했지만 회신의 시험 PASS 주장으로는 부족하다.

교정:

- preview 전후 격리 business DB의 표별 row count와 canonical hash가 같음을 검사하거나 storage 접근을 fail-fast spy로 막는다.
- `document-template-preview-service`, legacy sourcePath/sample loader가 호출되면 즉시 실패하는 spy 또는 import-boundary 검사를 둔다.
- invalid draft는 outputDir가 처음부터 없던 경우에도 폴더/파일을 만들지 않는 반례를 추가한다.

### E4 — 회신의 parser save code 표기가 실제 계약과 다르다

회신은 `PARSER_TABLE_POSITION_IMMUTABLE`을 적었지만 실제 안정 code는 `SCHEDULE_PARSER_POSITION_NOT_ACTIVATABLE`이다. 제품 계약은 후자를 유지하고, 시험과 다음 회신도 정확한 code를 적는다.
