1. 하나의 separator-aware 포함 판정을 만든다. `path.relative(root, candidate)` 결과가 빈 값/절대 경로/`..`/`..${path.sep}` 시작이면 경계 안으로 인정하지 않는다. 문자열 `startsWith(root)`는 사용하지 않는다.
2. manifest item에서 절대 `filePath`를 제거한다. 저장 가능한 파일명은 비어 있지 않은 단일 segment여야 하며 `.`, `..`, `/`, `\`, 절대 경로를 거절한다. generator의 `fileName`, `filePath` basename/실제 위치가 서로 맞지 않으면 생성 실패다.
3. 생성 결과를 manifest에 넣기 전에 아래를 모두 검증한다.
   - `tempRoot`와 `outputDir`의 canonical/real path 관계가 경계 안이다.
   - `outputDir`은 symlink/junction가 아닌 실제 directory다.
   - artifact는 `outputDir` 바로 아래의 검증된 파일명으로 계산한 대상과 일치한다.
   - `lstat`상 실제 regular file이고 symlink가 아니다.
   - artifact realpath가 outputDir realpath 안이다.
4. 검증을 포함한 create 전체 실패 경로에서 아직 등록되지 않은 자신의 outputDir만 정리하고 원래 오류를 보존한다. malformed generator 결과를 manifest에 일부라도 남기지 않는다.
5. resolve 때도 manifest 값을 다시 신뢰하지 말고 같은 파일명·directory·`lstat`·`realpath` 경계를 재검증한 뒤에만 `readFileSync`한다. 생성 뒤 디렉터리나 파일이 symlink/junction로 바뀐 경우 null이다.
6. expiry/`clear()` cleanup은 검증되지 않은 symlink/junction 또는 tempRoot realpath 밖을 recursive하게 따라가지 않는다. 안전을 증명할 수 없으면 외부 대상을 건드리지 않고 manifest만 제거한다. 정리 오류는 기존처럼 조회 결과를 노출시키지 않는다.
7. 새 dependency, 공개 API, 오류 fallback을 만들지 않는다. 작은 private helper로 중복 검증을 묶는 것은 허용한다.

#### 2) `document-layout-preview-artifact-service.test.ts`

1. 앞의 정상/stale/PDF/유효 resolve/만료 5개 `it`는 유지한다.
2. 여섯 번째 `it`를 실제 공격 증거로 교체·강화한다. 한 `it` 안의 여러 하위 시나리오는 허용하지만 총 `it`는 정확히 6개다.
3. 최소한 아래를 모두 증명한다.
   - 고정 UUID의 outputDir과 접두어가 같은 sibling(예: `<uuid>-evil`)에 sentinel 파일을 실제 생성하고, malicious generator가 그 절대 경로를 반환하면 `createPreview`가 reject하며 manifest/preview URL이 생기지 않고 sentinel bytes는 보존된다.
   - 정상 artifact로 실제 manifest를 만든 뒤 outputDir 또는 artifact 경계를 symlink/junction로 외부 sentinel에 돌리는 공격을 구성한다. `resolveArtifact`는 null이고 `clear()`/만료 cleanup 뒤에도 외부 sentinel bytes가 그대로다. Windows에서는 권한 없는 file symlink에 기대지 말고 directory junction 등 안정적인 동등 수단을 사용하며, 다른 OS에서는 directory symlink를 사용한다.
   - 잘못된 UUID/member와 없는 manifest는 계속 null이다.
4. 공격 준비가 실패했는데 시험을 skip/pass 처리하지 않는다. 플랫폼별 준비 코드는 명시적으로 성공을 assert한다.

#### 3) `scripts/smoke-require.mjs`

1. 기대 서비스 수 `77`을 실제 `78`로 바꾼다.
2. 그 숫자에 직접 연결된 주석/진단 문구가 있으면 같이 `78`로 맞춘다.
3. 서비스 glob, require 반복, 누락/초과 실패 로직은 그대로 둔다.

### 6.3 최소 변경 원칙

- 위 세 파일의 필요한 hunk만 바꾼다. 포맷/이름/주석의 광역 정리를 하지 않는다.
- 테스트를 구현에 맞춰 약화하지 않는다. 외부 sentinel 보존과 bytes 비노출이 실제 결과여야 한다.
- 기존 39경로 집합, 공개 계약 107개/operations 36개, 집중 68개, 전체 828개를 유지한다.

## 7. 적용할 불변조건과 과거 함정

### 7.1 필수 불변조건

- 서버측 파일·권한 경계는 UI나 URL 형식에 기대지 않고 서비스에서 재검증한다.
- 미리보기 artifact는 OS temp 아래에만 존재하고 repo/dataDir/DB에 남기지 않는다.
- manifest에는 안전한 상대 파일명만 두고 generator의 절대 경로를 권한처럼 사용하지 않는다.
- 관리자 인증/no-store/raw bytes, 10분 TTL, stale revision, PDF 비노출을 보존한다.
- 조용한 fallback이나 외부 파일 노출은 금지한다. 안전을 증명할 수 없으면 null/reject로 닫는다.
- 사용자 데이터와 V3 원본은 수정하지 않는다.

### 7.2 반드시 피할 과거 실패

- 경로 문자열 접두어 비교를 디렉터리 포함 판정으로 사용하는 것.
- `existsSync`만 보고 symlink/junction의 실제 대상을 읽거나 recursive delete하는 것.
- manifest가 없어 일찍 null이 된 결과를 traversal 차단 증거로 오인하는 것.
- `npm run smoke` 기대 개수만 낮추거나 새 파일을 열거에서 제외하는 것.
- self-report SHA나 시험 결과를 추측하는 것. 명령에서 얻은 full SHA/종료 코드만 회신한다.
