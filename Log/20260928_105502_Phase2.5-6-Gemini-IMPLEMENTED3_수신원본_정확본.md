## 4. Sol의 새 코드 전략 — 선택 여지 없이 이 순서로

1. `database-backup-service.ts:61-104`의 생성 계약을 기준으로 한다. 버전 1 JSON은 `SELECT *` 행을 `JSON.stringify`한 것이다. 현재 V4 40표의 `PRAGMA table_info` 실측은 **456열: TEXT 378, INTEGER 72, REAL 6, 명시적 NOT NULL 277**이다. 첫 행을 표본으로 타입을 추론하지 않는다. `sqlite-storage-service.ts`의 스키마를 격리 DB에서 읽어 열별 SQLite 선언 타입과 `notnull` 메타데이터를 뽑아, 기존 `TABLE_SCHEMA_COLUMNS`와 함께 **고정된 입력 계약**으로 서비스에 둔다. 런타임 검사를 위해 운영 DB·전역 SQLite 연결을 열거나 교체하지 않는다. 기존 열 이름 목록과 타입/NULL 계약이 분리돼도 좋지만, 한 열의 규격이 둘 사이에서 빠지지 않게 아래 2번 시험으로 잠근다.
2. 시험에서 격리 DB를 `initializeSqliteStorage`로 만들고 `PRAGMA table_info`를 읽는다. **40표/456열 전체의 이름·선언 타입·NOT NULL** 정합성은 내부 규격을 새 API로 `export`하지 않고 공개된 `checkDatabaseMigrationRequirements`의 동작으로 대조한다. 표별 빈 배열과 유효한 6개 업무 설정을 기본 fixture로 둔다. 열 하나를 시험할 때는 PRAGMA의 모든 열을 갖춘 합성 행을 만들고 TEXT에는 문자열, 숫자 열에는 숫자, nullable 열에는 `null`을 채운 뒤 해당 열만 잘못된 타입 또는 금지된 `null`로 바꿔 거절을 검사한다. 값의 의미를 추가로 요구하는 `app_setting_entries` 6키는 기존 전용 시험을 사용한다. 각 표의 열 누락·추가 시험도 포함한다. 시험 종료 후 연결과 격리 파일을 정리하고 보호 스키마 파일은 수정하지 않는다.
3. `validateTableRowsSchema`가 **첫 행 포함 모든 행**에 대해 누락·추가 열을 검사한 직후 각 셀을 검사한다. `TEXT`는 문자열, `INTEGER`/`REAL`은 유한한 JavaScript 숫자만 받는다. 객체·배열·불리언·숫자 문자열을 암묵 변환하지 않는다. `null`은 스키마가 허용한 열에서만 받는다. 실제 V3 JSON에는 **INTEGER 선언 열의 소수 숫자 180개**가 있다(`allowance_calculation_items.amount` 131, `performance_files.modified_time_ms` 37, `wage_rates.hourly_rate` 12). SQLite affinity의 실제 저장값이므로 INTEGER 선언 열에 `Number.isInteger`를 강제하거나 이 값을 반올림하면 **원본 훼손**이다. 허용 가능한 유한 숫자로 보존한다. `app_setting_entries`의 기존 문자열·정수형 문자열·불리언 문자열·실제 달력일 검사는 유지한다. 각 오류는 표/행/열과 기대 타입을 포함하고 `check-failed` 경로로 돌아간다.
4. `checkDatabaseMigrationRequirements`, `previewDatabaseMigrationUpdate`, `runDatabaseMigrationUpdate`가 이미 호출하는 **동일 `parseAndValidateBackupJson`**에서 위 검증을 수행한다. 실행의 SHA/토큰·사전 백업·원자 교체·롤백 순서는 바꾸지 않는다. 입력 행 값을 문자열화하거나 보정하지 않는다. 관련 없는 제약(예: 표 사이의 외래키)은 미리보기의 격리 DB 검증 경로를 유지하되, 이번 변경을 모든 가능한 제약의 사전 인증으로 과장하지 않는다.
5. 시험은 실제 직원/수당 행을 복사하지 않은 합성 40표 fixture로 만든다. `sites.id=42`와 `{bad:"object"}` 각각 검사 거절을 단언한다. TEXT 열의 숫자/불리언, INTEGER 또는 REAL 열의 문자열/객체, 명시적 NOT NULL 열의 `null`, 첫 행 및 뒤 행의 오류를 표·열 정보와 함께 거절하고, 미리보기 실패 및 운영 DB 지문 불변을 단언한다. 유효 파일을 미리본 뒤 같은 파일을 불량 값으로 바꿔 실행하면 SHA/토큰 검사로 거절되고 운영 DB·기존 사전 백업이 불변임을 별도 단언한다. 이 결과를 “실행이 셀 타입 검사를 직접 실행했다”라고 보고하지 않는다. 빈 표는 여전히 허용하며, V3의 실제 INTEGER 선언 열 소수 데이터는 아래 운영 JSON 검증기로 값 손실 없이 통과해야 한다. 기존 C01·C03·C04·C05 시험과 단언을 삭제·skip·약화하지 않는다.
