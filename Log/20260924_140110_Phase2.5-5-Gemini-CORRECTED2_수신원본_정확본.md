## 3. 차단 결함과 정확한 보정 범위

### P255-C2 — 전체 deadline 뒤 늦게 획득한 브라우저가 남는다

- 실제 코드: src/main/services/installed-chrome-pdf-service.ts의 renderHtmlToPdfBytes와 renderHtmlBatchToPdfBytes. Promise.race에서 timeout이 먼저 끝나면 바깥 finally가 현재 null인 browser/context/page만 닫는다. 이후 launch나 newContext/newPage가 완료되어 획득한 자원은 닫히지 않고 renderPromise가 계속 진행할 수 있다.
- Sol 재현: 설치 Chrome finder를 유효한 파일로 주입하고 launcher가 80ms 후 브라우저를 반환하게 한 뒤 timeoutMs:10으로 단일 렌더를 호출했다. 결과는 시간 초과 오류였지만 180ms 뒤 late_browser_closed=false였다.
- 현재 T-C2a 시험은 launcher를 300ms 지연하고 오류 문구만 검사한다. 늦게 반환된 브라우저의 close 여부를 검사하지 않는다. page.pdf pending + close 3종도 이 시험에서 실행하지 않는다.
- 요구: 단일/배치 렌더 모두 deadline을 생성, 문맥, 페이지, PDF 단계에 적용한다. timeout이 먼저 확정된 뒤 각 await에서 늦게 도착한 브라우저/문맥/페이지를 즉시 닫고 이후 렌더 단계를 진행하지 않는다. 이미 보유한 자원은 기존 finally에서 닫는다. timer는 성공·실패 모두 해제하고 늦은 promise의 미처리 거절을 남기지 않는다. 호출자의 PDF 옵션 우회 창구는 다시 열지 않는다.
- 필수 시험: (1) late launcher/context/page가 각각 deadline 뒤 resolve해도 획득 자원 close와 추가 렌더 0을 확인한다. (2) page.pdf가 영원히 pending일 때 timeout 문구와 page/context/browser close 3종을 확인한다. 시험 이름과 실제 실행 단계가 일치해야 한다.

### P255-C3 — 필수 mid-commit 음성 시험이 선검사에서 끝난다

- 실제 코드: installed-chrome-pdf-service.test.ts의 “중간 실패” 시험은 호출 전에 existing.pdf를 만든 뒤 그 파일을 두 번째 target으로 넣는다. commitPdfBatchAtomically의 1단계 existsSync 선검사에서 종료된다.

- 요구: T-C3a를 실제 첫 link 성공 뒤 두 번째 link 실패로 바꾸고, link 시도 횟수 또는 첫 target 노출을 시험 중 관측하여 preflight 실패와 구별한다. rollback 뒤 새 target 0, 기존 파일 불변, temp 0을 검증한다. T-C3b는 기존 target 충돌과 overwrite 0을 별도로 검증한다. 핵심 저장 코드는 이 시험에서 새로운 결함이 확인될 때만 최소 수정한다.

## 5. 코드 전략과 불변조건

1. Chrome 서비스의 deadline 상태와 자원 소유권을 한 곳에서 관리한다. 각 비동기 획득 직후 deadline 확정 여부를 검사한다. 단일과 배치가 동일한 종료 의미를 갖도록 하고, timeout 뒤 새 작업 시작을 막는다. 성공·오류·timeout 경로의 close 순서와 timer 정리를 시험한다.
2. 저장 코드의 no-replace linkSync 및 역순 rollback은 현재 재현상 작동한다. 먼저 시험이 실제 link 1회 성공 후 실패를 관측하도록 바꾸고, 그때 발견된 실제 결함만 저장 코드에 수정한다.
3. font.family validator의 허용 집합을 HTML/CSS 직렬화 규칙과 맞춘다. 저장 단계에서 제어문자를 거절하며, 렌더 단계의 이중 방어를 제거하지 않는다.
4. 기본 품의서 HTML/CSS의 남은 presentation diff를 baseline과 일치시키고, 변경 가능한 layout delta만 조건부로 적용한다.
5. 수정 범위 밖의 승인·계산 결과, 근무일 기준 요율, SQLite 구조, 인력 식별자, Excel 인테이크, 기존 5종 XLSX 정의를 변경하지 않는다. 기존 시험을 삭제·완화·skip/only 처리하거나 lint/타입 경고를 억제하지 않는다.
