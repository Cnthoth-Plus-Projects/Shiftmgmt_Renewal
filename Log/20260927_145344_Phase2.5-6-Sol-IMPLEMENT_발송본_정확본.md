## 1. 목표·비목표

관리자가 배포된 기기에서 선택한 JSON 하나로 40표 데이터를 미리보고 안전하게 복원하며, 기존 DB의 JSON 사전 백업을 확인한 뒤에만 교체한다. 업무 데이터와 근무표·수당 정책은 선택 JSON, 저장 경로·기기별 운영 설정은 복원 대상 기기, 마지막 복원 파일 경로는 이번 선택 JSON에서 온다. 배포 설치만으로 개발 PC 데이터를 자동 포함하지 않는다.

이 계약은 **DB 데이터** 백업이다. 일반 39표의 app_users 계정·권한도 선택 JSON 값으로 교체된다. performance_files.file_path 등 DB 행이 참조하는 실제 Excel/PDF/외부 파일의 바이트는 JSON에 포함되지 않는다. 기기 간 이동에서 파일 자체의 별도 보존·배치가 필요할 수 있음을 경고하고, 이번 작업에서 그 파일을 몰래 복사하거나 경로를 추측해 고치지 않는다.

비목표: Phase 3의 O9/O10 화면 제작, 2.5-7 최종 통합 판정, 5-4 패치 적용 스크립트 제작, 설치 데이터 스크립트 변경, 근무표 회수·업무 Excel/PDF 제거, DB 스키마/수당 계산/권한 재설계, 의존성 추가·업그레이드, 기존 백업 파일 삭제. V3.4 원본은 읽기만 한다.

## 6. Sol 코드 전략 — 순서대로

1. **원본 데이터 경계**: 기존 listUserTableNames/buildJsonBackupSnapshot, JSON_IMPORT_TABLE_ORDER의 순서+live table 순회, DEC-001 참조 차단/메타데이터 보정, database-replacement-service.ts 원자 교체/롤백을 재사용한다. sqlite-storage-service.ts 스키마를 바꾸지 않는다. 40표 이름 집합은 런타임 스키마와 비교하고 non-empty 미지원 표/열을 경고만 남기고 버리지 않는다. 원본 JSON 바이트를 SHA 계산 뒤 같은 바이트에서 파싱해 TOCTOU를 막는다.
2. **백업**: database-backup-service.ts에서 ExcelJS/Access 분기·관련 helper/import만 제거한다. JSON은 고유 파일명과 임시 파일을 써 완성 후 공개하고 SHA를 실제 파일 바이트로 확인한다. 실패 시 미완성 임시물만 정리한다. 이미 존재하는 사용자 백업은 건드리지 않는다. 정기·품의 승인 호출부는 수정하지 않고 같은 runDatabaseBackupNow 결과 타입으로 이어지게 한다.
3. **JSON 검증/설정 매핑**: 검사/미리보기/실행이 하나의 검증 함수와 설정 매핑 함수를 공유한다. app_setting_entries의 known key는 §2 설계 문서의 분류 7경로 + 1선택 경로 + 5운영 키 + 6업무 키 + 재해석 표지다. business 6 source 값은 필수(시작일 빈 문자열 허용). 대상 기기의 저장된 운영 키는 유지하고 없으면 대상 기본값을 쓴다. marker는 source에서 복사하지 않고 대상 상태와 정책 날짜 차이로 결정한다. 같은 값의 로컬 설정을 source 경로로 바꾸지 않는다. 미리보기는 운영 DB나 target 디렉터리를 새로 만들지 않으며, 임시 DB만 만들고 제거한다. updated_at 변화와 행 수는 별도 변환으로 보고한다. app-settings-storage-service.ts는 보호 파일이므로 검증 또는 재해석 표지를 유지하는 데 그 수정이 꼭 필요하다면 BLOCKED.
4. **토큰·활동 이력**: 서비스 내부 in-memory Map에 randomUUID 등 불투명 토큰을 10분 보관하고 만료 토큰을 정리한다. 토큰은 정규화 경로, 원본 바이트 SHA, 40표 스키마/행 내용 지문, 발급 시각에 묶는다(행 수만 비교 금지). 정상 미리보기의 현재 HTTP 활동 이력은 서비스가 토큰을 발급하기 **전에** 현재 live DB에 정확히 1회 기록하도록 operations-routes.ts가 동기 콜백을 넘긴다. 서비스는 임시 DB를 닫고 live DB를 다시 연 뒤 이 콜백을 실행하고, 그 후 현재 40표 행 수/지문을 읽어 토큰과 응답을 완성한다. 직접 서비스 호출(검증 스크립트)은 콜백 없이 발급 가능하다. 기존 runIpcActionWithCleanup의 후행 preview activity는 중복 기록하지 않는다. 콜백 전후 업무 표가 변했으면 미리보기를 거부한다.
5. **실행 상태 전이**: 토큰·문구·SHA·현재 DB 지문 검증 → 토큰 1회 소비 → current DB 완성 JSON 사전 백업 확인 → await 중 DB·원본 파일 지문 재검증 → 동일하게 검증한 원본 바이트를 임시 DB로 가져오기 → 40표 결과·integrity/quick check·필수 불변 확인 → 기존 replaceDatabaseFileAtomically로 교체 → live 재열기. 어느 실패든 기존 DB 유지, watcher 재시작, 임시 DB/sidecar 정리; 이미 완성한 사전 백업은 보존·경로 보고. 원본 JSON은 절대 수정하지 않는다.
6. **Access 출구 제거**: database-migration-service.ts의 3,411줄 중 Access 전용 타입/함수/분기만 제거하고 JSON·DEC-001 코드는 보존·변경 최소화. 전용 진단 서비스/시험 파일만 삭제한다. domain/file-policy/bridge/route의 .accdb 허용을 닫는다. Access 전용 시험은 제품 능력 폐기로 삭제할 수 있으나 JSON·데이터 보존 시험은 약화하지 않고 J4~J6 음성/회귀로 대체한다.
7. **생성물·문서**: TypeScript build는 낡은 dist/server JS를 스스로 지우지 않는다. 신규 clean-server-build.mjs가 정확한 저장소 dist/server인지 확인한 뒤 생성물만 청소하게 하고 package.json build:server에 연결한다. 다른 경로/심볼릭 링크/빈 루트 삭제는 실패로 막는다. smoke 기대 79를 실제 clean build 기준으로 확인한다. codebase-map의 해당 항목만 갱신한다. package-lock·의존성 불변.

최소 diff 원칙: 전체 저장소 포맷/재생성 금지, 닫힌 allowlist 안에서도 필요한 hunk만 변경. 구현 전략/요구사항이 충돌하면 추정하지 말고 BLOCKED.
