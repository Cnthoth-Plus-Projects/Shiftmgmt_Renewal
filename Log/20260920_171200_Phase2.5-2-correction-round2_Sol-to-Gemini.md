## 4. 결함 대조

### D25-2-003 — parity가 아직 일부 필드만 골라 비교함

현재 `built-in-excel-layout-service.test.ts`는 recursive full parity가 아니다.

- `normalizeFont`는 색의 `argb`만 보고 `theme/indexed/tint`, `outline`, `vertAlign` 등을 버린다.
- `normalizeBorder`는 `top/left/bottom/right/diagonal`의 style과 `argb`만 보고 `indexed/theme/tint`, `start/end`, diagonal flags를 버린다.
- `normalizeFill`은 pattern의 `argb`만 보고 `theme/indexed/tint`와 gradient 속성을 버린다.
- alignment 일부 필드가 빠져 있다.
- worksheet properties/pageSetup/margins는 `toMatchObject`라서 full deep equality가 아니다.
- `numFmt`은 표본 값이 truthy일 때만 비교해 generated 쪽의 예기치 않은 값을 잡지 못한다.

실제 committed JSON에는 비교가 빠지는 값이 이미 존재한다.

```text
font.color.theme: attachment1 775, attachment2 601, proposal 92,
                  template1 3835, template2 3607
border.color.indexed: attachment2 49, proposal 406,
                      template1 1100, template2 1112
```

따라서 현재 시험은 theme/indexed 변조를 통과시킬 수 있다. 직전 회신의 “전수 deep equality” 주장은 실제 helper와 일치하지 않는다.

### D25-2-004 — runtime validator가 손상 value/style/worksheet를 허용함

`validateBuiltInExcelLayoutDefinition`은 현재 root/key, 단순 regex, 배열 존재, index/address 중복만 확인한다. 아래 손상 정의가 오류 없이 통과했다.

```js
{
  schemaVersion: 1,
  layoutKey: "proposal-xlsx",
  canvasRange: "A2:A1",
  worksheet: { name: "품의서", properties: "BROKEN" },
  columns: [{ index: 1, width: -5, hidden: "yes" }],
  rows: [{ number: 1, height: -10, outlineLevel: "bad" }],
  merges: ["B2:A1"],
  cells: [{
    address: "A1",
    value: { formula: 123 },
    font: "BROKEN",
    alignment: 42,
    fill: { type: "BROKEN" }
  }]
}
```

실제 결과: `CORRUPT_SCHEMA_ACCEPTED`.

직전 회신의 음성시험에는 `cells[0].style.font` 손상 거절을 적었지만, 실제 시험 7은 `schemaVersion`과 `canvasRange` 두 개만 검사하고 위 손상을 검사하지 않는다.

### D25-2-005 — generator 사전 schema 검증도 같은 수준으로 얕음

`scripts/generate-built-in-excel-layouts.mjs:260-334`의 `validateLayoutSchema`도 D25-2-004와 같은 필드를 검사하지 않는다. `--write`의 메모리 생성·staging·rollback과 `--check` write 0은 Sol이 별도로 재현해 통과시켰다. 이번에는 그 구조를 유지하고, **쓰기 전 schema 검증만 runtime과 같은 계약으로 완성**한다.

### D25-2-008 — 별첨2 canonical 전환 중 기존 styleSpec 적용을 삭제함

직전 CORRECT 지시는 “profile 좌표를 값 배치에 사용하지 않고 canonical `별첨2/B1/G2/row5`를 쓰되 `styleSpec`은 유지”였다. 현재 writer는 canonical 값은 쓰지만 `applyDocumentTemplateStyleSpec` 호출을 삭제했다.

## 7. Sol의 코드 전략 — 순서대로 구현

### 7.1 runtime schema validator 완성

`built-in-excel-layout-service.ts` 안의 기존 validator를 유지·확장한다. 새 파일이나 dependency는 만들지 않는다.

1. `isPlainObject`, finite number/integer, cell address, range, color/style/value 검증 helper를 둔다.
2. 셀 주소는 Excel 범위 `A1:XFD1048576` 안이어야 하고, range는 시작 <= 끝이어야 한다.
3. `canvasRange`를 먼저 숫자 bounds로 파싱한다. columns/rows/merges/cells/logo가 canvas 밖이면 해당 field path로 거절한다.
4. 다음을 모두 검증한다.
   - root/schemaVersion/layoutKey.
   - `worksheet.name`, `properties`, `views[]`, `pageSetup`, nested `margins`, `headerFooter`의 object/array와 각 소비 필드 타입.
   - column `index/width/hidden/outlineLevel`: finite, integer/양수/boolean/range, index 중복.
   - row `number/height/hidden/outlineLevel`: finite, integer/양수/boolean/range, number 중복.
   - `logoRange`: finite integer, 양수, start <= end, canvas 안.
   - merge: 주소/range/방향/canvas/중복/겹침.
   - cell: address/canvas/중복, primitive 또는 지원 tagged value(`date`, `formula/result`, `richText`, `text+hyperlink`, `error`), `numFmt`.
   - font/alignment/border/fill/protection의 plain object, 알려진 field, enum/boolean/string/finite number, 모든 color mode `argb/theme/indexed/tint`.
5. unknown/오타 style field를 silent ignore하지 않는다. builder가 실제 소비하는 ExcelJS JSON 계약에 없는 키면 정확한 path로 거절한다.
6. 모든 오류 형식은 아래와 같이 layout key와 실제 path를 포함한다.

```text
[내장 Excel 레이아웃 오류 (proposal-xlsx)] 필드 'cells[0].font'의 형식이 올바르지 않습니다: ...
```

7. validator 성공 전 workbook/worksheet를 만들지 않는다.

### 7.2 generator validator 동등화

`generate-built-in-excel-layouts.mjs`의 기존 `validateLayoutSchema`에 §7.1과 같은 필드·범위·중복·주소 규칙을 구현한다. TS runtime 모듈을 import하거나 build 설정을 바꾸지 않는다. 이 dev-only script와 runtime validator의 명시적 중복은 이번 닫힌 범위에서 허용한다.

- `generateAllLayoutsInMemory()`가 5개 모두 생성·schema·scrub 검증을 끝낸 후에만 `runWriteMode`가 mkdir/staging에 들어간다.
- 현재 `runWriteMode`의 backup/stage/rename/rollback 및 `runCheckMode`의 write 0 구조는 바꾸지 않는다.
- committed JSON 5개 bytes는 바꾸지 않는다.

### 7.3 full parity helper 교체

선택식 `normalizeFont/Alignment/Border/Fill`을 없애고, false·0·빈 문자열을 보존하는 recursive normalizer로 실제 전체 객체를 비교한다.

1. primitive는 그대로, `Date`는 ISO, 배열 순서는 보존, object key는 정렬한다. `undefined`만 직렬화에서 제외한다.
2. cell tagged value/formula/result/richText/hyperlink/error를 전체 비교한다.
3. merged slave는 master 주소 관계를 비교하고 master의 value/style을 한 번 비교한다.
4. master cell의 `font/alignment/border/fill/numFmt/protection` 전체 enumerable field를 deep equality한다. theme/indexed/tint와 false를 버리지 않는다.
5. columns/rows의 width/hidden/outline, worksheet properties/views/pageSetup/margins/headerFooter/printArea는 `toMatchObject`가 아닌 normalized deep equality로 비교한다.
6. merge 집합, 주 시트 수·이름, logo count/tl/br/oneCell은 기존 exact 검증을 유지한다.
7. 제외는 zip entry 순서, zip timestamp, ExcelJS 내부 style/media relationship ID뿐이다. 이 값들은 비교 payload에서 명시적으로 제외하고 helper 주석과 회신에 정확히 열거한다. formula나 cell style field를 제외하지 않는다.
8. 기존 8개 `it` 안에서 대표 sample의 `font.color.theme` 또는 `border.color.indexed`를 한 번 변조해 parity helper가 실제로 throw하는 음성 assertion을 추가한다. 새 `it`는 만들지 않는다.

### 7.4 definition 격리

`getBuiltInExcelLayoutDefinition`이 static imported object를 외부에 직접 반환하지 않게 한다.

- static definition을 완전히 validate한 뒤 JSON-safe deep clone을 반환한다.
- 호출자가 반환 definition의 worksheet/cell/style/column을 수정해도 다음 definition과 다음 workbook은 원본이어야 한다.
- 기존 workbook 구성 중 style deep copy도 유지한다.
- test 8 안에서 `getBuiltInExcelLayoutDefinition` 반환값을 수정한 뒤 두 번째 definition과 workbook이 원래 값임을 assert한다.

### 7.5 attachment2 styleSpec 복원

`writeAttachmentTwoWorkbook`의 값과 prototype 좌표는 현재 canonical 상수 `별첨2/B1/G2/row5`, subtotal row 13, total row 86을 그대로 유지한다. `resolveAttachmentTwoTemplateFields`를 다시 사용하지 않는다.

- 동적 행/합계 작성과 빈 영역 정리 뒤, baseline과 동일하게 `applyDocumentTemplateStyleSpec({ workbook, template: input.template })`를 호출하고 파일을 쓴다.
- test 14의 attachment2 template에는 실제 `semanticZones`를 넣는다.
  - canonical style zone: `fieldKey: "dateRangeCell"`, `sheetName: "별첨2"`, `bindingType: "cell"`, `bindings: ["G2"]`.
  - fill `#F2F7FF`, horizontal alignment `center`를 검증한다.
  - merge 검증은 canonical 동적 값과 충돌하지 않는 별도 zone/range, 예를 들어 `D2:F2`, 를 사용한다.
- 같은 profile의 `fieldMappings`는 일부러 noncanonical(`titleCell: Z99`, `dateRangeCell: F99`, `dataStartRow: 9`)로 두고, 값은 여전히 B1/G2/row5에만 쓰이며 Z99/F99에 쓰이지 않음을 assert한다.
- 기존 3개 근무지 상세/소계/총합 assertion은 유지한다.
