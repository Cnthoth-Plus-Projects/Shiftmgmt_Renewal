## 6. Sol의 코드 전략 — 이 순서대로 구현

### 6.1 C1 — 정본과 옛 시험 동기화

1. `document-layout-preview-service.test.ts`의 기존 E4 `it` 하나만 수정한다.
2. 조정된 parser table position이 `assertValidDocumentLayoutDefinition(modifiedDef, "save")`에서 **throw하지 않음**을 명시적으로 검증한다.
3. 이어지는 preview 생성 성공과 기존 스타일 assertion은 보존한다.
4. 시험 이름·주석을 Phase 2.5-4 R6 계약에 맞춘다.
5. 새 `it`를 추가하지 않는다. 이 파일은 계속 6시험이다.

### 6.2 C2 — timestamp가 아니라 revision 의미로 history 정렬

1. `listDocumentLayoutHistory`의 `source_path = ''` 내부 revision 행 정렬만 바꾼다.
2. 내부 `version_label`은 `vN` 규약이므로 숫자 N을 내림차순 정렬의 1차 키로 사용한다. 예: SQLite에서 `CAST(SUBSTR(version_label, 2) AS INTEGER) DESC`.
3. `created_at DESC, id DESC`는 같은 의미 revision에 대한 결정적 보조 키로만 둔다.
4. 저장·reset·active 선택·public return shape·DB schema는 바꾸지 않는다.
5. 기존 history 시험에서 save/reset 뒤 해당 세 내부 행의 `created_at`을 동일한 고정 ISO 값으로 UPDATE한 다음 `v3,v2,v1`과 active v3을 검증한다. 새 `it`는 추가하지 않는다.

### 6.3 C3 — 예약 정의 이름 case-insensitive 단일성

1. `attachScheduleLayoutMetadataToWorkbook`에서 예약 이름과 대소문자만 다른 기존 정의 이름도 모두 제거한 뒤 canonical 이름 하나만 추가한다.
2. `readScheduleLayoutRevisionMetadataFromWorkbook`에서 예약 이름 비교를 case-insensitive로 수행한다.
3. case-insensitive match가 정확히 1개가 아니면 기존 metadata structure error 계열로 fail-closed한다. 0개인데 meta sheet만 있거나, 2개 이상인 경우 모두 거절한다.
4. range `'_ShiftMgmtMeta'!$A$1`, veryHidden, JSON strict 검증은 그대로 보존한다.
5. 기존 T3 metadata matrix 안에 canonical 이름과 case-variant alias가 서로 다른/충돌 range를 가리키는 case를 넣고 거절을 검증한다. 새 `it`는 추가하지 않는다.
6. raw XLSX XML 파서나 새 의존성을 도입하지 않는다.

- 통과를 위해 assertion을 삭제·skip하거나 오류를 fallback으로 숨기지 않는다.
- C1은 이미 확정된 R6에 시험을 맞추는 것이며, R6 구현을 되돌리면 안 된다.
