### 6.1 상대 경로 계약

1. `artifact.fileName`은 “단일 파일명”이 아니라 outputDir 기준 `/` 정규화 상대 경로다. manifest 필드명을 `relativeFileName` 또는 의미가 동등한 이름으로 명확히 해도 된다.
2. 검증 함수는 원문을 canonical `/` 상대 경로로 검사한다.
   - 빈 문자열, NUL/제어문자, `\`, `path.posix.isAbsolute`, `path.win32.isAbsolute`, `^[A-Za-z]:`, `:`, `//`/UNC를 거절한다.
   - `/`로 나눈 각 segment가 비어 있거나 `.`/`..`이면 거절한다.
   - Windows 금지문자 `< > : " | ? *`, 끝의 점/공백, device 이름 `CON/PRN/AUX/NUL/COM1..9/LPT1..9`(확장자 유무 무관)를 거절한다.
   - 정상 한글·숫자·공백·`-`·`_`와 중첩 `/`는 허용한다.
3. segment 배열을 native path로 결합하고 `path.relative(root, candidate)` 기반 separator-aware containment를 적용한다. 문자열 root prefix 비교를 되살리지 않는다.
4. `artifact.filePath`의 resolved path가 위 relative path에서 계산한 candidate와 정확히 같아야 한다. manifest에는 absolute `filePath`를 저장하지 않는다.

### 6.2 생성·조회 경계

1. tempRoot → outputDir → 상대 경로의 모든 중간 component를 `lstat`한다.
2. outputDir 및 중간 component는 실제 directory이고 symlink/junction가 아니어야 한다. 마지막 component는 실제 regular file이고 symlink가 아니어야 한다.
3. tempRoot/outputDir/final file realpath를 다시 계산해 각각 separator-aware containment를 확인한다.
4. 생성 결과 전체를 검증한 뒤에만 manifest를 등록한다. 일부 성공 manifest를 남기지 않는다.
5. resolve 때 manifest 상대 경로와 모든 component/realpath를 다시 검증한 뒤 bytes를 읽는다. 생성 뒤 교체 공격은 null이다.

### 6.3 안전한 cleanup

1. outputDir 자체가 link/junction이거나 tempRoot 밖이면 recursive target을 따라가지 않고 manifest만 제거한다.
2. 안전한 outputDir 내부도 무검사 `rmSync(dir,{recursive:true})` 한 번에 의존하지 않는다. directory tree를 `lstat` 기반으로 순회한다.
3. symlink/junction entry는 target으로 재귀하지 않고 link 자체만 제거하거나 안전하게 남긴다. 실제 directory는 realpath가 outputDir/tempRoot 안일 때만 재귀한다. 외부 target/sentinel은 절대 삭제하지 않는다.
4. cleanup 오류는 원래 create 오류를 덮지 않으며 resolve에서 bytes 노출로 fallback하지 않는다.

### 6.4 기존 6개 시험 안의 강화

1. 기존 정상 `it` 중 하나를 실제 기본 5종 통합 시험으로 강화한다. `generator` dependency를 mock하지 않는다.
2. 다음 5 key를 모두 `getDefaultDocumentLayoutDefinition`에서 얻어 실제 service로 create/resolve한다.
   - `schedule-xlsx/template1`
   - `schedule-xlsx/template2`
   - `proposal-xlsx`
   - `attachment1-xlsx`
   - `attachment2-xlsx`
3. 각 결과에서 relative filename이 `/`를 포함하고 예상 output pattern의 중첩 구조이며, resolve bytes가 non-empty XLSX ZIP signature(`PK`)이고 media type이 유지됨을 확인한다.
4. 여섯 번째 적대 시험의 현재 sibling 및 outputDir root junction 시나리오를 유지한다.
5. 같은 여섯 번째 `it` 안에 nested directory junction/symlink가 외부 sentinel을 가리키는 generator 결과를 추가한다. create reject, manifest 0, cleanup 후 sentinel 원문 보존을 확인한다.
6. drive-relative `C:evil.xlsx`, ADS `file.xlsx:stream`, `a/../b.xlsx`, 역슬래시, absolute/UNC 입력도 reject한다. 플랫폼별 공격 setup 실패를 skip/pass로 바꾸지 않는다.
7. `it(` 선언은 정확히 6개, 전체 집중 시험은 68개를 유지한다.
