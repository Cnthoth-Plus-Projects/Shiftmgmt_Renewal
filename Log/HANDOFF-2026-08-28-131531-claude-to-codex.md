## 배경 (이 파일만 읽고 판단할 수 있게 정리)

**제품**: 교대근무 사업장의 근무표를 만들어 배포하고, 실제 근무 실적을 엑셀로 회수해 승인하고, 연장·야간·휴일·대체 수당을 계산해 품의서·별첨 서류를 출력하는 **윈도우 설치형 데스크톱 앱**(Electron + React + TypeScript + Vite, 내장 SQLite, exceljs, echarts).

**실사용자**: 비기술 한국어 운영자(현장 운영자·사장). 개발 지식 없음. 사무실 PC, 1440×900 이상. 매일 사용하되 **월말에 사용 집중**(실적 승인·수당 정산).

**현재 버전**: v0.5.4. 화면 8개 / 화면이 부르는 내부 기능(API) 111개 / DB 표 36개 / 업무 로직 모듈 30개 / 처리 서비스 74개 / 자동 시험 990개 / 단일 CSS 약 19,000줄.

**리뉴얼 방침 (확정, 변경 불가)**
- **화면은 새로, 계산은 그대로.**
- 이관(복사만, 수정 금지): `src/shared/domain/`(30), `src/main/services/`(74), `src/main/ipc/`, `src/preload/`, `src/shared/bridge/`, 테스트 990개, `양식샘플/`
- 새로 작성: `src/renderer/` 화면 전체, 디자인 시스템
- 유지: SQLite 표 36개 구조, API 111개 계약
- 이관 검증 기준: 테스트 990개 전부 통과 + 표별 행 수 일치 + 승인 수당 총액 1원도 차이 없음

**이번 요청의 범위**: 코드가 아니라 **화면설계(정보구조·사용흐름·접근성·공통부품·시각 밀도)의 방향**을 정하는 단계다. 아직 코드는 한 줄도 쓰지 않았다.

**역할 정의 (사용자 지정)**
- Claude = 오케스트레이터(설계·지시서·검증·진행)

- **Codex = 교차검증자.** 오케스트레이터의 설계·검증·리뷰 등 중요 과정을 교차검증하고 동의/반대한다. Codex가 반대하면 다음 단계로 넘어가지 않는다.

### 초안 요약

**(1) 재검수로 찾은 현재 UX 문제 9가지** — 전부 기존 문서에 기록된 실제 사고/실측이 근거
| # | 문제 |
|---|---|
| P1 | 메뉴가 명사 8개 나열이라 "이번 달에 뭘 해야 하는지" 화면이 알려주지 않음. 월말 집중 사용인데도 |
| P2 | 엑셀이 안 읽혔을 때 볼 곳이 두 화면에 흩어져 있음. "파일이 안 뜬다"가 신고 1위 |
| P3 | 금액 0원·근무시간 0분일 때 화면이 이유를 말하지 않음. 과거 사고 5건의 공통 원인이 "조용한 폴백" |
| P4 | 되돌릴 수 없는 동작 5개(실적 승인 / 품의 승인 / 근무표 게시 / 삭제 / DB 교체)의 확인 방식이 제각각 |
| P5 | 권한 없을 때 버튼을 숨겨서 사용자가 헤맴 |
| P6 | 근무지 마법사에서 화면 상태 사고 반복(진입만으로 데이터 변경, 되돌리기 오작동, 없어진 근무형 잔존, 패널 겹침으로 버튼이 안 눌림) |
| P7 | 표가 무거움(한 달 수백~수천 행, 화면 파일 123KB) |
| P8 | 색만으로 상태·근무유형을 구분하는 곳이 있음 |
| P9 | 승인된 엑셀을 사람이 손으로 옮기면 고아 승인행이 생겨 승인이 영구히 막힘. 현재는 감지만 하고 화면에 상태를 안 보여줌 |

**(2) 설계 원칙 6개**
1. **빈 값·0에는 반드시 이유를 붙인다** (예: `수당 0원 · 지급 대상 아님 — 대체 투입자가 주간고정조`)
2. **되돌릴 수 없는 동작은 확인창 3종으로 통일** (단순 / 위험(건수·금액 표시) / 사유 입력). Esc·포커스 가둠·중복 클릭 차단
3. **권한 없으면 숨기지 말고 비활성 + 이유 표시**
4. **상태는 색 + 글자 + 아이콘 병기** (흑백으로 만들어도 읽혀야 함)
5. **전역 상태줄 신설** — 어느 화면에서든 하단에 `DB 연결 / 폴더 감시 / 승인대기 N건 / 업데이트` 상시 표시, 눌러서 원인·재시작으로 이동
6. **화면 상태를 데이터 신원(근무지·패턴 ID)에 묶는다.** 같은 근무지를 다시 열어도 재판정. 선택값은 현재 유효 목록과 대조해 자동 교체. 되돌리기 기록에 전/후 전체 상태 저장

**(3) 화면 구조 3안 — 사용자 결정 대기**
- A안: 업무 순서형. "홈(이번 달 진행)" 화면을 새로 만들고 메뉴를 준비/운영/정산/관리로 그룹화
- B안: 현행 메뉴 8개 유지, 표·상태·확인·빈 상태·접근성·성능만 재설계
- **C안(Claude 권장)**: 메뉴 8개 그대로 두고 **대시보드 위쪽에 "이번 달 할 일" 구역만 추가**
- 권장 근거: 실사용자가 비기술 운영자라 메뉴 변경 시 문의가 늘고, 이번 리뉴얼 최대 위험은 "화면이 낯설어짐". C안은 그 위험을 낮추면서 P1을 해결

**(4) 표 밀도 3안 — 사용자 결정 대기**
1440×900 기준 계산(측정값 아님): `900 − 제목줄56 − 필터바56 − 표머리40 − 아래여백48 = 본문 700px`
- V1 행 32px → 약 21행 (운영 밀집형)
- **V2 행 36px → 약 19행 (균형형, Claude 권장)**
- V3 행 40px → 약 17행 (여유형)
- 확정된 시각 제약: 흰색 셸 + 파랑 `#3e56b6`, **남색 배경 금지**(기존 가독성 결정), Material Symbols 한 세트, 문구 전부 한국어

**(5) 공통 부품 14종** — 데이터 표(가상 스크롤·그룹 접기·가로 스크롤) / 상태 배지 10종 / 확인 모달 3종 / 빈 상태 블록 / 사유 칩 / 권한 잠금 / 진행 표시 / 날짜 입력(선택 즉시 반영) / 숫자 스테퍼 / 패턴 페인팅 스트립 / 시뮬레이션 달력 / 조 카드 / 파일 경로 표시 / 전역 상태줄

**(6) 접근성 규칙** — 전 요소 Tab 접근·Enter/Space 실행, 표 ↑↓/Space/Enter, 모달 Esc+포커스 가둠+포커스 복귀, 흑백 변환해도 상태 구분, 본문 대비 4.5:1·배지 3:1, 표 본문 최소 13px, 오류는 아이콘+한국어 문장+조치 방법

**(7) 사용자 결정 항목 6개** — Q1 화면구조 / Q2 밀도 / Q3 안내 텍스트(151KB) 유지 범위 / Q4 밀도 토글 유지 / Q5 시안 제작 주체 / Q6 시안 범위(일괄 vs 순차)

**(8) 초안이 정직하게 인정한 미확인 사항**
- 운영자 실사용 관찰을 한 적 없음 (P1은 문서 근거이지 관찰 결과 아님)
- 밀도 토글을 실제로 쓰는지 모름
- 표 성능을 실데이터로 측정하지 않음 (§4 행 수는 계산값)
- 안내 텍스트 151KB 중 실제로 읽히는 비율 모름

## 제약 (이 프로젝트의 절대 규칙 — 설계 검토 시 위반 여부도 봐 주세요)

1. **이관 코드 수정 금지** — `src/shared/domain/`, `src/main/services/`, `src/main/ipc/`, `src/preload/`, `src/shared/bridge/`, 테스트 990개는 복사만 한다
2. **DB 스키마 변경 금지** — 표·컬럼 이름 변경, 컬럼 삭제, 외래키 신규 부여, `allowance_calculations.signature` UNIQUE 제거 전부 금지
3. **가짜 UI 금지** — 데이터·동작이 없는 장식 요소는 시안에 있어도 만들지 않는다 (과거 제거 사례: 전화/메시지 버튼, 증명사진, 가짜 건수, 통합 검색바, 동작 없는 눈·삭제 아이콘, 도달 불가 경고 배지)
4. **실적 직접 입력 화면 금지** — 엑셀 인테이크가 유일한 경로
5. **forward-only** — 승인된 계산 결과를 이력 없이 덮어쓰지 않는다. 규칙 변경은 "적용 시작일" 이후 근무일에만
6. **승인과 계산은 하나의 트랜잭션** — 승인만 되고 계산이 없는 상태는 존재할 수 없다
7. **배포 엑셀 줄 순서 = 조 → 배정 순서 → 사번.** 이름순 재정렬 금지(맨 위가 조장)
8. **조 표시 이름과 내부 식별자를 섞지 않는다** — 화면엔 표시 이름, 조회 키·저장엔 내부 식별자
9. **게시(release:publish) 금지** — 사용자 명시 승인 없이는 절대
10. **남색 배경 금지**, 아이콘은 Material Symbols 한 세트, 문구는 전부 한국어
