## [추가 판정]

### 1. 능력 매트릭스 검증 범위가 충분한가

**충분하지 않습니다.** 파일럿이 역할별 껍데기와 버튼 상태를 검증하므로 위 쓰기 권한 표는 파일럿 전에 `12`에 반영해야 합니다. 2차에서만 등장하는 세부 기능의 입력/출력 형태는 2차 전 확인해도 되지만, `planner/reviewer/admin` 경계는 지금 확정해야 합니다.

### 2. `[취소]` 전면 삭제가 과한가 / 대안

**문구 그대로라면 과합니다.** 금지 대상은 “실행이 시작된 작업을 실제로 중단한다는 뜻의 `[취소]`·`[중단]`”입니다. 실행 전 확인창, 저장하지 않은 변경 모달, 파일 선택창의 취소까지 없애면 안 됩니다.

- 저장 전 이탈 모달: `[취소]`보다 `[계속 편집]` / `[변경 버리고 나가기]`가 명확합니다.
- 실행 전 확인 모달: `[돌아가기]` / `[실행]`.
- 실행 후 상태 변경 작업: `중단할 수 없는 작업입니다. 완료될 때까지 이 화면을 유지해 주세요.`를 보이고 재실행·이탈을 잠급니다.
- 조회 전용 작업은 필요하면 `[결과 기다리지 않고 닫기]`를 둘 수 있으나, **“내부 처리는 계속되고 결과는 표시되지 않음”**을 명시하고 중복 실행을 막을 수 있을 때만 허용해야 합니다.
- `백그라운드에서 계속`은 재진입 상태 조회가 가능한 인테이크·시작 복구에만 정당합니다. 상태 조회가 없는 문서 생성·DB 교체에는 쓰면 안 됩니다.

따라서 “모든 `[취소]` 0개” 체크리스트를 “**실행 중 작업 중단을 약속하는 `[취소]`·`[중단]` 0개**”로 고치십시오.

### 3. 전역 상태줄 인테이크 상태 교체의 타당성

**방향은 타당하지만 watcher 건강 상태의 대체물은 아닙니다.** `get-sync-state.status = idle`은 앱 시작 직후 기본값일 수도 있어 감시기가 실행 중이라는 뜻이 아닙니다. 일반 역할에는 `최근 인테이크: 처리 이력 없음 / 읽는 중 / 해석 중 / 마지막 처리 완료 / 오류`처럼 중립적으로 표시하고 `updatedAt` 또는 완료 시각을 함께 보여주십시오. 초록 점과 `정상 감시 중` 같은 표현은 금지합니다. admin에게만 별도 `폴더 감시 실행/중단`을 보여주는 것은 맞습니다.

### 4. 홈 계산 규칙에 남은 가짜 UI 위험

가장 큰 위험은 **현재 상태, 월간 이력, 서로 다른 식별자를 한 진행률로 결합해 실제보다 완료로 보이는 것**입니다. 위 BLOCKER 2의 대상 집합·배정 기준일·siteId/siteName 결합을 확정하기 전에는 홈 진행률을 “확정된 계산”이라고 부르면 안 됩니다. 혼합 단위는 퍼센트만 숨기지 말고 `근무지/단계/월 정산 단계`를 텍스트로 노출하면 이해할 수 있습니다.

### 5. 파일럿 최소 JavaScript 요구의 타당성

**타당합니다.** 데이터 연동 없이도 Tab 순서, 표 roving focus, Space/Enter, 모달 focus trap/복귀, `aria-disabled` 설명은 동작해야 합니다. 단 위에서 지적한 정당한 권한 제한 상태와 실행 전/후 모달 구분을 먼저 보완해야 합니다.

### 6. 여전히 남은 가장 큰 위험

**홈이 “이번 달 업무가 끝났다”고 거짓 확신을 주는 위험**입니다. 특히 현재 비활성 근무지의 월중 실적 누락, 근무지 이름 변경, 파일 수와 행 수 혼용이 결합되면 100% 표시인데 처리할 업무가 남을 수 있습니다. 장기 작업은 그다음 위험입니다. 상태 조회가 없는 상태 변경 작업 중 앱 종료까지 발생하면 결과를 복구해 설명할 수 없으므로, “화면 이탈 잠금”이 라우트 이동·로그아웃·창 닫기 중 어디까지 가능한지도 별도 확인해야 합니다.

### 7. 절대 규칙 위반 여부

**문서 기준 위반 있음.** 현재 확인된 것은 다음입니다.

- 실행 중 인테이크 `[취소]`: 실제 중단 창구가 없는 버튼 약속 → 가짜 UI 위반.
- operator/reviewer에게 감시 중단·폴더 감시 상태 제시 → 권한 없는 데이터 약속.
- 근무지 마법사에 실제 맥락 없는 승인 버튼 요구 → 권한 예시를 위한 가짜 UI 위험.
- 아직 계산 불가능한 월말 활성 범위를 확정 진행률로 선언 → 가짜 수치 위험.

이관 코드, DB 스키마, 게시, 실적 직접 입력을 건드린 흔적은 없습니다.

## 반드시 고쳐야 할 것 (BLOCKER)

1. `11:500`의 작업 `[취소]` 삭제 및 전면 금지 문구를 **실행 중 작업 중단 버튼**으로 한정.
2. `12` 권한표에 `access-logs:list` admin 전용과 쓰기 역할 전체를 반영.
3. 홈 대상 집합을 계산 가능한 값으로 재정의: 현재 활성/월중 활동, 배정 유효 기준일, `siteId`/`siteName` 결합 규칙, 파일/행 단위 구분.
4. 홈 3지표에 `근무지`, `단계`, `월 정산 단계` 단위를 항상 표시.
5. `대기` 배지 색 교체, 기능성 경계·포커스 링의 실제 조합별 대비표 추가.
6. 파일럿의 `aria-disabled` 검증을 실제 권한 제한 동작이 있는 화면 상태로 이동.
7. BLOCKER 5의 문서 간 충돌 전부 수정하고 `rg`로 `[취소]`, `감시 중단`, `62`, `v1.0`, `111개`, `확인해야` 잔존을 재검사.
8. dirty 이탈 경로를 메뉴 이동뿐 아니라 근무지 전환·로그아웃·창 닫기까지 명시하고, 보호 코드 변경 없이 실제로 막을 수 있는 범위를 능력 매트릭스에 적기.

## 고치면 좋은 것 (NICE-TO-HAVE)

- 가상 표 요구에 `aria-rowcount`, 각 렌더 행의 `aria-rowindex`, 현재 선택 행의 낭독 규칙을 구체화.
- 상태줄 polling으로 `aria-live`가 반복 발화하지 않도록 이전 의미 상태와 달라졌을 때만 알림.
- 경고 4.545:1처럼 여유가 작은 색은 목업 캡처·글꼴 렌더링 후 재측정.
- 홈 계산이 여러 IPC 호출과 직원별 N+1 호출을 요구하므로 파일럿 이후 실제 데이터로 로딩 시간과 부분 실패 상태를 측정.
