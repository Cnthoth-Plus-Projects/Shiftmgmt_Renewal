## 6. Sol의 코드 전략 — 이 순서대로 구현

### 6.1 기존 구조 재사용

- 진입점은 `exportMonthlySchedulePlan`과 `exportAllowanceDocuments` 그대로 둔다.
- 근무표 데이터 업데이트 생성, 휴일 색 결정, `applyDocumentTemplateStyleSpec`, output path/history 저장을 재사용한다.
- 수당의 `resolveExportRows`, 정렬, 금액 집계, 품의서 compact writer, 별첨1 compact writer, 별첨2 동적 writer, output target/history 저장을 재사용한다.
- 등록 양식 관리/preview를 위한 `inspectSchedulePlanTemplate(filePath)`와 별도 template-management 서비스는 Phase 2.5-3까지 건드리지 않는다.
- 데이터 정본은 현재 SQLite 승인 결과와 저장 설정이다. JSON layout에는 사용자/월/금액 데이터를 넣지 않는다.
- PDF `outputFormat === "pdf"` 분기는 글자 단위 최소 변경 원칙으로 보존한다.

### 6.2 JSON 자산 계약

5개 JSON은 동일한 내부 schema를 사용한다. schema는 이번 단계 전용으로 `built-in-excel-layout-service.ts` 안에 타입과 런타임 검증을 둔다. `src/shared` 계약을 미리 구현하지 않는다.

필수 필드:

- `schemaVersion: 1`, `layoutKey`, `worksheet.name`, `canvasRange`.
- worksheet properties/views/pageSetup/pageMargins/headerFooter/printArea 중 표본에 존재하는 값.
- 열: index/width/hidden/outlineLevel 중 존재 값.
- 행: number/height/hidden/outlineLevel 중 존재 값.
- 정렬된 `merges[]`.
- 셀: address, scrub 뒤 남은 정적 tagged value, `numFmt`, font, alignment, border, fill, protection 중 존재 값. 빈 셀도 병합/서식/사용 범위에 영향을 주면 포함.
- tagged value는 string/number/boolean/null과 Date/formula/richText/error를 구별해 왕복한다. `Date`를 일반 문자열로 잃거나 formula result만 남기지 않는다.
- `logoRange`는 수당 3종에만 선언한다. 이미지 bytes는 JSON에 넣지 않는다.

직렬화는 키/주소/병합/행/열 순서를 고정하고 2-space UTF-8 JSON + 마지막 LF로 결정적으로 만든다. ExcelJS 내부 `styleId`, zip metadata, workbook 생성 시각, calcId 같은 비계약 값은 JSON에 넣지 않는다.

### 6.3 개발 전용 생성 도구

1. `scripts/generate-built-in-excel-layouts.mjs --write`는 먼저 표본 5개 SHA-256을 §3.1과 대조한다.
2. SHA가 모두 맞을 때만 V4 `양식샘플`에서 정확한 주 시트를 읽는다. 별첨1은 `별첨1`만 추출한다.
3. JSON 직렬화 전에 잠긴 명세의 바인딩 범위를 명시적 scrub map으로 비운다. 근무표의 사이트/월/명단/날짜·배정·변경 값, 품의서의 메타/제목/대상/상세·합계·날짜 값, 별첨1의 제목/상세·소계·합계 값, 별첨2의 제목/기간/상세·소계·합계 값이 대상이다. 머리글·안내문·정적 라벨과 모든 스타일/병합은 남긴다.
4. scrub은 값만 지우고 스타일/병합/행·열 크기는 보존한다. 표본에서 가져온 실제 사번·이름·근무지·근무일·시급·수당 금액은 JSON에 0건이어야 한다. 이를 허술한 문자열 blacklist가 아니라 좌표/바인딩 범위 allowlist로 보증한다.
5. 5개 JSON을 메모리에서 모두 만든 뒤 schema와 scrub 결과를 검증하고, 그 다음 허용된 5개 대상만 쓴다. 중간 실패 때 일부만 갱신하지 않는다.
6. `--check`는 같은 변환 결과와 committed bytes를 비교하고 동적 값 잔존 0건을 검사하되 파일을 쓰지 않는다.
7. 이 script를 package scripts/build/start에서 호출하거나 runtime service에서 import하지 않는다.

### 6.4 공용 built-in workbook 빌더

1. 5개 JSON을 **정적 import**한다. runtime `fs.readFile`, 경로 탐색, process cwd 기반 fallback을 사용하지 않는다.
2. layout key와 JSON 내부 key/schema를 검증한다.
3. 호출마다 새 Workbook/Worksheet와 새 style object를 만든다. JSON 객체 또는 이전 호출 workbook을 mutate해 다음 출력으로 새지 않게 한다.
4. 값/열/행/병합/서식/보기/인쇄 설정 순으로 적용한다. merged slave 값을 중복 적용하지 않는다.
5. 수당 문서의 로고는 workbook 생성 뒤 `document-brand-logo-service`의 새 helper로 기존 `brand-logo-clean*.png`를 찾아 정확한 범위에 1개 추가한다. 기존 loaded-workbook 로고 교체 함수는 template preview 호환용으로 유지한다.
6. build 결과에 imported JSON 5개가 `dist/server/main/services/document-layouts/` 아래 포함돼야 한다. tsconfig/package 변경으로 해결하지 말고 현재 `resolveJsonModule` 동작을 사용한다.

### 6.5 근무표 전환

1. `resolveSchedulePlanTemplateLayout`은 `template.profile.kind === "schedule"`이면 그 layout을 그대로 반환한다.
2. profile이 없는 legacy seed는 stable ID `template-schedule-sample1-2026-1`, `template-schedule-sample2-2026-1`만 각각 sample1/sample2로 매핑한다.
3. 그 밖에 variant를 결정할 수 없으면 `지원하는 기본 근무표 레이아웃을 확인할 수 없습니다.`처럼 명시 오류를 낸다. source path 검사나 파일 inspect fallback 금지.
4. `writeSchedulePlanWorkbook` 입력에서 `templatePath`를 제거하고 resolved variant 또는 5키 중 schedule key를 받는다. built-in workbook에 기존 update/fill/styleSpec을 적용해 쓴다.
5. `schedule-plan-export-service.ts`에서 source-path import/call을 제거한다. history의 template ID/label은 호환을 위해 그대로 저장한다.
6. `inspectSchedulePlanTemplate`과 `inspectSchedulePlanTemplateFromWorkbook`은 구형 관리/시험 호출용으로 유지한다. 이 존재 자체는 runtime export 의존이 아니다.

### 6.6 수당 Excel 전환

1. 품의서는 항상 `proposal-xlsx` built-in compact 기본을 사용한다. `updatedProposalTemplateFileNames`, 파일명 감지, sourcePath 기반 legacy/generation 분기를 export 호출 그래프에서 제거한다.
2. 현 `writeUpdatedProposalWorkbook`의 동적 행/병합 로직을 재사용하되 시작 workbook만 built-in으로 바꾼다. 기존 profile styleSpec 적용은 유지한다.
3. 별첨1은 항상 `attachment1-xlsx` built-in compact 기본을 사용하고 `writeCompactAttachmentOneWorkbook` 흐름을 재사용한다. 파일명 기반 compact 판정과 legacy workbook 경로는 export에서 제거한다.
4. 별첨2는 `attachment2-xlsx` built-in workbook의 detail/subtotal/total prototype row style을 capture한 뒤 현 동적 writer를 그대로 적용한다.
5. `readWorkbook`/`resolveDocumentTemplateSourcePathOrThrow`가 allowance XLSX export에서 완전히 사라져야 한다. `resolve*TemplateFields`는 profile style/anchor 호환에 필요한 범위만 유지할 수 있으나, built-in 기본 좌표를 다른 파일에서 추론하면 안 된다.
6. template record는 export history ID 호환과 styleSpec 적용에만 사용하고 `sourcePath` 값·basename·존재 여부로 분기하지 않는다.
7. PDF 분기와 PDF writer 호출 인자는 변경하지 않는다.

### 6.7 parity 비교 규칙

`built-in-excel-layout-service.test.ts`에서 표본은 오직 정답 fixture로 읽는다. 표본과 generated workbook에 동일한 명시적 dynamic-value scrub map을 적용한 뒤 다음을 정규화해 deep equality한다. 최종 동적 셀 값은 이 비교에서 버리는 대신 schedule/allowance 통합 시험의 합성 데이터 기대값으로 직접 검증한다.

- 시트 이름과 주 시트 수. 별첨1 generated output은 `별첨1` 하나만.
- 선언 canvas 안 모든 셀의 **정적** tagged value/formula, merge master 관계. 동적 범위의 generated 값은 빈 값이어야 하고 표본 값이 JSON에 복제되지 않았음을 별도로 assert한다.
- merge range 전체 집합.
- 명시 column width/hidden/outline, row height/hidden/outline.
- font(name/size/bold/italic/underline/color 등), alignment, border 각 변, fill, numFmt, protection.
- worksheet properties/views, pageSetup, pageMargins, headerFooter, printArea.
- 로고는 binary/media ID가 아니라 이미지 개수 1, 명세 anchor, `oneCell`을 확인한다.

비교에서 제외 가능한 것은 zip 순서·생성 시각·ExcelJS 내부 style/media ID처럼 실제 화면/판독에 영향 없는 volatile metadata뿐이다. 셀 스타일 필드나 빈칸을 광범위하게 제외하지 않는다. 제외 항목은 test helper에 이름을 명시하고 회신에 열거한다.

### 6.8 정확히 추가할 신규 시험 15건

기존 시험은 삭제하지 않고 아래 `it` 15개를 순증한다.

1. template1 built-in ↔ 표본 정적 값·구조·서식 parity + 동적 값 scrub.
2. template2 built-in ↔ 표본 정적 값·구조·서식 parity + 동적 값 scrub.
3. proposal built-in ↔ 표본 주 시트 정적 값·구조·서식 parity + 동적 값 scrub.
4. attachment1 built-in ↔ 표본 `별첨1` 정적 값·구조·서식 parity + 인력/사번/금액 scrub.
5. attachment2 built-in ↔ 표본 정적 값·구조·서식 parity + 인력/금액 scrub.
6. 수당 3종 topology/단일 시트/로고 anchor.
7. 알 수 없는 layout key가 fallback 없이 실패.
8. 두 번 생성한 workbook이 독립적이며 첫 객체 수정이 두 번째에 새지 않음.
9. sourcePath가 없는 template1 export → 수정 → 회수 parse 동일.
10. sourcePath가 없는 template2 export → 수정 → 회수 parse 동일.
11. template2에 E근무 입력 시 기존 오류와 미생성 보증.
12. 수당 template 3개의 sourcePath가 모두 존재하지 않아도 XLSX 3파일 생성.
13. 품의서 `정규 0/조기 1`과 `정규 1/조기 0` 두 경계 조합의 좌표·병합·`해당 없음`.
14. 품의서 정규/조기 여러 근무지 조합과 별첨1 동적 상세/조기/22행 안내·단일 시트, 별첨2 소계/합계.
15. 정상 승인 흐름에서 Pool·BP·사번 없는 비BP는 승인/문서 대상 0건이고 사번 있는 일반 인력만 세 XLSX에 존재.

9~11은 `schedule-plan-export-service.test.ts`의 기존 stale-path 시험을 강화하면서 **순증 2건**이 되게 한다. 12~15는 `allowance-document-export-service.test.ts`에 **순증 5건**이 되게 시나리오를 쪼갠다. 1~8은 신규 파일 8건이다. 따라서 순증은 정확히 15건이다.

### 6.9 최소 변경 원칙

- 요구사항과 직접 연결되지 않은 정리·이름 변경·대규모 포맷 변경을 하지 않는다.
- 파일 전체 재생성은 JSON 5개에만 허용한다. TypeScript는 필요한 hunk만 수정한다.
- 테스트를 구현에 맞춰 약화하지 말고 구현이 기존·신규 계약을 만족하게 한다.
- `as any`, `@ts-ignore`, eslint disable, try/catch로 오류 삼키기, 숨은 sample fallback을 쓰지 않는다.
- 커밋은 만들지 않는다. Sol 검증 전 제품 완료나 Phase 완료를 선언하지 않는다.

## 7. 적용할 불변조건과 과거 함정

### 7.1 이번 작업의 필수 불변조건

- 배포 Excel 인원 줄 순서는 **조 → 배정 순서(`sortOrder`) → 사번**이다. 이름순 재정렬 금지.
- 실적은 회수 Excel intake로만 들어온다. 화면/DB 직접 입력 경로를 만들지 않는다.
- `DATE`, 변경 사유, 휴일 날짜의 분홍 채움, 대체/연장 표 좌표는 회수 판독 의미다. 단순 장식으로 보고 바꾸지 않는다.
- 수당 지급 대상은 **사번이 있는 비Pool·비BP**뿐이다. Pool은 대체·휴일·연장 모두 미지급, BP는 인력/근무표에 무사번으로 있을 수 있으나 실적·수당·문서에는 들어오지 않는다. 사번 없는 비BP도 제외한다.
- 이미 승인·계산된 과거 결과를 삭제하거나 재계산하지 않는다. 이번 변경은 출력 표현만 바꾼다.
- 품의서 행 삽입 뒤 merge registry 충돌을 방지하는 현 보정 로직을 유지한다.
- 데이터/행 한도 초과를 조용히 잘라내지 않는다. 오류 또는 기존 확장 동작을 유지한다.
- 실행 시 AI·인터넷·외부 API 호출은 0회다.

### 7.2 반드시 피할 과거 실패

- 표본 파일을 다른 디렉터리에서 찾아주는 fallback은 결함을 가린다. missing `sourcePath`가 성공해야 하는 이유는 built-in 생성이지 다른 표본 발견이 아니다.
- 파일명(`품의서_2026-04_수정본.xlsx` 등)으로 writer 세대를 정하면 사용자 이름 변경 때 출력이 달라진다. 새 경로는 key만 사용한다.
- JSON에 sample 이미지 binary를 넣거나 xlsx 전체를 base64로 감싸는 것은 생성기 구현이 아니다. 금지한다.
- 표본 주 시트에는 실제 사번·이름·근무지·금액이 있다. 이를 JSON에 그대로 직렬화해 두고 나중 writer가 지울 것이라고 가정하면 안 된다. committed 기본값 단계에서 이미 0건이어야 한다.
- attachment1 표본의 역사/검증 보조 시트를 출력하면 개인정보·불필요 자료가 따라간다. 주 시트 1개만 둔다.
- 병합 셀 slave에 값/스타일을 다시 쓰거나 행 splice 뒤 stale merge를 남기면 파일이 깨진다.
