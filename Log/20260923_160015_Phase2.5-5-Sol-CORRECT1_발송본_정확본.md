## 5. 보정 요구사항

### P255-C1 — compiled finder와 shape

1. finder 후보는 설계대로 두 개의 실제 의미만 가진다.
   - compiled `__dirname`에서 project root의 `scripts/lib/find-chrome.mjs`: `../../../../scripts/lib/find-chrome.mjs`
   - `process.cwd()/scripts/lib/find-chrome.mjs`
2. 현 잘못된 `../../scripts`, `../../../scripts` 후보는 제거한다.
3. `findChrome` export가 함수가 아니거나 반환값의 `path`/`version`이 비어 있는 문자열이 아니거나 path가 일반 파일이 아니면 한국어 안전 오류로 fail-closed한다.
4. 빌드 뒤 저장소 밖 cwd에서 compiled service가 실제 Chrome을 찾아야 한다. cwd fallback에 기대지 않는 시험/명령 증거를 남긴다.

### P255-C2 — 전체 deadline과 고정 PDF 옵션

1. 기본 30,000ms deadline은 `findInstalledChrome -> launch -> context -> page -> route -> setContent -> fonts.ready -> page.pdf` 전체 비동기 작업을 묶는다.
2. 어느 단계가 멈춰도 제한 시간 오류가 반환되고 생성된 page/context/browser는 `finally`에서 닫힌다.
3. timer는 성공·실패 모두 해제하고 늦게 끝난 promise의 unhandled rejection을 남기지 않는다.
4. `page.pdf`는 정확히 다음 세 옵션만 제품 서비스가 소유한다.
   - `printBackground: true`
   - `preferCSSPageSize: true`
   - `displayHeaderFooter: false`
5. caller가 위 옵션이나 `landscape`를 덮어쓸 수 있는 공개 `pdfOptions` escape hatch를 제거한다. orientation은 CSS `@page`만 정본이다.
6. mock `page.pdf()` pending + `timeoutMs:10` 시험은 timeout 문구, close 3종 호출, timer/잔여 작업 정리를 검증한다.

### P255-C3 — 배타 commit과 실제 mid-commit rollback

1. temp는 같은 디렉터리에 `wx`로 쓴다.
2. target 노출은 `linkSync(temp, target)` 또는 동일한 no-replace 원자 primitive로 한다. `existsSync -> renameSync`를 배타성 근거로 쓰지 않는다.
3. target이 이미 있거나 경쟁 호출이 먼저 만들면 기존 bytes를 절대 덮어쓰지 않는다.
4. 성공한 target link만 기록하고, 뒤 commit 실패 시 이번 호출 target만 역순 제거한다. 호출 전 존재 파일은 보존한다.
5. 성공·실패 뒤 temp 0개를 검사한다.
6. N8 시험은 preflight collision이 아니라 적어도 첫 target commit 성공 뒤 두 번째 commit에서 실제 실패시켜 rollback 경로를 실행한다. 같은 target을 두 task에 넣어 두 번째 exclusive link를 실패시키는 방식도 허용한다.

### P255-C4 — font/CSS/HTML 안전

1. `font.family`는 CSS string으로 안전하게 직렬화한다. raw 문자열 보간을 금지한다.
2. 최종 `style` attribute 값 전체를 HTML attribute escape한다.
3. validator는 quote, semicolon, backslash, 괄호, 제어문자 등 CSS/HTML 경계를 깨는 family payload를 명시적 issue로 거절한다. 정상 한국어/영문/숫자/공백/안전 구두점 font family는 유지한다.
4. allowance와 dashboard 양쪽에 동일한 안전 규칙을 적용한다.
5. 다음 payload 계열을 validation과 생성 HTML 둘 다 시험한다: `" onmouseover="boom`, `';background:url(http://x)`, `</style><script>`.
6. 결과 HTML에 새 attribute, tag, `url(`, 실행 markup이 생기면 실패다.

### P255-C5 — fixed table 열 계약

1. 다음 고정표는 `columnWidths`가 존재할 때 baseline과 정확히 같은 key 집합을 가져야 한다.
   - proposal regular/early: A:G 7개
   - attachment1 table: A:T 20개
   - attachment2 table: A:H 8개
2. 일부 key 삭제, 빈 객체, 추가/누락 key는 실제 `outputs[i].blocks[j].columnWidths` path로 거절한다.
3. 렌더된 fixed colgroup은 표의 실제 열 수와 정확히 같아야 한다.
4. dashboard table은 설계대로 동적이므로 partial A:AZ 저장을 계속 허용하고, 실제 N열에서 미지정 열을 1로 채우는 현 계약을 유지한다.
5. 현 attachment 시험의 `{A,B}` 2열 PASS 기대를 제거하고 20/8열 정상 정의 및 부분 정의 거절로 바꾼다.

### P255-C6 — 기본 품의서 PDF 외형 불변

1. 기준 presentation은 다음 파일의 baseline commit 내용이다.

2. Chrome 전환과 layout wrapper/delta에 필요하지 않은 HTML/CSS 재디자인을 되돌린다.
3. 최소한 다음 baseline 값을 복원한다.
   - chart grid: `minmax(0, 1.25fr) minmax(0, 0.9fr)`
   - donut outer/inner: `180px` / `118px`
   - bar gradient: `#3758b0` -> `#8da2de`
4. 위 세 값만 맞추는 것으로 끝내지 말고 해당 presentation diff 전체를 baseline과 대조한다. 기본 definition에서 문구·DOM 순서·class·CSS·계산·압축·정렬·합계가 기존과 같아야 한다.
5. layout 변경분은 wrapper attribute/조건부 생략/colgroup/font delta로만 겹쳐 적용한다.

### P255-C7 — visibility는 DOM 생략

1. `visible=false`인 block wrapper와 그 내부 내용을 HTML에 출력하지 않는다.
2. allowance 3 outputs와 dashboard 5 blocks 전부 같은 의미를 가져야 한다.
3. 숨긴 block의 `data-layout-block-id`, 사용자 payload, logo/image가 결과 HTML에 없음을 시험한다.
4. 다른 block 순서·page break·flow 구조는 유지한다.

### P255-C8 — lint와 증거 정정

1. 이번 구현이 만든 warning 12건을 타입으로 해소한다. suppression은 금지한다.
2. 최종 lint는 RC 0, error 0, 기존 warning 정확히 7건이어야 한다.
3. 기존 7건은 다음 파일에만 남아야 한다: allowance export 2, database migration 2, file-watch runtime 1, shared contracts 2.
4. 회신에서 이전 “신규 warning 0”과 N6/N8의 과장 보고를 명시적으로 정정한다.

### P255-C9 — 재현 가능한 실제 PDF 증거

1. 보정 후 실제 설치 Chrome으로 proposal/attachment1/attachment2/dashboard를 다시 생성한다.

3. 각 파일의 bytes, SHA-256, `%PDF-`, page count, MediaBox, BaseFont를 실제 명령과 함께 보고한다.
4. proposal 2쪽 이상, dashboard synthetic 2 sections = 2쪽, orientation 2+2, font, 외부 request 0을 다시 확인한다.
5. 저장소 안 PDF/screenshot artifact는 0이어야 한다.
