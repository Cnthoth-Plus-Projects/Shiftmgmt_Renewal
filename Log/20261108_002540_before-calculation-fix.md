## 1. 요율 기간 선택 — 최우선

1. 근무일이 적용 시작일~종료일 안에 드는 정식 적용 버전을 선택하는 공통 규칙을 둔다. 초안은 제외한다. 종료 버전은 기간이 확정된 과거 구간에서 사용할 수 있게 한다. 같은 기간 후보는 정의대로 시작일이 가장 늦은 것을 선택하며 동일 시작일의 모호한 버전 중복은 차단한다.
2. 같은해/다른해/현재활성으로 넘어가는 범위 밖 대체 선택을 제거한다. 적용 근거가 없으면 명시 오류로 승인을 거부하고 승인·계산을 함께 롤백한다. 저장 자료가 없다는 이유로 계산 중 시험용 요율을 대신 선택하지 않는다.
3. 미래 요율 등록으로 현재 요율을 오늘 종료시키지 않는다. 새 시작일과 앞뒤 버전의 경계를 검증하고, 필요한 경우 이전 적용 구간의 종료를 새 시작일 전날로 명확히 기록한다. 연도 라벨 대신 실제 날짜로 처리한다. 화면의 현재/예정/종료 표시와 확인 문구를 이 동작에 맞춘다.
4. 기존 자료의 잘못된 종료일·빈 기간·동일 시작일 중복을 추측해 일괄 보정하지 않는다. 진단과 명시적 정정 대상으로 분리한다. 기간 변경은 사유와 변경 이력을 남기며 기존 승인 스냅샷은 수정하지 않는다.
5. 승인 계산·미리보기·연장 보강이 서로 다른 대체 요율을 고르지 않게 공통 선택을 사용한다.

## 2. 정밀 금액과 원 배분

- 시급·근무분·배율을 십진 분수/정수 기반으로 계산한다. Node24 내장 BigInt를 사용할 수 있으므로 새 라이브러리는 도입하지 않는다. 소수 시급을 포함한 기존 유효 입력의 지원을 유지한다.
- 기존 규칙 유지: 실적1건의 라인 원금액 합계만 올림 → 각 라인 내림 → 소수부 큰 순서에 잔여1원 배분, 동률은 기존 라인 순서. 월 전체를 합쳐 한 번 올리도록 바꾸지 않는다.
- 15,510.000000000002 같은 이진 오차를 원금액에 남기지 않는다. 고정 epsilon, 임의1원 감산으로 맞추지 않는다. 안전하게 표현할 수 없는 금액은 조용히 자르지 않고 실패 처리한다.

## 3. 공휴일 추가 연장 지급

- 공휴일 기본근무와 별도 추가근무를 각각 계산한다. 추가분에는 해당 근무일의 휴_연장 연장/야간 배율을 적용한다. 일반 평일은 평_연장 배율을 적용한다.
- 휴일 추가분이 이미 지급됐다고 가정해 무조건0원 처리하는 설명을 제거한다. 실제 운영 배율은 요율 관리에서 정하며, 초기값0을 임의의 다른 숫자로 바꾸지 않는다.
- 제안하는 안전 처리: 지급 대상이며 실근무가 있는데 적용 배율 때문에 총액이0이면 요율 확인 안내와 함께 새 승인을 보류한다. Pool/BP 제외와 혼동하지 않는다. 양수 배율을 등록한 후 다시 확인·승인한다. 이 처리 역시 계획 승인 후 구현할 항목이다.
- 일반 토·일 분류는 별도 확인 항목이다. 현재 등록된 공휴일만 휴일 요율인 기준을 답변 없이 주말 전체로 확장하지 않는다. 이 결정과 무관한 요율 날짜·정밀 금액 수정은 독립적으로 진행 가능하다.

## 4. 승인 원문·시작 시 보강 보호

- 승인·계산이 이미 있는 행은 시급/요율 변경, 패치 후 재시작, 재가져오기만으로 재계산하거나 원문을 다시 쓰지 않는다.
