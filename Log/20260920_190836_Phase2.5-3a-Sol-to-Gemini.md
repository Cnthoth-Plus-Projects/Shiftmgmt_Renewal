- schedule: `{year}년/{monthNumber}월/{year}_{monthNumber}_{siteName}.xlsx`

### 5.2 capability 최소 규칙

- 전체 `editableProperties`: `position`, `size`, `visibility`, `text`, `logo`, `column-width`, `font` 고정 순서.
- 전체 `protectedProperties`: `row-order`, `value`, `binding`, `row-height`, `merge` 고정 순서.
- 제목/설명/note/footer의 정적 문구: position, size, visibility, text, font.
- logo: position, size, visibility, logo.
- 일반 field/summary: position, size, visibility, font; binding/text 값은 보호한다.
- 일반 table: position, size, visibility, column-width, font; 행 순서·값·binding·행 높이·병합은 보호한다.
- schedule 판독 table(`calendar-grid`,`reschedule`,`substitute`,`overtime`): position, column-width, font만 capability에 두고 size/visibility/text는 보호한다. position 변경은 preview 검증만 허용하고 save 검증은 `SCHEDULE_PARSER_POSITION_NOT_ACTIVATABLE` 오류로 거부한다.
- `month-anchors`: `protectedBlockIds`에 포함하고 editable 0; editable 7종과 protected 5종 모두 block protected 목록에 둔다.
- `bindingKey`, `kind`, `page`, `layoutMode`, `flowOrder`, `autoHeight`, `repeatHeaderOnPageBreak`, `pageBreakBefore`, output member 순서/ID, canvas는 기본 정의와 달라질 수 없다.

### 6.3 저장 형식

신규 layout row만 다음 형식을 쓴다.

```text
template_type = storage key 5종 중 하나
source_path = ""
status = "approved"
is_default = 활성 판 1, 과거 판 0
profile_schema_version = "1.0"
profile_json = JSON.stringify(DocumentLayoutDefinition) 자체
validation_json = JSON.stringify({ operation: "save" | "reset", changeReason?: string })
output_file_name_pattern = null
checksum = null
created_at = updated_at = approved_at = 같은 ISO 시각
```

- `version_label`은 같은 신규 저장 키의 `source_path=''` 판 수를 기준으로 `v1`, `v2`, ...를 transaction 안에서 부여한다.
- `revisionId`는 새 UUID 기반 ID다. 기존 판 ID를 재사용하지 않는다.
- `usingBuiltInDefault`는 저장 행이 0개라 fallback을 직접 쓸 때만 `true`; reset으로 기본 정의 복사본을 저장한 직후에는 active revision이 있으므로 `false`다.
- history는 `document_template_history` 이벤트 표가 아니라 신규 key의 version rows 자체를 기준으로 한다. 삭제가 없으므로 모든 판이 남는다.

### 6.4 최소 변경 원칙

- 요구사항과 직접 연결되지 않은 정리·이름 변경·포맷 변경을 하지 않는다.
- 기존 공개 호출 계약은 유지한다. 이번 패킷 외 API 변경이 필요해 보이면 구현하지 말고 반환한다.
- 파일 전체 재생성 대신 필요한 hunk만 바꾼다.
- 테스트를 구현에 맞춰 약화하지 말고, 구현이 정본과 음성 계약을 만족하게 한다.

## 7. 적용할 불변조건과 과거 함정

### 7.1 이번 작업의 필수 불변조건

- 새 표·열·migration 없음. 기존 `document_template_versions.profile_json`과 `source_path=''`를 사용한다.
- forward-only: 저장과 reset은 항상 새 row다. 과거 판을 수정·삭제하지 않는다.
- active 판은 저장 키마다 정확히 0 또는 1개다. 2개 이상을 임의 선택하지 말고 데이터 오류로 거부한다.
- 저장 전 optimistic concurrency를 강제한다. `expectedRevisionId=null`은 현재 active가 없을 때만 맞다.
- capability는 프로그램이 계산하는 값이며 저장 JSON에 포함하지 않는다.
- 값·binding·행 순서·행 높이·병합은 어떤 block에서도 저장 변경을 허용하지 않는다.
- schedule 판독 표 position은 preview-only다. 2.5-4 전 active 저장은 금지한다.
- 사용자에게 노출될 수 있는 오류는 한국어로 “무엇이 잘못됐는지”를 설명하고 영문 기술 코드만 단독 노출하지 않는다.
- 기존 수당 필터 불변식: Pool, BP, 사번 없는 비BP는 지급 대상에 포함하지 않는다. 이번 작업은 관련 파일을 건드리지 않는다.

### 7.2 반드시 피할 과거 실패

- `template_type` 전체를 legacy `TemplateType`으로 cast해 신규 키를 old profile normalizer에 흘리지 않는다.
- 표 전체 count 때문에 신규 row가 legacy seed 생성을 막지 않게 한다.
- active 2개 중 첫 행을 조용히 고르지 않는다.
- validation 뒤가 아닌 일부 DB 변경 뒤 오류를 내서 반쪽 저장을 남기지 않는다.
- candidate object를 얕게 복사해 다음 호출이 오염되지 않게 한다.
- unknown key를 무시하거나 JSON parse 실패를 built-in fallback으로 숨기지 않는다.
- PDF를 임시 빈 block, 가짜 capabilities, “나중에” placeholder로 넣지 않는다.
- allowlist 밖 API/renderer/UI를 선행 구현하지 않는다.
- 자가 보고 SHA를 창작하지 말고 `Get-FileHash -Algorithm SHA256` 전체 64자를 사용한다.
