## 실제로 동작해야 하는 것 5가지

| # | 동작 |
|---|---|
| 1 | **Tab 이동** — 메뉴 → 탭 → 필터 → 표 → 버튼. 포커스 링이 눈에 보일 것 |
| 2 | **표 키보드** — ↑↓ 행 이동, Space 선택, Enter 상세 열기 |
| 3 | **모달** — 포커스가 모달 안에 갇힘, Esc로 닫힘, 닫으면 원래 버튼으로 복귀 |
| 4 | **비활성 버튼** — `aria-disabled="true"`. 포커스는 가되 눌리지 않음. 사유를 `aria-describedby`로 연결 |
| 5 | **승인(되돌아오는 방식)** — 승인하면 배지가 `대기`→`승인`, 상단 건수 갱신, 포커스가 다음 미처리 행으로, `aria-live` 영역 문구 변경. **페이지를 새로 열면 원래대로 복귀** |

**5. 파일 쪼개기 계획** (용량은 계산 추정 — 근사식을 밝힌다)

- 근사식: **파일 용량 ≈ 상태 수 × (껍데기 5KB + 본문 3~9KB) + 공통 CSS 11KB + 동작 JS 5KB.** 표 전량(17행+) 상태는 본문에 +15KB.
- 이 식으로 **화면 3파일은 성립하지 않는다**: 홈 ≈ 60KB / 실적 ≈ 130~150KB / 마법사 ≈ 100KB — 규칙 11(30KB) 위반.
- **30KB를 그대로 지키려면 상태당 1파일(25파일)까지 가야 하고, 그래도 표 전량 상태는 단독 30KB 턱걸이~초과**한다. 25파일은 "스크롤만 내리면 전부 보인다"는 검수 방식의 이점도 크게 깎는다.
- **제안 (추천 — 결정은 Claude·사용자)**, 세 가지가 한 묶음이다:
  - ⓐ **검수용 HTML에 한해 상한을 파일당 50KB로 완화.** 30KB 규칙의 취지는 이관되는 앱 소스의 유지보수(123KB 사고 재발 방지)이고 이 HTML은 이관되지 않는 검수 산출물이다.
