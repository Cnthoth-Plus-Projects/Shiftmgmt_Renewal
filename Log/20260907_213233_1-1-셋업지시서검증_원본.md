## 5. 창구 규약 문서 (`docs/api-convention.md` — 1-3 구현의 기준, 이번에는 문서 + 헬퍼 뼈대만)

1. 주소: `POST /api/<채널명>` — 채널명은 `04-api-contract.md`·`src/preload/index.ts`의 111개 문자열 그대로(예 `employees:list`).
2. 요청: `Content-Type: application/json`, 본문 = 인수 배열(`[]` 허용). 1 MB 상한.
3. 응답: `contracts.ts:869-880`의 `BridgeResult<T>`(`{ ok: true, data }` / `{ ok: false, errorCode, message }`) JSON 그대로. HTTP 상태는 200(계약 결과) · 400(본문·호스트 오류) · 401(세션 없음) · 404(채널 없음) · 413 · 500(예외 → `getErrorMessage`).
4. 세션: `auth:sign-in` 성공 시 서버가 세션 id 발급 → `Set-Cookie: sm_session=<id>; HttpOnly; SameSite=Strict; Path=/`. 서버 메모리 `Map<id, AuthSession>`. `auth:sign-out`이 삭제. 프로그램 재시작 = 전부 로그아웃(원본과 같은 단일 프로세스 의미).
5. 가드: 원본 `withSession`·`withActionPermission`·`withAdmin`·`withAccessHistory`·`recordSuccessfulActivity`를 **같은 이름·같은 판정**으로 옮긴다(1-3a 완료 조건). 판정 로직은 `ipc-auth-guard-service.ts`(services, 복사본) 호출.
6. 파일 대화상자 14곳: 가져오기 10곳 = `multipart/form-data` 업로드 → `<dataDir>/uploads/<yyyyMMdd-HHmmss>-<원래이름>` 저장 → 그 경로를 서비스에 전달 / 내보내기 4곳 = 서비스가 만든 파일을 `Content-Disposition: attachment`로 내려주거나 `<dataDir>/exports/`에 저장하고 경로를 응답에 실음(화면이 안내). 1-3c에서 확정.
7. `/api/health`만 GET 허용(브라우저 주소창 확인용).
