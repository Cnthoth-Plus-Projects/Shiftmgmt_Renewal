### 1. 판정 항목 ①~⑧

1. **① AGREE(구조 방향), 보완 필수.** `src/shared/`·`src/main/services/`의 원래 자리를 유지하고 `src/main/server.ts`·`src/main/http/`·`src/web/`를 더하는 S2는 1-2 복사와 1-3 통신 재작성에 맞다. 다만 §5가 필수 산출물로 선언한 `docs/api-convention.md`가 §3 파일 트리에는 없다. §3에 넣고 `docs/codebase-map.md` 검증 대상에도 포함해야 한다. 서버용 CommonJS와 브라우저용 ESM의 출력 폴더도 ④ 대안처럼 분리해야 한다.

2. **② DISAGREE.** `listen(..., "127.0.0.1")`와 정확한 Host 허용 목록, CORS 미개방은 좋은 기본선이다. 그러나 쿠키 인증으로 급여·인사 데이터를 바꾸는 서버의 완료 기준으로는 다음이 빠졌다.
   - 모든 상태 변경 요청은 `Content-Type: application/json`을 **실제로 검사**하고 `text/plain`·폼 전송을 415로 거부한다. 파일 업로드 multipart는 채널별 명시 예외로 둔다.
   - 브라우저 요청의 `Origin`이 실제 서버 origin과 같은지 검사하고, `Sec-Fetch-Site: cross-site`인 변경 요청은 403으로 거부한다. 헤더가 없는 로컬 점검 명령을 허용할지는 별도 규칙으로 명시한다. `SameSite=Strict` 하나에만 맡기지 않는다. 근거: [OWASP CSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)의 Origin/Fetch Metadata 및 simple content type 방어 권고.
   - 정적 응답에 최소 CSP(`default-src 'self'` 등), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `frame-ancestors 'none'`를 둔다.
   - `port 0` 테스트에서는 실제 배정 포트로 Host 허용 목록을 만든다.
