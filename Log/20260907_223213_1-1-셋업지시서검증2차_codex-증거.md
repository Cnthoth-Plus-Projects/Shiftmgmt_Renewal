## 5. 전송 계약 문제

1. `operations:select-directory`는 원본에서 `showOpenDialog`의 `openDirectory/createDirectory`로 **서버가 계속 사용할 절대 폴더 경로**를 반환한다(`register-operations-handlers.ts:166-183`, 계약 `contracts.ts:986-988`). 이를 multipart 업로드로 치환할 수 없다. 파일 업로드와 별도로 서버 측 폴더 선택 또는 검증된 절대 경로 입력 규약이 필요하다.
2. `performance:open-source-file`은 `shell.openPath`를 실행한 뒤 `BridgeResult<null>`을 반환하고 활동도 기록한다(`register-performance-handlers.ts:239-264`, `ipc-handler-helpers.ts:210-241`, 계약 `contracts.ts:1186`). “경로만 응답”은 반환형과 행위 계약을 모두 바꾼다.
3. 저장 대화상자 채널은 기존 `BridgeResult<...Record>`에 `outputPath`를 담는다. 같은 HTTP 응답을 JSON 계약 그대로 유지하면서 동시에 attachment로 내려줄 수 없다. 서버가 exports에 기록하고 기존 JSON을 반환한 뒤 별도 인증된 일회성 다운로드 URL을 쓰는 등 2단계 규약을 채널별로 고정해야 한다. 근거: `DashboardChartExportRecord`/`DashboardReportExportRecord`(`contracts.ts:799-827`), `DocumentTemplatePreviewRecord`(`:862-866`).

## 6. 브라우저 빌드 문제

`tsconfig.browser`의 ESNext/Bundler 컴파일은 상대 import에 `.js`를 자동으로 붙이지 않는다. 1-2에서 그대로 복사할 shared 런타임 파일에는 확장자 없는 import가 남아 있다. 예:

```text
src/shared/domain/allowance-service.ts:17  from "./rounding"
src/shared/domain/monthly-schedule-draft.ts:1-4,12
src/shared/domain/schedule-rule-warning.ts:1
src/shared/domain/team-membership.ts:2-3
src/shared/domain/team-work-type.ts:1
```

브라우저는 이런 URL에 `.js`를 추론하지 않으므로 `dist/browser/shared/**`를 직접 ESM으로 제공하는 S3/S7은 Phase 3에서 실패한다. build-only 번들러로 `src/web/app.ts`를 번들하거나, 검증 가능한 출력 import 재작성/정적 서버 확장자 fallback을 지시서에 고정해야 한다.

## 7. 추가 재현

- Pretendard CSS는 `./woff2/Pretendard-*.woff2`와 `./woff/Pretendard-*.woff`를 참조한다. §3처럼 woff2를 `assets/`에 평면 복사하면 404다. `assets/woff2/` 구조를 보존하고 woff fallback도 복사하거나 CSS를 명시적으로 재작성해야 한다. Material Symbols의 woff2만 CSS와 같은 폴더가 맞다.
- §3 `dev.mjs`의 “Chrome 또는 서버 종료 시 나머지 종료”는 기존 Chrome 프로세스가 URL을 넘겨받아 launcher가 즉시 끝나는 Windows 동작에서 서버를 바로 종료시킬 수 있다. 서버/SIGINT를 수명 기준으로 삼고 Chrome child 종료는 무시하거나, 고유 user-data-dir의 소유 프로세스를 띄워야 한다.
- §1은 깨끗한 checkout 빌드를 요구하지만 §8은 `git clean -xfd -n` dry-run만 실행한다. 실제 clean 환경 증거가 아니다. 별도 임시 clone에서 `git status --porcelain` 빈 출력 후 `npm ci && npm run build`를 실행해야 한다.
- §8-9 명령의 `Out-File -NoNewline`은 135개 status 행을 구분자 없이 이어 붙인다. 재현 결과 기준 파일은 10,656 B/SHA `d05cfcc0...`, 지시 명령 출력은 10,521 B/SHA `f49c20c9...`였다. 다음과 같이 LF와 마지막 LF를 명시해야 한다.

```powershell
$lines = @(git -C C:\Projects\Active\ShiftMgmt_V3.4 status --porcelain=v1)
[IO.File]::WriteAllText($env:TEMP + '\v34-status.txt', (($lines -join [char]10) + [char]10), [Text.UTF8Encoding]::new($false))
```

- 원본 상태는 올바른 LF 방식으로 다시 계산했을 때 135행, 10,656 B, SHA `d05cfcc0b3d16fb8ae286d44525de973d52e44da59565612df964b49a610e403`으로 기준과 동일했다. 검증 중 원본 파일 및 Git 상태는 변경하지 않았다.
- CSP `style-src 'self'`과 Phase 3 ECharts/동적 스타일의 호환성은 실제 Chrome CSP 테스트를 Phase 3 진입 조건으로 추가할 필요가 있다.
