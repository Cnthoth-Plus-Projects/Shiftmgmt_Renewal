**지적이 맞다.** 871줄에서 05를 실적 관리의 `처리 중`으로 세어 놓고 873줄에서 같은 것이 빠졌다고 다시 셌다. **같은 문단 안의 자기모순**이었다.

| 칸 | 사유 |
|---|---|
| 홈 — 권한 없음 | 홈은 **모든 역할이 보는 화면**이다. 역할에 따라 `관리` 그룹이 안 보이는 것은 **메뉴에서 빠지는 것**이지 "권한 없음 상태"가 아니다 |

**🔶 후속 5칸 — 각각 왜 필요한지도 적었다.** 두 칸은 **내가 소스·정본에서 새로 확인한 것**이다.

| 칸 | 근거 |
|---|---|
| 실적 관리 — 로딩 | 화면을 여는 즉시 수천 행 집계 (`12`가 "오래 걸림"으로 분류) |
| 마법사 — 로딩 | 기존 근무지를 열 때 설정 로드 |
| **마법사 — 권한 없음** | 🔴 **새로 확인**: `12-능력-매트릭스.md:151` — 근무지 쓰기 `site-write` = **planner, admin**. `:139` — "reviewer는 직원 등록·근무지 등록·근무표 배포를 할 수 없다" |

**따라서 후속은 4장이 아니라 5장이다. 20 + 5 = 25장, 84 + 5 = 89장.**
§6·우선순위 표 7행·§7 체크리스트를 전부 이 숫자로 맞췄다.

🔴 **그리고 검산 중에 내 오류를 하나 더 찾아 고쳤다.** 집계를 처음에 `✅ 있음 11칸`이라고 썼는데 **3 × 5 = 15칸이므로 채워진 것은 8칸**이다(상태는 9개 — 마법사 오류가 10·18 두 장). 8 + 5 + 2 = 15로 맞췄다.

또 **"이 표는 20장 전체를 나눈 표가 아니다"** 를 명시했다. 나머지 11장(03·04·13·14·15 / 08·09·17·19·20)은 평상시 화면과 그 변형이라 다섯 상태 어디에도 들어가지 않는다.

### ④ 승인 자동검증을 측정 가능하게 → **반영**

**지적이 맞다.** 브라우저 자동화로는 화면 낭독기가 실제로 소리 내는지 확인할 수 없다. 두 가지를 바꿨다.

**(a) 낭독 항목을 DOM 판정으로**

```
· 승인 전부터 `aria-live="polite"` 영역이 화면에 있고,
  승인 후 그 영역의 글자가 승인 완료 문장으로 바뀌는가   ← 화면의 구조를 보고 판정
```

> ⚠️ 네 번째 항목은 "실제로 낭독되는지"를 재는 것이 아닙니다. …
> 확인하는 것은 **① 낭독될 영역이 미리 자리 잡고 있는가**(승인 후에 새로 만들어 붙이면 안 읽힙니다) **② 그 영역의 글자가 바뀌는가** 두 가지입니다.
> **실제로 소리가 나는지는 사람이 화면 낭독기를 켜고 확인하는 별도 항목**이며, 이번 제출물에 포함하지 않습니다.

**(b) "되돌아오는 방식" 자체를 검증 항목으로 추가**

```
· 페이지를 새로 열면 배지·건수·행이 원래 03 그림으로 되돌아오는가
```

§1의 최소 JavaScript 5번 문구도 **"미리 자리 잡아 둔 `aria-live="polite"` 영역의 글자가 승인 완료 문장으로 바뀝니다"** 로 고쳐 §5-3과 맞췄다.
