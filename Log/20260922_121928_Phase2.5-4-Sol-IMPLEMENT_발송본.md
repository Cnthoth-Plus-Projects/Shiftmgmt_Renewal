### 5.1 metadata v1의 정확한 계약

- worksheet: `__shiftmgmt_meta`
- worksheet state: `veryHidden`
- payload cell: `A1` 단 하나
- defined name: `_SHIFT_MGMT_SCHEDULE_LAYOUT_REVISION`
- defined name target: 정확히 `__shiftmgmt_meta!$A$1` 한 범위
- 허용 root field는 아래 7개뿐이며 누락·추가·타입 오류는 거절한다.

```json
{
  "definitionSha256": "<64 lowercase hex>",
  "format": "shiftmgmt.schedule-layout-revision",
  "generatorCompatibilityVersion": "built-in-excel-layout-v1",
  "layoutKey": "schedule-xlsx/template1",
  "revisionId": "<stored UUID 또는 builtin:layoutKey:definitionSha256>",
  "revisionKind": "stored",
  "schemaVersion": 1
}
```

- `layoutKey`: `schedule-xlsx/template1|template2`
- `revisionKind`: `stored|built-in`
- stored `revisionId`: 기존 DB row UUID
- built-in `revisionId`: `builtin:<layoutKey>:<definitionSha256>`
- `generatorCompatibilityVersion`: 정의의 값과 동일
- canonical JSON/digest: 모든 깊이 객체 키 사전순, 배열 순서 보존, 공백 없음, Node 내장 `crypto` SHA-256, 외부 의존성 없음

### 6.3 상대 좌표와 용량

- block range는 `x+1`, `y+1` 규약을 새로 계산하지 말고 기존 `targetRanges` 결과를 쓴다.
- 기존 주소는 built-in 기본 block 시작점에 대한 역할별 offset으로 한 번 정의한다.
- `schedule.site`의 `C3`, `schedule.calendar-heading`의 `W6`, `schedule.roster`의 `B7`도 이동량을 반영한다.
- calendar의 `DATE` 표식/주차/근무 셀, reschedule의 일자/근무/사유 셀, substitute/overtime의 각 열을 모두 해당 block 내부 offset으로 번역한다.
- substitute는 현행 11~26행의 16행을 유지한다.
- overtime는 block 스타일 높이 11행으로 축소하지 말고 현행 34~100행의 **67행 scan window**를 시작 offset 기준으로 평행 이동한다.
- month anchors는 보호된 현행 위치를 유지한다.

### 6.4 strict metadata와 legacy 분기

1. 메타 시트/정의 이름이 모두 전혀 없으면 strict legacy 검사로 간다.
2. 둘 중 하나만 있거나 이름/범위/state/payload가 틀리면 invalid metadata로 거절한다.
3. metadata가 있으면 정확한 revision을 찾기 전 variant 고정 셀 탐지를 하지 않는다.
4. stored는 역사 row, built-in은 현재 알려진 exact digest만 허용한다. 장래 built-in 변경 시 compatibility registry가 필요하며 현 단계에서 현재 판을 과거 판으로 가장하지 않는다.
5. metadata 검증 후 definition 기반 보호 구조를 확인하고 그 뒤에만 실적 builder를 실행한다.
6. legacy는 pre-2.5-4 기본 protected geometry가 정확할 때만 기존 고정 variant를 허용한다. metadata를 지운 shifted 파일은 반드시 거절한다.

### 6.5 최소 변경 원칙

- 요구사항과 직접 연결되지 않은 정리·이름 변경·포맷 변경을 하지 않는다.
- 새 shared public type이 필요해 보여도 `src/shared`를 바꾸지 말고 허용 서비스 내부 타입으로 닫는다.
- renderer가 이미 export한 range helper를 재사용하고 renderer 파일은 바꾸지 않는다.
- 파일 전체 재생성 대신 필요한 hunk만 수정한다.
- 테스트를 구현에 맞춰 약화하지 말고 구현이 기존·신규 계약을 만족하게 한다.
